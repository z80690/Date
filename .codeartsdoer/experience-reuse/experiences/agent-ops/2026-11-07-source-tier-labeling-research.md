# 信源三级分级标注：禁止跨级冒用的调研引用纪律

## Scenario
智能体执行调研类任务（技术选型、方法论借鉴、外部经验引用）时，信息来源天然分层：官方一手原文、官方议程/公告页、第三方转述摘要。用户质疑"你的信源是不是唯一信源"并打回"未读作者原文即写计划（只凭头条摘要关键词，不合格）"的产出。

## Key Signals
- 可获取的信息只有第三方转述（头条文案、摘要、截图 OCR），而结论被当成原文级引用。
- 官方一手内容存在但无法自动获取（如需表单注册的回放、付费墙）。
- 用户要求给出信源链或质疑信源唯一性。

## Essence
不同层级的信源只能支撑不同强度的结论：转述级内容只能支撑"存在某观点"的存在性判断，不能支撑内容细节。跨级冒用（拿转述当原文）是调研被打回的高频根因。解法不是"找到唯一信源"，而是**如实标注每条结论所用的信源层级**，把不确定性显性化。

## Approach
1. **定义三级**：原文级（官方文档/论文/演讲全文，最高）→ 议程级（官方活动页/公告，仅含标题、讲者、时间等元信息）→ 转述级（第三方文案/摘要/OCR，最低）。
2. **实抓定级**：引用前实抓（记录 HTTP 200 等获取证据）；抓不到的内容明确标注"已实测不可得"及原因（如回放需表单注册），不虚构补位。
3. **逐条标注**：计划/文档中每条外部结论标注其信源层级与出处链接；同一主题多层信源并存时呈现为信源链（如：官方 session 页议程级 → 头条文案转述级 → 官方工程文章原文级）。
4. **禁止跨级冒用**：细节性结论必须落在原文级依据上；只有转述级信源时，结论降级为"存在性/方向性"表述并诚实标注。
5. **方法论文压到原文级**：涉及方法论依据（怎么做）的引用，必须落到原文级；实在没有则在文档中列为"待补充材料"，留待用户补充或后续获取。

## Faster Next Time
- 调研启动时先做一次信源分层盘点（能拿到哪几级），再决定计划里哪些结论能写多硬，避免写完返工。
- 把"需表单/登录才能获取"的实测结果直接写进交付物，可一次性回答用户的信源唯一性质疑，省去一轮解释。

## Applicability Boundaries
- 适用：通用 Agent 模式的调研/引用类任务（方法论借鉴、外部案例分析、技术方案依据）；尤其适用于交付物会被人工评审的场合。
- 不适用：纯内部事实（项目内实查结果不分级，但要标注"实查"）；用户明确豁免引用规范的快速草稿；无法分级且无关结论强度的背景性提及（一句话带过即可）。
- 与相邻经验的边界：2026-11-07-secondhand-summary-insufficient-verify-primary-source 解决"动笔前把依据从二手升级到一手原文"（前置升级动作）；本条解决"引用时逐条标注信源层级、禁止跨级冒用"（引用纪律）。顺序：先升级等级，再标注层级。
