# 混合仓库中纯文档模块（笔记目录）的知识文档生成路径：模块级空骨架属预期+清单抽样核验组织方式+旧版参考实读校正演进差异

## Scenario

以 subagent 身份承接代码仓知识文档模块派工，模块不是源码目录而是纯 Markdown 知识笔记目录（如 Obsidian vault 的笔记层，20-30 篇 md 含子目录）。派工单提供：符号骨架路径（空）、切片产物路径（0 条）、旧版 wiki 模块文档残留路径（声明"可参考其组织方式，但须以当前目录实际内容重新核验"）、文档模板与 `.code-links.json` 契约、粒度约束（全文 ≤5KB、架构小节 ≤300 字）。subagent 独立执行、不可中途向派工方确认。

## Key Signals

- 符号骨架为空、切片产物 0 条——对 md 笔记目录这是**预期形态**而非提取故障；仓库其余部分有源码（混合仓库），"仓库级纯文档仓库"判定不适用，须做**模块级**形态判定。
- 旧版模块文档存在但已过时：条目已被剥离归档（如注册表退役至档案区、状态标"已剥离"）、成果类笔记数量已增长（4→7 篇）、工作笔记计数与当前清单不符——模块演进会让旧版计数与状态系统性失真。
- 派工说明明确文档重点 = "笔记体系的组织方式与治理机制"而非逐篇罗列内容。

## Essence

混合仓库中，"预提取产物为 0"的判定单位是**模块**而非仓库：源码模块骨架空才可能是异常，md 模块骨架空与形态自洽、属正常。此类模块的可写内容不是代码结构而是**知识资产的治理机制**（分类体系/索引契约/加载机制/归档规则），组织方式由"全量清单+代表性抽样"归纳即可获得，无须逐篇全读；旧版文档只可借其章节骨架与叙述框架，其内容断言一律以当前目录实读为准——直接沿用旧版等于把过时事实写进新版"权威"文档，且这类失真（剥离、增补、计数漂移）恰是文档最核心的结构信息。

## Approach

1. **模块形态判定**：Glob 全清单（含子目录）+ 确认骨架空/切片 0 与 md 形态自洽 → 判为纯文档模块，不进入提取排错。
2. **清单全量 + 代表性抽样**：清单本身即架构叙述素材；抽读 2-3 篇代表性笔记（索引类/事实源类/机制规程类）确认分类体系、字段契约与编写约定（命名、frontmatter、结论前置、核验日期标注），不逐篇全读。
3. **旧版参考实读校正**：读旧版文档借其章节组织方式，逐节与当前清单对照；差异点（条目剥离归档、成果篇数、状态变化）以实读结果为准写入新版，旧版计数与状态一律不抄。
4. **按治理机制写架构小节**：以"子域分组 + 机制条目"叙述（用"- **子域**：一句话"格式覆盖各类笔记），禁逐篇罗列；粒度按派工约束执行。
5. **code_refs 行号取证**：md 无符号锚点，行号取被引笔记的标题行或引用依据行（如 `notes/xxx.md:1`），与文档写作同步完成，不回头补。
6. **噪音甄别留痕**：写盘后 IDE 推送的其他项目 LSP 报错按路径归属甄别（本例全部指向第三方克隆 PHP 文件），留一句说明后继续交付。

## Faster Next Time

- 一行判定：模块清单全是 .md 且派工声明"骨架空属预期" → 走本经验路径；清单含源码 + 骨架健康 → 切换骨架先行路径（见相邻经验 skeleton-first）；清单含源码 + 骨架空/切片少 → 先查语言支持范围定性空因（见 source-module-empty-skeleton-expected-doc-gen），勿默认属预期也勿进排错循环。
- 警惕信号：旧版文档的计数/状态与 Glob 清单对不上 → 旧版必然过时，逐节实读校正而非增量修补旧文。
- ROI：清单 1 次 + 抽样 2-3 篇 ≈ 逐篇全读的零头；架构叙述有据可依，粒度验收一次通过；旧版差异校正防止过时事实借"新版权威文档"复活。
- 反模式：对 0 条预提取产物进入排错循环；抄旧版计数与状态；逐篇罗列笔记内容。

## Applicability Boundaries

- 适用：混合（或任意）仓库中以 md 文档/笔记目录为单位的模块知识文档全新生成或再生成；subagent 独立执行派工模式，平台无关（CodeArts 类 IDE 实证）。
- 不适用：有源码模块+健康符号骨架（骨架先行与行号复用见 `2026-11-14-skeleton-first-targeted-read-module-doc-gen`）；仓库级纯文档仓库的规范知识生成（逐字核对全部数据源防编造见 `2026-11-06-doc-repo-zero-extraction-knowledge-gen`）；"参照某目录风格"类产物因参照系残缺被打回的返工场景（全集盘点纪律见 `2026-11-07-reference-style-requires-full-directory-inventory`）。
- 与相邻经验分工：doc-repo-zero-extraction 的判定单位是仓库、方法是逐字核对；本条判定单位是模块、方法是抽样核验（目录篇数大时不逐篇全读）。skeleton-first 假设骨架健康可用；本条假设骨架空属预期。lsp-diagnostics-triage 管写盘后外来诊断噪音甄别，本条 Approach 第 6 步复用其结论（本会话再次验证命中）。
- 证据等级：单次顺畅闭环（25 篇清单 + 3 篇抽样 + 旧版差异校正 → 约 3.5KB 文档 + code-links.json 一次落盘通过，无返工），无失败对照；"沿用旧版会引入过时事实"为基于差异实证的推断。
