# 上游断言（含用户"幻觉指控"）与磁盘实态矛盾时先实测对质：断言不可直接采信也不可默认接受

## Scenario

长会话收工阶段，用户基于自己的观察对 AI 交付物做出存在性否定断言（"你之前提到的 notes 路径和报告文件名是幻觉——目录无 notes，文件未落盘，无需再找"），同一消息附带后续执行授权（直接执行终验收工）。AI 上下文持有此前每份文件的落盘回执与留痕记录，双方断言矛盾。Agent 面对的选择：默认接受指控（跳过验证/重新落盘/错误自纠）、对抗性坚持（显得越权争辩）、或第三条路——实测对质。

## Key Signals

- 矛盾信号：用户断言"目录不存在/文件未落盘" vs AI 侧落盘回执与留痕指针齐备——两个断言直接冲突，任何一方都不能当裁判。
- 陷阱信号 1：指令附带"无需再找"——若默认接受指控，会跳过存在性验证直接进入下一步，真实产物状态永远无据可查。
- 陷阱信号 2：若把指控当"自己真幻觉了"而重新落盘，会造成同一交付物二次写入（重复文件/覆盖时间戳），污染留痕链。
- 决定性证据形态：实测三件套一次给出可回放结果——目录存在性、文件清单（字节数+mtime）、git 状态。

## Essence

**磁盘实态是交付存在性的唯一仲裁方；断言（无论来自 AI 自述、子代理汇报、还是用户/上游指控）都不能替代实测。** 此前经验已确立"对下"方向：子代理交付自述不可直接采信，须落盘复验兜底（related claim-verification）。本条补"对上"对偶面：外部断言（含用户指控 AI 幻觉）同样既不可直接采信、也不可默认接受——观察时点错位（用户查看早于 AI 最后一次写入）、IDE 视图未刷新、路径展示形式差异（如点前缀目录显示差异）都可能让真实存在的文件被误判为不存在。"禁止虚构"原则双向适用：AI 不虚构交付，也不虚构"自己确实幻觉了"——后者是另一种不诚实。

正确动作序列：实测对质 → **一行如实呈报实测结果**（不做对抗性定性争论，不指控用户看错）→ 按实测口径继续执行对方授权的动作 → 留 git 状态等可复核证据等对方裁决。矛盾往往在后续交互中自然解除（如对方确认"版本发布由我手动完成"——实测的 git status 与该口径互证一致）。

## Approach

1. **触发判定**：收到"X 是幻觉/不存在/没落盘"类存在性否定断言时，先做实测再回应——不因断言来自上位而跳过，也不因自信而跳过。
2. **实测三件套**（可回放命令）：
   - 目录存在性：`Test-Path <path>`；
   - 文件清单+指纹：`Get-ChildItem <path> | Select-Object Name,Length,LastWriteTime`（mtime 是"何时落盘"的客观证据）；
   - 版本控制态：`git status --short`（未提交的 modified 列表佐证文件真实存在且待归档）。
3. **呈报纪律**：回复开头一行呈报判定与依据（如"实测：目录存在、三文件 X 字节、mtime 完整，指控与磁盘实态不符"），随后立即执行对方在同一消息中授权的动作——对质与执行并行，不阻塞进度、不发起定性争论。
4. **留痕移交**：把实测证据（文件清单、git status）留在会话与留痕文件中，等待对方后续裁决（如发布归属），矛盾以对方确认或进一步实测解除。

## Faster Next Time

- 双向口诀：**"自述≠交付（对下复验），指控≠实态（对上对质）"**——两个方向的仲裁方都是磁盘。
- 最短路径：任何存在性争议，第一动作是三件套实测（秒级成本），第二动作是一行证据呈报；禁止在实测前做"重新落盘"或"认错自纠"动作。
- 早发现：交付阶段每份产物落盘后即保留 mtime+字节数指纹记录，争议发生时直接对表，无需重新取证。

## Applicability Boundaries

- 适用：通用 Agent 模式（CodeArts 码道平台实证；平台无关）。一切"外部断言 vs AI 落盘回执"矛盾场景：用户的幻觉指控、上游文档否认产物存在、协作方声称"没收到文件"。
- 不适用：断言方明示"我已实测并给出反证据"（如贴出不存在截图且时间晚于 AI 落盘）——此时按其证据优先处置，转向"落盘后被外部删除/回滚"假设；断言针对的是内容质量而非存在性（内容争议走逐段复核，不是三件套）。
- 边界：实测矛盾时不争辩"谁看错了"，只呈报证据与继续执行——若对方裁决仍与实测相反，以对方裁决为准执行并留痕（用户授权权高于实态陈述权，但实态证据必须已留痕供回查）；文件确被对方删除的场景（断言与实测均"不存在"）按断言处置，无需对质。
