# 事件驱动公约下子智能体触发时机的条款化：唯一唤醒事件+场景枚举+三禁+SOP 末步移交

## Scenario

项目公约"禁自建定时任务，一切触发走事件"时，为子智能体在 spec/配置中定义触发时机与 SOP，容易违规落成"定期检查待办""轮询队列""常驻监听"等形态，或写成"主智能体需要时触发"这类无事件锚点的模糊句，导致触发不可判定、公约合规不可核验。

## Key Signals

- 公约/规则层含"禁定时""一切触发走事件"字样——触发时机的合规性本身就是验收项。
- 需求要求明确子智能体"什么条件下被唤醒、执行什么步骤、产出交给谁"。
- 链路含门禁：产出需按合格/不合格分支流转，分支回环若写成循环重试即变相轮询。

## Essence

触发时机条款化的固定四件，合成一条链式事件编排（无任何常驻进程）：

1. **唯一唤醒信号**：每个子智能体只听一个具名事件（如"考核出题事件""作答完成事件"），不做广播订阅。
2. **触发场景枚举**：唤醒场景收为有限清单（如首次考核/重学重考/可运行验证/对比测试四类），清单外一律不响应——枚举即边界。
3. **显式三禁**：禁定时器、禁轮询、禁常驻监听，逐字写进条款而非默认前提。
4. **SOP 末步移交事件**：SOP 闭环节为"收输入→前置自检→执行→产出自检→落盘→发布下一环节移交事件，完成即退"——编排由事件链承担，不靠存活进程。

门禁回环也走事件：不达标时由门禁方重发上游事件（如重发考核出题事件），而非循环重试。

## Approach

1. 盘点链路交接点：列出全链路各环节之间的每次交接，给每个交接点命名事件（如出题完成/作答完成/批改完成）。
2. 每个子智能体写触发规则条款：唯一唤醒信号 = 事件名；触发场景枚举清单；三禁声明。
3. 每个子智能体写 SOP 闭环条款：六步（收参数→前置自检→执行→产出自检→落盘→发布移交事件），并声明完成即退。
4. 写移交分支条款：产出含门禁结论时按阈值分支（达标→放行移交；不达标→重发上游事件回环），回环必须走事件。
5. 配留痕条款：每次事件触发与 SOP 各步各留一条记录，供门禁与审计核验。

## Faster Next Time

- 模板即抄："唯一唤醒信号=X事件；触发时机=场景1/场景2/场景3/场景4；禁定时、禁轮询、禁常驻监听；SOP=六步闭环；完成后发布Y事件并退出。"
- 合规自检信号：spec 中出现"定期""轮询""监听""等待触发""需要时"字样即违规或模糊，逐处整改。
- 反模式：把触发时机写成"主智能体需要时"（无事件可判）；用常驻监听替代事件；门禁回环写成自循环重试；SOP 只有步骤没有移交事件（链条断头，下游靠猜）。

## Applicability Boundaries

- 适用：有事件驱动公约或多智能体交接链的平台，spec/配置层定义子智能体行为契约。
- 不适用：允许定时任务的场景（三禁条款无意义）；单 Agent 无交接链的简单流程（事件命名是纯开销）。
- 平台相关性：模式通用，事件名与通道实证于码道 CodeArts Agent（事件通道 H1–H7 承载），跨平台时事件通道名需按平台映射。
