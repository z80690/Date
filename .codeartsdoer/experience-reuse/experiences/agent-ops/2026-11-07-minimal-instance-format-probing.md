# 平台配置实体持久化能力验证：预留载体实查 + 最小实例反推格式法

## Scenario
需要验证"后端（主智能体）能否直接生成/批量注册某类平台配置实体"（如自定义子智能体定义），但官方文档不可得或未覆盖该细节。此时可行性判断不能笼统回答可行/不可行，必须拆分实证，且程序化批量生成的文件格式契约不能靠猜。

## Key Signals
- 磁盘上存在平台预留的载体目录（如 roles/、scene/ 类配置目录），但**全空**——载体在、实例零，格式无参照。
- 同类能力存在**自动注册先例**（如技能文件创建后自动生效注册），提示平台有"落盘即注册"的等价逻辑可类比。
- 运行时派工能力（Task 工具派独立会话 Worker）已有多次实战成功，且存在可实查的**会话存档目录**作为实证。

## Essence
把"可行性"拆为**三态**分别取证，核心差异在于运行时能力与持久化注册能力是两类问题：
1. **运行时调用能力**：以隔离会话实战 + 会话存档目录为证，属"可行已验证"。
2. **持久化注册能力**：以磁盘载体存在性 + 真实实例格式为证；载体存在但无实例 = "部分可行/待实证"，二者不可混谈。
3. **格式契约获取路径**：文档缺失时，用"最小实例反推格式"补齐——先有一个真实实例，再程序化复制其格式。

## Approach
1. **实查磁盘预留载体**：检查平台预留配置目录的存在性与其下是否有实例文件（存在但全空是关键中间态信号）。
2. **分离两类能力并分别归档证据**：运行时派工 → 找历史会话存档；持久化注册 → 找实例文件与格式。逐态给出"可行已验证 / 部分可行待实证"的显式结论。
3. **设计最小实例反推路径**：请用户在官方前端手工创建 1 个最小配置实体 → 后端实查其落盘文件结构（字段、命名、目录归属）→ 格式确认后即可程序化批量生成。
4. **以同类先例作等价逻辑参照**：若平台某类资产（如技能）已有"文件落盘即自动注册"先例，可作为目标资产批量生成的类比依据，但格式仍须实测确认。
5. **待实证项显式标注**：未实证的部分在结论中明确标"待实证"，禁止以先例类比替代格式实测。

## Faster Next Time
- 先查"同类能力的自动注册先例"，再查预留载体目录，两步即可把可行性问题收敛为"格式待反推"这一具体缺口。
- 用三态表述（已验证/待实证/建议路径）代替二值结论，避免后续被笼统判断误导返工。
- 格式未实证前禁写批量生成代码；最小实例是最短路径，胜过反复猜测目录结构。

## Applicability Boundaries
- 适用于：平台能力验证、官方文档不可得或未覆盖、配置实体有持久化载体且需批量生成的场景。
- 不适用于：官方文档完整可直接查阅的场景（直接查文档更省）；仅运行时一次性使用、无需持久化的能力（不必走格式反推）。
- 平台相关性：方法为通用 Agent 平台模式；证据来自 CodeArts Agent 平台（主/子智能体体系），字段与目录结构细节不可跨平台照搬。

## Evidence or Examples
- 实查发现用户级与项目级的 agent-team/roles、agent-team/scene 目录均存在但全空；agents/ 目录用户级与项目级均空。
- Task 工具派工出题官/批改官/spec 三类子智能体实战多次成功，用户级 session/ses_* 目录即这些 subagent 会话的存档实证。
- 技能有"文件创建自动注册"先例（review-code 技能），而自定义子智能体无实例可参照格式。
- 官方文档站当时被 WAF 人机验证拦截，文档检索路径受阻，进一步凸显本地实证 + 最小实例反推的必要性；该受阻处置见 debugging 类姊妹经验。
