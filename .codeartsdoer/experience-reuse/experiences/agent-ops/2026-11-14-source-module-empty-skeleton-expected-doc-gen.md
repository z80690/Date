# 有源码模块但预提取产物缺失的知识文档生成第三形态：骨架空/切片少先查语言支持范围判预期，按派工建议源文件定向直读

## Scenario

以 subagent 身份承接代码仓知识文档模块派工，模块是有源码的（第三方开源项目的一个应用框架与部署配置层，约 62 文件、以 PHP 为主），但派工单声明：符号骨架为空（该语言不被符号扫描器支持）、切片产物仅 1 条（"PHP 产物极少属预期"），并同时提供"源码建议"名单（抽读页面装配框架、建库入口、配置模板三个关键文件），其余文件用目录列举确认。模板、`.code-links.json` 契约、粒度约束（全文 ≤5KB、架构小节 ≤300 字）与敏感信息禁令齐备，subagent 独立执行、不可中途向派工方确认。

## Key Signals

- 模块清单含大量源码文件（.php）但符号骨架为空——既不符合"清单全是 .md → 空属预期"的纯文档模块形态，也不满足"骨架健康 → 骨架先行"的前提，恰好落在两条既有经验路径之间的判定缝隙。
- 派工单直接给出空因：语言不被符号扫描器支持 → 骨架空是**该语言形态的预期**而非提取故障；声明与"清单含源码 + 骨架空"的形态自洽，不进入排错。
- 派工单的"源码建议"名单实质上把骨架原本承担的"装配枢纽定位"职能前置到了派工方：框架装配文件、入口文件、配置模板各指定一个，枢纽选择无须 subagent 自行推断。

## Essence

预提取产物"空/少"的判定单位是**语言×模块**，不是仅看模块形态：源码模块骨架空有两种成因——① 语言/文件类型不被符号扫描器支持（天然空，属预期，走直读路径）；② 骨架统计失真（异常，切行号权威源）。先按语言支持范围定性空因，再选阅读路径。无骨架时的阅读降级路径是"**派工建议源文件定向直读 + 全目录列举确认结构**"：枢纽名单由派工事实包承担，其余目录用列举而非通读；行号取证同步回退为"直读时记录、交付前对照源码核实"，不存在骨架锚点可抄。

## Approach

1. **空因定性**：清单含源码但骨架空/切片少 → 先查空因。派工单已声明语言不支持 → 采信其"属预期"结论直接走直读路径；无声明 → 用最小代价验证（确认符号扫描器的语言支持范围，或抽查模块文件类型分布），不进入提取排错循环。
2. **定向直读**：按派工"源码建议"抽读关键源文件（本例 6 个文件内收口：页面装配框架、建库入口、配置模板、部署编排、入口页、数据库适配），其余结构用递归目录列举确认，不通读。
3. **行号同步取证**：直读时记录被引代码的行号，code_refs 随文档写作同步完成，交付前对照源文件核实；无骨架时可抄，此步是行号唯一来源。
4. **架构小节按装配写**：页面生命周期、适配分支、子目录职责各一句，用"- **子包名**：一句话"格式覆盖全部子目录，禁罗列文件清单（违反粒度约束）。
5. **敏感值脱敏**：源码模板/部署编排文件含默认凭据时，文档只描述"存在哪些配置项及其用途"，值一律用占位符，不复述真实值（通用写作纪律见 `2026-11-14-config-doc-sensitive-placeholder-discipline`）。
6. **噪音留痕**：写盘后 IDE 推送的目标项目 LSP 报错按路径归属甄别（诊断 file 不在本次产出集合内即为无关噪音），留一句甄别说明后继续交付。

## Faster Next Time

- 一行判定链：清单全 .md → 纯文档模块路径；含源码 + 骨架健康 → 骨架先行路径；含源码 + 骨架空 → 先查语言支持范围：不支持 = 预期，走本经验直读路径；支持 = 骨架不健康，切换行号权威源而非硬找锚点。
- 派工建议源文件名单 = 免费的枢纽清单：派工方已核实过结构时，其"建议抽读"名单直接当枢纽列表用，无须自行推断装配枢纽。
- ROI：6 文件定向直读 + 目录列举 ≈ 全模块通读的零头；行号取证与直读同步，免写完回头全仓定位。
- 警惕信号：派工单没解释骨架空因且清单含源码 → 不要默认"属预期"，先做最小验证再定路径。

## Applicability Boundaries

- 适用：有源码模块的知识文档全新生成、预提取产物因语言不被符号扫描器支持而空/少的场景（PHP 等脚本/过程式语言典型）；subagent 独立执行派工模式，平台无关（CodeArts 类 IDE 实证）。
- 不适用：骨架健康可用（骨架先行与锚点复用见 `2026-11-14-skeleton-first-targeted-read-module-doc-gen`）；纯文档/笔记模块（见 `2026-11-14-md-notes-module-doc-gen-stale-ref-verify` 与 `2026-11-06-doc-repo-zero-extraction-knowledge-gen`）；骨架对本次变更文件失真（行号权威源切换见 `2026-11-12-prompt-snippet-authority-over-stale-skeleton-anchors`）。
- 与相邻经验分工：本条补齐"清单含源码但骨架空"的第三形态，与前两条经验构成"骨架健康 / 纯文档 / 语言不支持"三分支判定链；写盘后 LSP 噪音甄别复用 `2026-11-13-lsp-diagnostics-path-attribution-triage` 结论。
- 证据等级：单次顺畅闭环（62 文件模块：空骨架 + 1 条切片判预期 → 6 文件定向直读 → 约 3.9KB 文档 + 22 条 code_refs 一次交付，无返工），无失败对照；"语言支持范围定性空因"的判定链为基于派工声明的合理归纳，复用中验证。
