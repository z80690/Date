# 执行存在配套"环境适配契约"技能的流程时，主技能加载后、首条脚本执行前伴随加载配套技能

## Scenario

执行一个有既定脚本链的主技能流程（本例 Wiki 增量更新：需要连续执行符号提取、影响查找、patch 合并等多个带长路径参数的 Python 脚本）。本机此前已演化出配套的执行适配技能，记录了该流程在本机环境（bash 运行时、路径格式、参数契约）的已知坑与修复模式。本次执行只加载了主技能，未伴随加载配套技能，首条脚本命令即踩中 WSL 路径坑（盘符路径被相对拼接报 FileNotFoundError）。执行者独立运行、无法中途确认环境差异。

## Key Signals

- 经验检索上下文（hook 注入）中出现标题含"执行适配/执行契约/环境怪癖"的条目且主题与当前流程直接对应——这是配套技能存在的显式提示，但注入的是经验条目摘要而非技能本身，需主动加载。
- 首条脚本执行即失败且失败模式"眼熟"（此前同类流程踩过并修复过）——说明坑已被记录过，只是本次执行前未进入上下文。
- 主技能文档描述的是通用流程，不含本机环境差异信息；本机差异信息沉淀在另一个演化技能里——两者的分层关系本身是"该伴随加载"的结构性信号。
- 流程具有周期性（定时任务/高频重复），同一执行者或同类执行者会再次进入该流程，踩坑会复利。

## Essence

这是知识的"可发现性"缺口而非知识缺口：修复模式早已落盘，但执行时未加载，等于不存在。执行有配套适配技能的流程时，**主技能加载完成即应检索并伴随加载配套技能，让已知环境契约先于第一条命令进入上下文**；判据不是"是否已经踩坑"，而是"该流程是否存在配套执行契约技能且本机环境与其记录形态相关"。配套技能的触发条件若未覆盖"伴随加载"场景（只在踩坑报错后才被检索命中），应补强其 description 的触发时机——从"报错后排查"前移到"流程执行前置加载"。

## Approach

1. **加载主技能后即查配套**：识别当前流程领域在本机是否已有配套的执行适配/怪癖类技能（来源：经验检索注入条目的指向、项目演化技能库清单）；有 → 立即加载，不等到报错。
2. **吸收契约后再写命令**：从配套技能提取与本轮直接相关的环境契约（路径格式、参数形态、脚本运行时），在生成第一条脚本命令前完成吸收——契约先于命令，而非命令先行再补救。
3. **注入条目视为指向标**：经验检索上下文中命中的"执行契约/适配"类条目，其正文通常源自配套技能——按条目来源找到技能本体并加载，比只读条目摘要获得更完整的契约面。
4. **无配套时的降级路径**：确认无配套技能时按通用环境探测执行（先短命令探测 bash 运行时类型，再写长命令），并把新踩的坑沉淀为新契约或新技能，补齐伴随加载的物质基础。
5. **演化反馈**：踩坑闭环后若发现配套技能的触发条件未含"前置伴随加载"，推动修订其 description 触发时机，让下一次执行在加载主技能时即被引导伴随加载。

## Faster Next Time

- 快捷信号：主技能流程含脚本链 + 本机非默认环境（WSL、特殊 shell、路径映射）→ 必查配套适配技能；经验注入条目主题与当前流程重合且含"契约/适配/怪癖"字样 → 即为配套技能指向。
- ROI：一次伴随加载（读一个技能文件）换取跳过"踩坑→试错修复→重跑"至少一轮往返；周期性流程下该收益按执行次数累乘。
- 反模式：把经验注入条目当纯背景读完即弃、不追技能本体；主技能加载完直接开写命令；踩坑修复后不回写配套技能（坑只修复未沉淀，下轮照踩）；以为"修复成功"等于闭环而不补触发条件。

## Applicability Boundaries

- 适用：主技能 + 配套执行适配技能的分层技能体系；周期性重复且依赖本机环境细节的脚本链流程；执行者环境与技能作者环境不一致的场景。
- 不适用：无配套技能的一次性流程（无沉淀可加载）；纯文档类主技能（无脚本链、无环境耦合）；配套技能内容与当前流程领域无关的误命中（按主题重合度判断，不强加载）。
- 平台边界：实证载体为 CodeArts Agent（主 Agent 加载技能 + 经验库 hook 注入 + 演化智能体修订技能）；"先加载契约再执行"的纪律本身是通用 Agent 模式，不依赖特定平台。
- 与相邻经验分工：skill-doc-env-mismatch-fallback 管技能文档与环境不符时的现场降级，本条管"配套适配技能存在但未被加载"的可发现性问题——前者是执行中适配，后者是执行前加载，时机不同。
