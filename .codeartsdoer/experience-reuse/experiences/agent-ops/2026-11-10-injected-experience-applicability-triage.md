# 注入经验指导段的适用前提分诊：吸收回标、前提不成立的裁剪显式声明、不适用条目弃读

## Scenario

主智能体派工 spec-design-agent 执行 SDD design 阶段任务（承接已确认的 571 行 EARS 规格，产出 design.md）。派工 prompt 内嵌平台 hook 自动注入的"经验检索上下文"：关键词提取记录、相关经验清单（带精排依据）、任务经验指导（带来源）。注入的指导条目全部来自 spec 阶段经验（约束→EARS 翻译、规格重做差异分流等），而本次任务是 design 阶段；深读的经验又含"三纪律"式方法论模板，其中第三纪律有明确适用前提（规格含未闭合裁决项）。执行者需在动笔前决定：哪些注入内容真正适用、哪些必须裁剪。该场景在每次派工都会出现，高频复用。

## Key Signals

- 注入条目按关键词/场景精排命中而非按适用前提筛选——"检索相关"≠"当前适用"。
- 注入指导的阶段属性与当前任务阶段不一致（spec 阶段方法论出现在 design 阶段派工单里）。
- 深读的经验方法论含条件分支（"若规格含未闭合裁决项→设预设承接章节"），前提是否成立需用任务事实核对。
- 硬套症状：设计文档章节骨架出现与任务事实无关的仪式性章节；或把 A 场景纪律（重做差异分流）套到 B 场景（全新设计）上。

## Essence

注入经验解决的是检索相关性，不解决适用性；经验复用的正确消费姿态是逐条核对适用前提后做**三态处置**：①吸收——前提成立，吸收为核心纪律并在产物中来源回标；②裁剪——方法论某分支的前提不成立，显式声明该部分"不需要+理由"，而非默默忽略或硬造空章节；③弃读——整条与任务场景不匹配（如阶段错配），不深读不引用，深读预算只花在适用条目上。机械全盘应用的两个直接后果：为不存在的前提造空章节（设计文档出现无内容的承接/裁决章节）；对非目标场景套错纪律产生噪音甚至越权裁决。分诊不是拒绝复用——裁剪时须保留与母经验的关联并写明理由，维持溯源链可审计。

## Approach

1. 通读注入指导段，逐条提炼每条经验的"适用前提"（方法论的条件分支写出来，如"第三纪律前提=规格含未闭合裁决项"）。
2. 用任务事实核对前提：从派工单与上游文档版本记录读出事实（如"v1.1 全部条款已确认、无未闭合裁决项"），不凭印象判定。
3. 三态处置并留痕：前提成立→列入关键纪律清单并标注来源 id；前提不成立→在吸收声明中显式写"X 章节/纪律不需要（理由：前提不成立的任务事实）"；整条不匹配→仅凭摘要定性，不投入深读。
4. 深读预算按适用性分配：只对吸收条目 read 全文；对注入清单中同任务不匹配的条目弃读。
5. 产物内回标：正文采用的每条纪律落点标注（来源：经验 id），延续注入指导段的溯源闭环要求。

## Faster Next Time

- 收工检查单：吸收声明里是否出现"不需要/不适用+理由"的显式裁剪？每条被采用的纪律是否带来源 id？未深读条目是否已凭摘要定性（而非漏看）？
- 预警信号：产物章节骨架出现与任务事实无关的承接/裁决类章节＝硬套症状，回头检查分诊是否遗漏。
- 效率收益：深读预算集中到 1-2 条真正适用的经验，避免逐条全读；裁剪声明一次写清可避免用户质询"为何缺某章节"。

## Applicability Boundaries

- 适用：任何含经验检索注入段（平台 hook 自动注入或派工单内嵌）的主/子智能体消费场景，不限 SDD 流程。
- 不适用：无注入、主动检索场景——主动检索本身已隐含适用性判断；但"核对前提再应用"的纪律仍可复用。
- 通用 Agent 模式，不绑定特定平台；分诊对象是经验条目，不适用于普通需求约束（约束须全量承接，见约束盘点类经验）。

## Evidence or Examples

- 本次 trace 实录（ses_e3a76558fffeJ5OaAXOblCvPar）：注入指导段含 3 条经验来源（spec 阶段方法论：约束→EARS、门禁切分、规格重做分流）；执行者按"与设计阶段直接相关"标准深读 2 条（design-stage-large-spec-inheritance-discipline、fuzzy-success-word-to-judgeable-closure），未深读 spec 阶段条目；吸收声明中显式写"本 spec 无未闭合裁决项（v1.1 全部条款已确认），故'预设承接'章节不需要"；design.md 中各纪律落点均带"（来源：经验 id）"标注；落盘收工时产物无空章节（grep 章节锚点核验四大章节完整）。
- "注入条目未被机械套用（spec 阶段指导未出现在 design 产物中）"为从 trace 行为归纳的推断；"硬套产生越权裁决"的后果推演无反例数据支撑，属预防性判断。
