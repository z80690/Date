# 派工单内嵌关键实证事实包（主智能体会话记忆向子智能体的结构化迁移）

## Scenario

主智能体通过 Task 工具向持久化子智能体（agents/*.md 注册）派工 SDD design 阶段任务。子智能体会话完全隔离，无法看到主智能体会话中积累的实证结论（平台机制实证结果、环境怪癖、资源状态、约束清单）；若不预置，子智能体要么重新调研（成本高、结论可能漂移），要么凭推断落笔（把猜测当事实写进下游产物）。

## Key Signals

- 派工单正文单列一段"关键已实证事实（设计依据）"，按主题打包：持久化子智能体格式契约、注册机制（落盘即注册+listSkills 实证）、环境怪癖（EdgeOne 拦截华为云文档站）、资源状态（mcp_settings.json 为空、cairn-mcp 可运行）、硬约束清单（禁定时任务/禁改 .mdc/不删文件）。
- 子智能体接到派工单后未做任何重复调研，直接进入存量文件实查与设计产出，一次对齐成功。
- 下游设计文档对每个机制引用均标注"实证值 vs 推断待实测"，事实包提供的实证基线是这一区分的前提。

## Essence

子智能体的判断基线完全由派工单构成——派工单不仅是任务说明书，更是子智能体唯一的世界观来源。把主智能体已实证的关键事实结构化打包预置进派工单，等于把主智能体的会话记忆迁移给子智能体：既消除重复调研成本，又防止子智能体独立调研得出与既有实证矛盾的结论，避免同一项目出现"第二事实源"。事实包必须区分实证与推断，推断部分显式标注，否则事实包本身就成了新的污染源。

## Approach

1. **派工单维护固定事实包段**：模板化为"关键已实证事实（设计依据）"一节，置于任务目标之后、具体要求之前。
2. **按证据类型分组打包**：格式/机制契约（附文件路径实证来源）、平台注册行为、环境怪癖（网络拦截、编码等）、资源状态（配置文件现值、二进制可用性）、硬约束（禁用项/红线，单列防遗漏）。
3. **每条事实附证据锚点**：写明来源文件路径或实证动作（如"test_mini 实证：listSkills agents 字段自动挂载"），让子智能体可按需复核而非盲信。
4. **实证与推断分离标注**：已实证结论直接给值；仅有推断依据的给推断值+"待实测"标注，禁止混写。
5. **子智能体侧纪律**：事实包视为基线，禁推翻、禁重调研既有实证项；发现事实包与磁盘证据矛盾时以证据实况回退并呈报，不静默采信任一方。
6. **派工前刷新时效**：事实包条目须与当前磁盘状态核对过才可写入，过时事实（如配置已变更）不打包。

## Faster Next Time

- 主智能体派工模板预置"事实包"空段，派工前按当前任务相关性填入——只放与本次任务相关条目，禁全量倾倒（无关事实稀释信噪比）。
- 警惕信号：子智能体在设计产物中出现与事实包矛盾的表述，或对已实证项重新发起调研——立即检查事实包是否缺失或标注不清。
- 事实包与"推断值登记区"配合使用：包内实证条目是设计阶段区分实证/推断的判定基准。

## Applicability Boundaries

- 适用：主→子智能体 Task 派工（隔离会话）；跨会话接力任务；项目存在大量前期实证结论且下游任务强依赖这些基线的场景。
- 不适用：同一会话内直接对话（上下文已共享，重复打包是噪声）；全新探索任务无实证可打包（应打包的是约束与降级路径而非"事实"）。
- 边界：事实包的可靠性受制于主智能体打包时的核验纪律——未刷新就打包的过时事实会以"实证"名义传导错误基线；子智能体对事实包的"以证据实况回退"纪律是最后的防污染屏障，不可省略。
- 平台标注：经验证于 CodeArts（码道）平台 Task 派工机制；打包结构本身为通用 Agent 模式，可迁移至其他主/子智能体平台。
