# 考教分离下作答方接触 key 的结构化自披露与独立性保全

## Scenario

考教分离考核流程（出题官/作答方/批改官三方上下文分离）中，作答方在作答前因流程性核验任务接触了评分标准文件（key）的部分内容——典型触发：批改包自检清单要求"题号-key 对照抽验"，或主智能体需先核验 key 格式才能放行后续流程。作答完成后，接触事实成为审计疑点。

## Key Signals

- 作答卷无法解释"为何作答前读过 key"，独立性声明缺失时批改方只能凭猜测裁定。
- 无既定处置规则时容易两极化：要么整卷作废重考（过度），要么沉默跳过（审计断链、被质疑放水）。
- 派工清单中"接触 key 的核验步骤"排在作答前，事后才被识别为独立性风险。

## Essence

接触本身不必然破坏独立性；隐瞒与过度反应（废卷重考）都会损害流程可信度。正确处置是把"接触"转化为显式审计信息：**自披露接触范围 + 声明作答独立依据 + 交由独立批改方裁定是否构成障碍**。核验需求应当尽量前置消除（后置或旁路），消除不了才走披露路径。

## Approach

1. 作答前梳理接触事实：何时、为何（引用触发它的核验条款）、接触到什么范围（题号区间与深度——仅格式/对应关系，还是答案要点）。
2. 作答卷头部固定位置写入独立性声明：逐项列出接触范围 + 明确"本卷作答一律以材料原文为依据组织，不以 key 表述为准"。
3. 归档时声明随卷进入批改包，由独立批改官按既定分支裁定：无证据表明依赖 key 作答 → 如实记录、不据此改判；有证据（答案与 key 表述高度雷同且材料原文无此表述）→ 按泄露事件处理，作废重考。
4. 出题/派工清单设计时前置规避：把"key 格式核验"类任务移到作答归档之后，或改为不读 key 内容的旁路核验（仅核对文件存在性、行数、题号计数）。

## Faster Next Time

- 预防优于披露：派工清单中凡要求接触 key 的核验步骤，先检查是否必须在作答前执行——能后置就后置，能旁路就旁路。
- 判据一句话：接触"格式与题号对应关系"可自披露继续；接触"成段答案要点"直接触发重考。
- 批改包三件齐套自检（题目/key/作答）中的 key 检查项，改为数量与对应关系校验即可，禁读内容。

## Applicability Boundaries

- 适用：任何考教分离/盲评流程（三方分离）中作答方因流程性任务接触评分标准文件的情形；不限于特定平台。
- 不适用：作答方与批改官为同一上下文（无独立性可言，应先修架构）；批改官自身读 key 属职责内，无需披露。
- 边界约束：自披露路径仅适用于"最小、流程性、非答案主体"的接触；大面积实质接触不走披露，直接重考。
