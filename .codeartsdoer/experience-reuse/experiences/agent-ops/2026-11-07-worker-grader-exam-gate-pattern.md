# 考核/开工门禁的角色分离设计：独立出题官与批改官双上下文，双参数门禁+补学闭环

## Scenario

- 通用多代理模式（非特定平台）：学习考核/产出验收场景中，"产出（Worker）"与"验收（Grader，含出题官）"由角色分离、上下文隔离的代理分别承担。
- 典型触发：派工单含"学不会禁止开工""旁人出题、出题官批改、禁自判学会"类条款——Agent 必须通过能力考核才能进入下一阶段，但自出自考存在利益冲突；或作答方自带自我评估（如自评掌握程度）且该评估将作为开工依据。
- 规模参考：50 题量级批量语义作答（概念辨析/架构选型/工程决策场景题），出题官+批改官双角色。

## Key Signals

- 约束含"旁人/第三方/禁自判"字样，而执行主体是单一 Agent；
- **自评失真是默认假设**：作答方对自己的产出给高自信度是系统性倾向，自评值不可作为门禁输入；
- 通过标准不量化（"学懂了""差不多了"）时门禁不可判定；
- Worker 与 Grader 若为同一会话/同一上下文，判定会被作答过程锚定（先入为主），失去独立性；
- 批改若无逐题依据留痕，门禁结论不可复核，等于没有门禁；
- 考核材料本身有获取风险（如网络依赖），材料不可得时门禁会死锁。

## Essence

"旁人/独立评审"在多 Agent 系统中的等价物是**角色分离的独立 subagent**：出题官、批改官与被考核 Agent 上下文隔离，复刻人类组织的利益冲突隔离。关键差异在于："产出"与"验收"必须是两个独立上下文的两次调用，而不是同一代理的两次思考。门禁模式由四个要素构成：

1. **角色分离**：出题官、批改官均以独立会话启动；批改官只读题目、key、作答三份材料，禁止接触作答方的自我评估；
2. **独立自信度**：综合自信度由批改官独立给出（0–100%），明确不受作答方自我评估影响；
3. **双参数门禁**：作答覆盖率 100%（逐题硬标准，完整性）+ 综合自信度阈值（如 ≥80%，质量），两条同时满足才放行；门禁是放行条件而非软建议，不达标则后续阶段任务封存；
4. **不达标闭环**：批改官必须输出薄弱角度清单与补学方向，把"拒绝"变成"下一轮学习任务"，避免死循环或随意放行。

批改纪律配套两条：从严判定禁放水；判定必须给依据（每题一句依据，可复核）。

## Approach

1. **角色转译**：把"旁人"落为独立 subagent（出题官、批改官），与被考核方无共享上下文，禁止自出自判；
2. **出题侧**：按学习材料（论文/项目）× 审视角度拆分题目维度，每维度固定题量（如 10 题）；题量、通过率、自信度阈值写入 spec 供用户对齐（出题任务的派工契约格式见关联经验）；
3. **批改侧派工即定纪**：给批改官的任务提示写明四要素，并显式声明"综合自信度由你独立给出，不受作答方自我评估影响"；
4. **限定输入**：批改官只读三份文件（题目/key/作答），屏蔽作答方的自评与过程叙述，防止锚定；
5. **收口输出**：要求批改官返回 ≤150 字收口报告（统计 + 自信度 + 是否达标），供主代理机械核对门禁；逐题判定与折算方法见关联经验（批改 rubric）；
6. **材料降级路径**：为考核材料（论文/项目）预设获取失败时的降级途径（多渠道、可替代来源），防止门禁死锁；
7. **分支处理**：达标 → 放行开工；未达标 → 把薄弱角度清单作为补学任务回注 Worker，形成"作答→批改→补学→再作答"闭环，直到达标或触发停止条件；
8. **结果留痕**：考核记录/批改报告写入 spec 定义的可验证字段，作为门禁放行证据；主代理只消费结论字段（PASS/PARTIAL/FAIL 数、自信度值、达标布尔），不重跑批改过程。

## Faster Next Time

- 直接复用四要素任务提示模板派工批改官，无需每次重新设计考核流程；单轮批改（一次读三件套 + 一次写报告）即可出结果；
- 早期信号：若作答方自评与批改官判定差距 > 10 个百分点，说明自评通道已不可信，后续一律以批改官值为准；
- 遇"禁自判/第三方验证"类要求，先找"独立 subagent 角色分离"落地方案，不要拒绝执行也不要假装已验证；
- 反模式警示：被考核 Agent 自出自判；把自评作为门禁输入；考核未量化即放行；批改官看到作答过程细节破坏独立性；材料获取无降级路径导致门禁死锁。

## Applicability Boundaries

- 适用：有 subagent/多角色机制的 Agent 平台（主 Agent + Subagent 架构均可）上的能力认证、评审把关、开工准入类门禁；单用户强确认文化的工作流。
- 不适用：无 subagent 能力的单角色 Agent（退化为用户人工出题判卷）；无客观 key 的开放式创意产出（缺"矛盾即 FAIL"的判定锚点）；产出可被自动化测试完全验证的场景（此时直接跑测试，无需批改官）；非考核类的常规任务（角色分离是纯开销）。
- 前提：门禁阈值（如 80%）与覆盖率要求应由项目规则预先冻结，批改官只执行不制定标准。
- 分工边界：本篇只管"考核者选任、上下文隔离与门禁裁决"；逐题判定口径与自信度折算公式见 workflow/2026-11-07-independent-exam-grading-rubric.md；出题任务本身的派工契约见 workflow/2026-11-07-exam-question-authoring-contract.md。

## Evidence or Examples

- **设计阶段实例**（2026-11-06，ses_e4ee545ecffetg5iXD9Tdm4vgS）：派工单"强制学习"条款（5 篇论文多角度 + 5 个项目正反例）落为 `.codeartsdoer/specs/kb_arch_foundation/spec.md` 前置考核门 M1–M4：出题官=独立 subagent、每角度 10 题、100% 作答、出题官批改禁自判、综合自信度 ≥80% 方可进入架构设计（§5.1–5.4）；
- **实测阶段实例**（2026-11-07，ses_e4d629bd9ffeg4S4QWbYvDcgS0，同项目 ST2 学习考核）：执行代理（Worker）完成 50 题作答并附自评；批改官（@general subagent，独立会话）依据题目/key/作答三份文件逐题判定，得 PASS 47 / PARTIAL 3 / FAIL 0，独立给出综合自信度 96%（折算基础 97%，扣轻微瑕疵 1%），双门禁（100% 覆盖 + ≥80%）达标放行；批改官同时列出薄弱角度清单（经验条目字段化、骨架章节数、审查验收对照），证明"达标"与"指出改进方向"可以并存，门禁不因放行而失去诊断价值；
- **证据链完整性**：本模式经历"spec 设计（M1–M4 门禁成文）→ 运行验证（批改报告 st2-exam-review.md 可整卷复核）"两个阶段，设计假设（独立 subagent 可担任出题官/批改官、双参数可判定、不达标可闭环）均获实测支撑。
