# 外部视频链接内容核对：截图 VLM 核对模式与完整还原路径分流决策

## Scenario

用户贴出外部视频平台链接（头条/抖音/B站等）并附一张视频截图，要求"看视频内容"或核对视频信息，且常限定任务范围（"只需要核对信息，其他不用干"）。此类请求高频出现，且用户往往默认 AI 能"看视频"。本条覆盖该请求族在**无视频下载工具链/未获安装授权**前提下的默认处置模式；若用户需要完整内容且示意可自主装工具，转入完整还原流水线（见关联经验）。

## Key Signals

- 请求对象是视频动态内容（可播放媒体），而非静态图片或文本。
- 链接指向外部平台页面，浏览器工具即使能打开页面也无法回读视频内容（见关联经验）。
- 可用输入只有用户附带的截图：某一帧定格画面 + 页面文字信息。
- 截图地址栏/页面上的长数字串（如 19 位视频 ID）经 VLM OCR 识别后，与用户提供的 URL 中数字出现排列不一致。
- **升级分流信号**：用户明确批评"只声明看不了"的回答并示意自主解决（"你可以做个切片嘛""安装个工具"）→ 截图核对模式不足以收口，转完整还原流水线。

## Essence

- **决策分流**（本条与完整还原流水线经验的分工规则）：诉求是"核对信息"（标题/账号数据/字幕要点/发布信息）→ 本条截图核对三段式即可收口；诉求是"看完整内容"且允许安装工具 → 直接走下载还原流水线（yt-dlp→抽帧→转写→OCR，见关联经验），勿在截图核对模式上停留。
- 无下载工具链前提下的可交付物 = 基于截图的 VLM 静态识别核对；结论前置声明本模式的覆盖范围（基于截图某一帧 + 页面文字，非视频动态内容）可避免虚假承诺与空泛回答。
- OCR/VLM 对长数字串（约 15 位以上）易抄错位；截图识别出的数字不可作为权威来源。与用户提供原文不一致时，两源不可互证；若存在可获取的第三方权威源（实例：下载视频本体读取真实 ID）可据此仲裁，否则交还用户核对原文，不猜测、不推理补齐。

## Approach

1. **先分流再动手**：判断诉求是"核对信息"还是"看完整内容"；核对 → 进入本条流程，完整还原且可装工具 → 转流水线经验（关联条目）。
2. 结论前置声明本模式覆盖范围：明确"当前基于截图（某一帧定格 + 页面文字）做静态识别核对，视频动态内容不在本模式覆盖内"。
3. 对截图执行 VLM/OCR 识别，输出结构化核对清单，逐项列出并标注来源为"截图识别，非视频本身"：视频标题、创作者及粉丝/获赞数据、可见字幕、发布时间、播放/赞/评/藏数据、画面内容。
4. 对长数字串做双源比对：用户提供的 URL 数字 vs 截图地址栏 OCR 数字。不一致时先查有无第三方权威源可仲裁（如可下载视频本体则以实录 ID 为准）；无仲裁源则声明"OCR 长数字易抄错、双源不可互证"，提醒用户自行核对地址栏原文。
5. 明确补救路径：如需完整内容，说明可经授权安装工具链走下载还原流水线，或请用户提供文字稿/更多关键帧截图。

## Faster Next Time

- 看到"视频链接 + 看内容/核对"先做一次分流判断再选模式：默认核对 → 本条三段式；用户示意"自己想办法/可装工具" → 直接跳流水线经验，避免在降级应答上白耗一轮再返工。
- 任何截图中的长数字（ID/单号/时间戳串）默认视为低置信，仅在与其他独立来源一致时才采信。
- 警告信号：同一数字串出现两个版本且其一来自 OCR → 先找第三方权威源仲裁（下载实录/页面结构化数据），找不到再走"交还用户核对原文"分支，不要尝试用推理补齐。

## Applicability Boundaries

- 适用：用户附带截图（或图片）+ 外部媒体链接的**信息核对类**请求；通用 Agent 模式，不绑定特定平台。
- 不适用：视频内容完整还原场景（有工具链安装授权且平台在 yt-dlp 支持列表内时，走关联经验的下载还原流水线，本条只覆盖截图静态核对）；本地视频文件（具备文件读取/多模态分析能力时走文件分析路径）；需要动态交互验证的场景（截图无法覆盖）。
- OCR 长数字不可信规则独立于视频场景，适用于任何长数字串的双源核对。
