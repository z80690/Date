# 子智能体编队规划克制准则：新增成员须先过不可合并论证

## Scenario

规划或重构多智能体体系时必须回答"一共定义几个子智能体、怎么构建"。放任增长会造出职责重叠的冗余成员；过度合并又会破坏独立性与门禁价值。需要一套可操作的克制决策准则，把"数量要克制"从口头原则变成决策流程。

## Key Signals

- 用户显式要求"数量要克制（每加一个须论证不可合并）"——这是编队规划的强约束信号，应转化为逐成员的论证义务，而非总体感觉上的"少建几个"。
- 存量资产盘点先行信号：平台内置 Worker 类型、既有技能、实战先例（出题官/批改官）、实验品（已禁用测试子智能体）都已在册——先看存量能否覆盖，缺口才新增。

## Essence

克制准则 = **默认不加、论证才准入**：

1. **不可合并论证**：每个候选新增成员必须给出"为什么不能并入其他成员"，核心论据是职责独立性被破坏的后果（如考核者合一 = 运动员兼裁判，门禁失效）。
2. **存量优先**：平台内置、既有技能、实战先例能覆盖的角色不新建。
3. **低频不持久化**：低频临时能力用运行时 Worker（Task 派工）按需实例化，不占持久化编制——常驻成员有维护成本与维护衰减风险（高引用 ≠ 高维护，星标框架也可能停更），常驻编制宜少。
4. **反设三方向**：对每个新增做反向假设——能否合一（并入相邻成员）？能否降为惯例（不设独立角色）？能否用工具/技能替代（不设智能体）？三问全"否"才准入。

克制 ≠ 最少：独立性有真实价值时（考核分离、上下文隔离）应保留独立成员，克制针对的是冗余。

## Approach

1. **列存量资产清单**：平台内置 Worker 类型、既有技能、实战先例、实验品，标注各自已覆盖的职责。
2. **起草编队完整清单**：每成员五要素（名称/职责/挂载技能/触发条件/与主智能体分工）。
3. **逐成员写不可合并论证**：引用既有独立性设计先例（角色分离 = 上下文隔离的利益冲突隔离）作为论据模板。
4. **跑反设三方向**：对每个"想新增"逐项检验合一/降惯例/工具替代，全部否定才进入新增流程（且须走功能准入流程）。
5. **实验品处置**：已禁用成员明确"不入编队但留存"，避免误用也避免误删。

## Faster Next Time

- 一句话决策规则：先存量后新增；新增必答"为什么不能并入"；低频用临时派工不占编制。
- 反设三方向 checklist：合一检验（职责能否并入相邻成员）、常驻化检验（是否低频到只需临时实例）、工具替代检验（一个技能/脚本是否就够）。
- 数量参照：本实例收敛结果 = 1 主 + 2 持久化 + 3 内置运行时 + 1 按需临时，**新增定义仅 2 个**——大多数需求存量已覆盖。

## Applicability Boundaries

- 适用：有多角色/子智能体机制平台的体系规划与重构；多代理框架（Router/Worker 编排）的规模决策。
- 不适用：单人单会话任务；已论证且用户裁决过的稳定编队的日常运行（克制准则只在规划/重构时生效）。
- 前提：存在可盘点的存量资产清单；用户或规则层已认可"新增须走准入"的治理约束。

## Evidence or Examples

- 实录（2026-11-07，ses_e4cdf992cffeY5nxZpoxvM1wZ2）：编队规划落为 spec v3 编队章，核心编队 = 1 主 + 2 持久化（出题官、批改官）+ 3 平台内置运行时（spec 三代理、bug-fix Worker）+ 1 按需（调研 Worker），实验品不入编队；新增定义仅 2 个持久化成员。
- 反设三方向实录：考核官合一 → 否定（考教分离，自批 = 运动员兼裁判）；调研 Worker 常驻化 → 暂缓（低频 + 维护衰减教训：高星多代理框架近 10 个月无推送）；编码专职智能体化 → 暂缓（既有技能 + 平台 Worker 已覆盖）。
- 新增构建路径：按已实证的 agents/*.md 格式契约后端生成，须先走功能准入五步（查复用评估表→归类→生成→登记→留痕）。
