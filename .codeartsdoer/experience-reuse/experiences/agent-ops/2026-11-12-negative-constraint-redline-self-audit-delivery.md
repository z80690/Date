# 负向红线约束的产物侧可审计交付：头部自查声明+正向语境限定+摘要复述三件套

## Scenario

多角色考核/派工链路（主智能体→出题官→批改官→放行判定方）中，派工单携带**禁止性红线**——以"禁出/禁含/禁引用"句式约束产物的语义内容（如考核出题派工单中"禁出某项目'某机制'相关题、相关题仅限另一项目语境"）。负向约束的固有困境：下游无法机械证明"产物不含 X"——文件存在性检查、字节数核验均无效，语义排除只能靠人读。若执行方仅在返回摘要口头声称"已遵守红线"，产物本身无合规证据，下游核验成本被转嫁给重读整条派工链。

## Key Signals

- 派工单红线以"禁出/禁含/禁引用/禁编"句式出现，且约束对象是**语义内容**而非可 grep 的字面字符串（换措辞即可绕过字面扫描）。
- 红线同时伴随**正向语境限定**线索（"X 相关内容仅限 Y 语境"）——这是把负向排除转为可核查正面边界的现成材料。
- 存在同名/易混概念干扰（如两个同名仓库、两个相近机制名），负向排除若不给语境界定，下游无法区分"内容违反红线"还是"内容属于允许语境"。
- 执行方产物为多文件交付（题目文件+key 文件类成对产物），红线合规需在**每个交付物**上独立成立，漏一处即链路破防。

## Essence

负向约束（"没做什么"）不可直接证明，唯一可行路径是**把验证成本前移到执行方自查，并把自查结论物化为产物内的可审计声明**。三个要点：① 自查声明引用红线**来源指针**（派工单/裁决注记的文件路径），使声明可回溯而非孤立口号；② 用**正向语境限定**替代纯负向排除——"禁止 X"翻译为"X 相关内容仅允许 Y 语境"，给下游一个可核查的正面边界，语义排除从"证明不存在"降级为"核对语境归属"；③ 自查结论在**返回摘要中复述**，主智能体收口时无需重读产物即可核对红线合规。本质与"存在≠语义"分层判定（前置自检证据化经验）同源：正向产出验其存在，负向约束验其声明——声明是把不可验证量转化为可审计量的唯一载体。

## Approach

负向红线交付三件套（执行方收到禁止性红线后逐件落实）：

1. **产物头部红线自查声明**：在每个交付文件的头部注记区写三要素——红线原文（或条款号）+ 红线来源指针（派工单/裁决注记路径）+ 遵守结论与覆盖范围（"本文件及关联产物均不含 X 内容"）。成对交付物（如题目文件与答案 key）须各自独立声明，key 侧声明额外覆盖"对应题目"。
2. **正向语境限定替代纯负向**：凡红线可转译为语境归属的，写成"X 相关内容仅允许 Y 语境"（可核查的正面边界），与负向禁令并列写入头部声明；同名/易混概念场景必须在声明中点名语境区分依据（哪个项目/哪个机制的哪种用法在允许范围内）。
3. **返回摘要复述自查结论**：完成摘要中单列"红线自查通过"一行（含红线名称），不展开细节；摘要同时遵守既有纪律（禁复述受控内容如 key 要点）。三件套外加一道机械兜底：落盘后对产物做红线关键词扫描（确认禁用词仅出现在"声明其不存在"的语境中），扫描结论写入自检留痕。

## Faster Next Time

- 三件套清单可直接复用于任何含禁止性红线的派工：头部声明（逐文件）→ 正向语境限定 → 摘要复述 → 关键词扫描兜底。
- 一句话自查：每条禁令先问"下游怎么证明我没做？"——答不出就补声明；每条禁令再问"能否转成仅允许什么？"——能转就写正向语境限定。
- 红线来源指针写入产物头部后，下游批改官/验收方核验红线合规只需读产物头部注记区，无需回溯派工链原文，核验成本从 O(全链) 降为 O(头部)。
- 警示信号：产物头部只有正向内容说明、无红线声明 → 下游应退回补自查；声明写了但无来源指针 → 声明不可回溯，视同未声明。

## Applicability Boundaries

- 适用：含禁止性/语义级红线的派工执行方（考核出题、文档生成、报告撰写、代码生成中"禁引用某机制/禁含某内容"类条款）；考教分离链路中下游需快速核验红线的场景；同名/易混概念语境区分场景。
- 不适用：可机械验证的负向约束（字面禁用词可直接 grep、行为禁用项可跑测试/扫描的——直接跑机械验证，勿以声明替代强验证）；纯正向约束（要求做什么的，走常规验收条款与证据文件）；红线仅约束执行过程而非产物的场景（过程约束用事件流水留痕）。
- 边界：自查声明是自律证据，不等于强验证——高价值/高风险场景应在批改或验收环节补一道独立机械抽查（关键词扫描+语境抽读）构成双保险；声明由执行方自写，其可信度依赖执行方已通过前置自检证据化流程（材料实读、范围锁定）。
- 平台：实证于 CodeArts（码道）平台主子智能体 Task 派工机制（出题官 subagent 隔离会话）；三件套为通用 Agent 模式，可迁移。
- 相邻经验分工：前置状态的正向证据重建（门禁语义/旧轮闭环/材料实读）见 agent-ops/2026-11-08-examiner-precheck-evidence-parallel-audit——该条管"动笔前证明前置成立"，本条管"落盘后证明红线被遵守"，前后衔接；红线的规格化条款化（派工方视角约束→EARS 条款→编号门禁）见 workflow/2026-11-06-constraint-dispatch-to-ears-gated-spec；题答分离双文件契约（本条三件套的宿主产物结构）见 workflow/2026-11-07-exam-question-authoring-contract。
