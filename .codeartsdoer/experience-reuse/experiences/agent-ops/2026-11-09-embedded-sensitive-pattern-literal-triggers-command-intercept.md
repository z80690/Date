# 命令文本内嵌安全扫描模式串触发平台拦截："解析目标路径失败"的内容型变体与扫描执行职责分离

## Scenario

Agent 为完成"事件纪律核查"（验证门禁脚本无定时器/轮询/守护进程/网络访问），把检测正则（含 `--watch`、`Start-Sleep`、`http://`、`Register-ScheduledTask` 等模式串）直接内嵌进 bash 命令文本执行扫描，命令被平台拦截。

## Key Signals

- 报错"从命令中解析目标路径失败"——与既有"多语句长命令被工具层拒绝"症状完全一致，容易误归因为结构问题。
- 关键差异：本次命令结构简单（几行赋值 + 一次扫描），仍被拒；同会话内第二次出现（补录核查结论时又把模式串写进命令）再次被拒——跨场景稳定复现。
- 触发面是**内容字面量**而非命令结构：轮询/定时/网络类检测模式串被平台安全检测视为敏感载荷；改走 Grep 工具立即成功。

## Essence

平台命令通道对命令文本的安全检测不止看结构（多语句/长度），也看内容——把"我要扫描这些危险模式"的正则字面量写进命令，等于把危险模式本身送进了检测器。既有经验的"长命令降级为脚本文件"对此**无效**（脚本文件内容同样在执行载荷里）；有效解法是职责分离：**扫描类操作走专用 Grep 工具（模式匹配由工具完成，命令文本不含模式串），结论回填走 Edit/write 工具（不走命令通道）**。

## Approach

1. 判型：命令被报"解析目标路径失败"时先看结构——无多语句/高嵌套仍被拒 → 疑内容型触发。
2. 职责分离改写：模式扫描 → Grep 工具（pattern 参数传正则，不经命令文本）；扫描结果落盘 → Edit/write 工具。
3. 禁忌：不要把敏感正则字面量（--watch、Start-Sleep、定时器/网络类关键词）拼进任何 bash/PowerShell 命令文本；也不要改写成脚本文件再执行（内容仍在载荷里）。
4. 需要动态正则匹配时，优先选支持正则参数的专用工具，而非命令内联。

## Faster Next Time

- 判别口诀："结构越精简越被拒 → 内容触发；换 Grep 工具一跑即过 → 实锤"。
- 执行"无 X 核查"类任务（无定时器/无轮询/无网络/无敏感词）时，第一步就规划 Grep 工具路径，不进命令通道。
- 预警：第一次被拦后把模式串"换个写法"塞回命令仍会被拦——换载体而非换写法。

## Applicability Boundaries

- 适用：带命令安全检测的平台（拦截报错含"解析目标路径失败"类统一文案）、需要扫描代码/脚本中危险模式的核查任务。
- 不适用：真正的结构型拦截（&&、多语句、超长命令）——按既有经验降级为脚本文件执行仍有效；模式串不敏感的普通文本处理。
- 边界：Grep 工具扫描目标须为文件路径（先落盘再扫）；跨平台拦截文案可能不同，判型依据是"结构简单仍被拒 + 换载体即过"。
