# 阶段状态机的运行契约：迁移三要素、唯一写者与非法迁移拒绝

## Scenario

多阶段长流程（盘点→环境→考核→设计→规则→实施）选定"阶段状态机+迁移守卫"作为流程管控机构后，进入落地运行。此时真正的问题从"选什么机构"变为"状态机怎么运行才不腐化"：状态字段存在事实源文档里，任何会话、任何角色理论上都能改；阶段推进若只改状态值不留证据，审计与回溯都会失效；流程被外部条件卡住时若无显式状态，卡死对外不可见。

## Key Signals

1. 状态腐化前兆：状态字段的更新没有固定入口，谁顺手谁改——出现"状态是 ST2 但没人说得清为什么不是 ST1"。
2. 迁移失证：每次状态跳转只有新值，没有"依据什么准出条件、什么证据、在哪登记的"三问答案。
3. 隐性卡死：某阶段依赖的外部条件不满足（如等待确认、网络不通），流程停在原地但状态机里没有任何"被阻塞"的表达。

## Essence

状态机防止腐化靠的不是自觉，而是三条运行契约：**①迁移三要素缺一即无效**——每次状态迁移必须同时具备"准出条件满足 + 证据链接（指向可查的验证产物）+ 变更日志留痕"；**②唯一写者**——状态区只允许一个约定角色（如"事实变更钩子"）写入，其他任何环节只能发起迁移请求、不能直接改状态；**③非法迁移拒绝 + 阻塞显式化**——不满足守卫条件的迁移直接拒绝，被外部条件卡住时迁入显式阻塞态（登记阻塞原因/恢复条件/回迁目标），而不是留在原态装作正常。

## Approach

1. 状态区落盘于单一事实源（如项目事实表专用章节），表结构固定三列：当前状态（含迁移理由）/ 最近迁移证据（指向产物路径）/ 阻塞记录（原因、恢复条件、回迁目标、进入时间）。
2. 定义迁移三要素检查单，每次迁移逐项核对：准出条件逐条满足？证据产物路径可查？变更日志已记一行？任一缺项即不迁移。
3. 指定唯一写者角色（项目中为事实变更事件钩子），在运行规则文档中明写"本区唯一写者=X"；其他环节的合法动作是"完成准出验证→通过写者触发迁移"。
4. 枚举合法迁移边（含回迁边），不在枚举内的目标状态一律拒绝；把枚举表写进运行规则文件供守卫核对。
5. 阻塞态（SX）登记模板化：进入时必填四项（原因/恢复条件/回迁目标/时间），恢复时按回迁目标重走迁移三要素——阻塞不是异常旁路，是状态机的一等公民。

## Faster Next Time

- 每次改状态前自问三句：准出条件过没过？证据在哪？日志记了没？——三句答不全就不许写状态。
- 审计一个陌生项目的状态机，先看最近迁移证据列是否为空：空=状态机已腐化，状态值不可信。
- 设计状态机时就把阻塞态画进去（含恢复边），不要等卡死再补——补出来的阻塞态永远缺恢复条件。

## Applicability Boundaries

- 适用：状态以文档/表字段形式人工维护、无独立流程引擎的多阶段流程（Agent 项目治理、派工单生命周期）；"唯一写者"模式依赖项目存在统一的事件钩子或固定执行角色。
- 不适用：由代码强制管制的状态机（写者约束由框架保证，无需纪律性契约）；阶段少于 3 且无审计需求的轻流程（契约成本大于收益）。
- 泛化说明：本契约提炼自一个 ST0→ST5+SX 全程实战项目；"唯一写者=事件钩子"为项目实现细节，泛化形态是"单一写者角色"。

## Evidence or Examples

- 实录：kb_arch_foundation 全程按契约运行——ST1→ST2 迁移留痕"准出四项全满足（Cairn 构建验证/Super-agent 实证/P3C 已验收/嵌套核查）+证据汇编路径+变更日志一行"；ST2→ST3→ST4 同构留痕，事实表 §5 三列表结构可查。
- 实录：写者约束原文写入事实表页脚："本区唯一写者=H7 on_fact_change；迁移三要素缺一即无效迁移。"
- 实录：SX 阻塞态在案期间保持"四项全空=当前无阻塞"的显式表达——即使从未触发，模板在位本身就是可审计的运行契约证据。
