# 实验性双路检索冲突时写路径不变量优先、实验继续而非终止

## Scenario

对既有机制做"引入第二检索/知识通道"的实验性评估设计时，需要为实验写判定标准：哪些结果算成功接入、哪些算仅作补充、冲突如何处置。触发条件：实验通道（新检索源）与权威通道（既有索引/登记机制）并存，双路对同一批主题给出可对比结果，实验报告是后续接入决策的唯一依据。规模：机制级只读实验，实验对象为有限主题集（本例 3 个主题查询）。

## Key Signals

- 实验判定标准草案中出现"结果冲突→终止实验"类条款——这是把冲突当故障处理的信号。
- 冲突信号本身携带信息（新通道返回与文件实况矛盾、疑似幻觉或过期内容的证据）——终止实验等于丢弃这些证据。
- 写路径另有唯一权威通道（索引唯一登记入口），实验通道即使继续运行也不会污染任何现行机制。

## Essence

核心张力是"实验安全 vs 决策数据完整性"。冲突正是实验要收集的决策数据：单点冲突不足以全局否决新通道，但必须留痕；而安全性根本不需要靠"终止实验"兜底——只要写路径唯一性作为不变量锁死（任何情形下写入只走权威通道），实验通道就是纯只读的，继续运行零风险。因此终止条件应只绑定不可恢复的工具级故障（检索连续多次不可用），不应绑定数据冲突；冲突主题记录对比结论（冲突详情+证据+不可信原因），剩余主题照常执行，全部完成后按综合判定收口。

## Approach

三个备选方案的取舍：

1. **冲突即终止实验**（原设计，弃）：冲突即最有价值数据，终止=放弃决策依据，且后续仍要重做实验补数据，成本更高。
2. **冲突即否决新通道**（弃）：单点冲突（可能是幻觉/过期内容）不足以全局判定，且不记录对比证据就无法审计否决理由。
3. **写路径不变量+冲突继续+综合收口**（采纳）：写路径唯一走权威通道（不变量，任何情形不变），新通道降为只读补充继续实验；冲突主题记录对比结论，实验按全部主题完成后的综合判定收口。

落地步骤：

1. 判定标准写三情形并显式单选：结果一致→可接入态；部分可补→补充态；冲突→冲突主题记录对比结论后继续，最终综合收口归入补充态。冲突不是独立态，是附带记录字段。
2. 退出条件重写：仅工具级故障（连续 N 次不可用）走异常登记并中止实验；数据冲突不触发退出。
3. 接口与数据结构同步：判定枚举从三态收敛为两态（接入/补充），原"退出记录"字段更名为"冲突记录"字段，语义从终止凭据变为对比结论载体。
4. 修订后全文档 grep 旧态名/旧术语清理残留（本次靠核验发现模块描述处仍残留旧表述"三态判定结论"并同步修正）。

## Faster Next Time

- 写实验判定标准时对每条终止条件自问：这条防的是"不安全"还是"不愉快"？冲突、偏差类信号是实验结论不是故障，应记录不应终止。
- 安全兜底放在写路径不变量上，与实验流程解耦——不变量保证"怎么继续都安全"，实验流程只管"收集什么结论"。
- 判定枚举收敛（三态并两态）时，立即 grep 被删态名与关联字段旧名，残留旧表述是最常见的波及遗漏。

## Applicability Boundaries

- 适用：只读评估类实验——新检索源/新知识通道/新工具的对比评估，写路径另有唯一权威通道；实验报告作为接入决策依据。
- 不适用：冲突可能造成写污染的场景（写路径不唯一时必须先终止实验排查，不能带冲突继续）；运行时 A/B 分流策略（那是流量治理不是实验判定）；工具级故障处理（走异常登记路径）。
- 重评触发条件：新通道拟从只读评估转正参与写路径时，本模式失效——须先走准入登记把写路径扩展为新不变量，再谈实验结论采纳。
- 证据等级：判定标准为设计阶段的用户裁决改判（原"冲突即终止"被改判），实验本身尚未执行；首次实验运行后若发现冲突处理细则不足，应回写本条。
