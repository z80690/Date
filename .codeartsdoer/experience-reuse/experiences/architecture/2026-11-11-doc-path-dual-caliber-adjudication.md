# 目录重组后文档路径双轨口径的核实与裁决

## Scenario
目录结构归拢/搬迁（如根目录内容收敛进工作区子目录）完成后的一段时间内，文档体系中会同时存在两套路径口径：一套是分区体系自身的"逻辑口径"（文档表格、约定中引用的分区内部目录名），另一套是"文件系统实际路径"（重组后的真实目录层级）。修订知识库或 README 时，这是一道必须主动裁决的取舍题而非默认改法：把所有旧目录名一律替换为实际路径，可能破坏分区文档的内部口径自洽；全部保留，则会让描述仓库构成的句子持续误导。

## Key Signals
- 派工单/变更说明断言"文档中的路径已过时"，但仅给出单一改法。
- 同一文件内出现两类路径写法：结构说明处写实际路径，表格/约定处仍写分区内部目录名。
- 文档中的目录名在文件系统根目录下已不存在（如被上移进工作区子目录），但在权威 README 的分区表格中仍作为正式条目出现。

## Essence
核心张力在于：分区表格的目录名是**分区体系的内部逻辑口径**（描述归档流向的约定命名），与**文件系统物理位置**是两个层面的事实；重组只改变后者，不自动作废前者。裁决准则：描述"仓库构成/代码在哪"的句子须对齐实际路径；引用分区体系自身约定（归档流向表、目录用途表）的内容保留内部逻辑口径。两套口径各自成立，不互为错误。

## Approach
1. 修订前先实读文件系统，验证实际路径存在性（旧路径是否已消失、新路径下内容是否可达）。
2. 实读权威 README/权威源文档，确认其当前口径写法及各处口径的使用层面（构成描述 vs 分区内部约定）。
3. 对目标文档逐句判定口径层：构成描述类 → 改为实际路径；分区体系引用类 → 保留原口径不动。
4. 采用最小变更（如 replace_content 仅改路径片段，其余逐字保留），并附带行号的代码引用作为依据。

## Faster Next Time
- 警告信号：只要看到"文档目录名在根目录 ls 中不存在"，先别判过时——查权威 README 分区表是否仍以该名作为逻辑条目。
- 核对清单：实际路径存在性 ✓ → README 口径层判定 ✓ → 逐句归类（改实际路径 / 留逻辑口径）✓ → 最小 patch + 行号引用 ✓。
- 不确定时以"该句子回答的是仓库构成问题还是归档流向问题"作为快速分流判据。

## Applicability Boundaries
- 适用于：目录归拢/搬迁后的过渡期文档修订、知识库概述类小节更新、README 与知识库口径不一致的仲裁。
- 与相邻经验分工：dir-consolidation-path-prefix-batch-fix 管已判定须改的旧路径引用批量校正（映射表全小节加前缀），本条管其前置裁决——先判定路径引用属逻辑口径须保留还是构成描述须改，再进入批量校正。
- 不适用于：口径单一且结构稳定的仓库（此时不一致即错误，直接改）；分区体系本身被废弃或重命名的场景（此时应整体重写口径而非逐句裁决）。
- 重评条件：权威 README 自身在分区表中显式标注实际路径、或分区结构再次搬迁时，应重评口径基准再沿用本规则。
