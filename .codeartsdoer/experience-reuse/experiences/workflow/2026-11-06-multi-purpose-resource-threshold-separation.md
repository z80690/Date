# 同一资源多用途时逐用途过门槛：接入可行性与学习材料质量是独立判据

## Scenario
技术选型阶段确定了一个目标框架（作为接入/集成对象），随后同一仓库又被考虑纳入学习清单（论文/项目学习考核）。两类用途各有门槛：接入看"能跑、方向与基线匹配"；学习材料看"权威性、引用度、内容质量"。两个门槛混用时会产生误判。

## Key Signals
- 出现"选型结论 = 学习材料候选"的推导，或反过来"学习门槛不合格 → 选型也不行"的否决——两种方向的混用都是信号。
- 候选仓库的社区指标（star 数、维护者身份、引用度）在两类用途下权重完全不同，但没人分开算。

## Essence
**用途不同则门槛不同**。接入可行性与学习材料质量是两个独立评判维度，一仓库多用途时必须逐用途分别过门槛，结论可以是"此用途合格、彼用途不合格"。混用导致两类错误：① 因学习门槛不合格而整体放弃一个能用的接入目标；② 因选型合格而默认学习也合格，把低权威材料带进学习流程。

## Approach
1. 登记资源时先列**用途清单**（如：接入目标 / 学习材料 / 参照仓库），不默认全用途复用。
2. 逐用途对各自门槛评判，结论按用途分别标注（合格/不合格/待裁决）。
3. 某用途不合格时：保留该用途结论 + 另寻合格资源补位，**不放弃整资源**、也不降低门槛迁就。
4. 评判冲突或门槛覆盖不到的情形，登记为显式风险项（编号+一句话+状态"待追认"），交由授权方裁决，不自作主张放行。

## Faster Next Time
- 一句话检查：给这个仓库贴用途标签了吗？每个标签都各自过门槛了吗？
- 社区指标速判：个人维护 + 低 star 数 → 接入可行性与学习权威性大概率分离，必须分开判；大厂/高引用 → 两门槛常同时过，但仍需分别确认。
- 风险项登记模板：编号 + 风险一句话 + 已采取的隔离措施 + 状态（待追认），一行入册，不展开成文。

## Applicability Boundaries
- 适用于：任何"一资源多用途"场景——仓库、文档、工具、数据集均同理。
- 不适用于：单一用途资源（无需拆分）；门槛本身未定义时（先定义门槛再做本判，禁凭感觉评）。
- 反模式：为通过某用途门槛而虚报资源指标，或把"待追认"风险项默默放行不登记。

## Evidence or Examples
- 实证会话：2026-11-06 kb_arch_foundation spec 重构。选型命中 LofiSu/deepseek-super-agent（12⭐、个人维护、TypeScript 独立实现），作为目标接入框架与用户基线一致；但作为 5 项目学习材料不满足"大厂高引用"门槛。
- 处置实证：在 spec v2 中固化区分"目标框架 ≠ 学习清单成员"，5 项目学习材料须另行过质量门槛；风险登记为未决项 U8（含风险描述与"已在 spec 固化区分、登记在册待用户追认"的状态），未擅自放行。
