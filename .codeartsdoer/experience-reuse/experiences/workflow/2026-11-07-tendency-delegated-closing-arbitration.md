# 收尾待决项的倾向委托裁决：用户倾向+授权表述即定案依据，落盘留痕恢复条件而非再反问

## Scenario

多阶段任务收尾时，工作残留若干待决项（降级接受与否、产物登记授权、特性是否关闭）。用户最后一轮回复常以"三个待决项（请按既定规范留痕，不替你强判）+ 每项列出可选方案 + 当前倾向 X"的格式收尾。执行方此时面临两难：再反问确认违反"禁反复呈报"偏好；直接定案又怕越权。

## Key Signals

- 用户消息中出现"可选：A / B。当前倾向 A，但你可据实裁决"或"若需我确认，我默认同意上述'倾向'但不强替你定"——这是授权语义而非悬而未决。
- 同一消息中用户明确要求"按你最终裁决落盘"，即最终裁决权已随倾向一并移交。
- 待决项彼此独立，可逐项处置，无需打包等待统一答复。

## Essence

"倾向+授权表述"的语义是：用户已完成裁决思考，倾向即结论，"不强替你定"是留给执行方根据事实微调的空间，而非要求再次确认。真正的动作是把裁决**落盘并留痕三要素**：授权来源（用户倾向表述原文）、定案内容、恢复条件（什么情况下重新打开该项）。

## Approach

1. 逐项识别用户消息中的待决项与其倾向表述；任一项无倾向表述且无授权语句时，仅该项冻结呈报，其余照常推进。
2. 按倾向逐项定案；若磁盘实况与倾向冲突（如倾向授权登记但实测注册失败），以实况为准并在留痕中说明偏差依据。
3. 每项落盘时记录三要素：授权来源（用户原话短引用）、定案内容、恢复条件（如"社区案例补齐：前端检索到文章链接后按七字段补充"）。
4. 落盘后一次性呈报定案结果，不再就同一待决项发起第二轮确认。

## Faster Next Time

- 见到"当前倾向 X + 不强替你定 / 默认同意"组合＝可直接按 X 定案，省去一轮往返。
- 恢复条件必须显式登记，否则降级定案会被误读为永久关闭。
- 涉及"必须由用户界面操作"的事项（如规则粘贴）不在可委托范围内，仍须呈报操作指引。

## Applicability Boundaries

- 适用：收尾阶段的待决项批量裁决、降级定案、登记授权、特性关闭确认等低风险治理决策。
- 不适用：用户仅陈述问题未给任何倾向（此时应给选项化裁决单）；涉及红线操作（删文件、改平台托管文件、外部发布）仍须用户显式执行或确认。
