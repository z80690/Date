# 派工目标产物路径失配的定性降级："相对外部根"声明 + 内嵌权威内容成立即降级继续，禁中止禁无限搜索

## Scenario

以派工方式修订外部 Wiki 文档的小节级内容（建议-合并分离模式：修订者不持直改权，产出结构化 patch JSON 由上游合并脚本统一应用）。派工单提供：变更文件最新全文（口径变化要点清单）、受影响小节当前内容、逐节 action 指令与 code_refs 组成；目标文件路径明示为"相对 wiki 根"。修订者独立执行、无法中途确认，且派工受硬预算约束（默认≤20 分钟）。规模为单文档 2 小节。

## Key Signals

- 痛点信号：按派工单路径 read 目标文件报 File not found；按文件名 glob 全项目零命中；列仓库根目录无 wiki/project-knowledge 类产物根目录。
- 定性信号：派工单路径写明"相对 wiki 根"——这是产物根不在本仓库的显式声明，不是笔误也不是幽灵引用。
- 降级条件信号：派工单已内嵌"受影响小节当前内容"并标注为权威输入——失配时动笔依据仍完整可得。
- 反向信号：若派工单既无内嵌内容又无外部根线索，则不属于可降级情形（应回报而非猜测）。

## Essence

目标路径失配必须**先定性再降级**，定性判据是派工单的路径声明方式而非"文件找不到"这一单值结果："相对 wiki 根/相对外部根"类声明 + 内嵌权威小节内容齐备 → 失配根因是产物在外部根，属可降级情形，以内嵌内容为权威输入继续产出 patch；两条件缺一 → 回报派工方，禁自行猜路径。搜索设预算上限（1 次 glob + 1 次目录列举即收敛），超预算即定性，不进入无限搜索。**与幽灵引用预检的分工**：那条管上游生成产物时对要写进去的引用做写前预检（区分"待新建"与"幽灵引用"），本条管下游执行者遇到派工单目标路径失配时的降级裁决——主体、时机、处理动作三者均不同。

## Approach

1. **先验口径声明**：实读派工单声称的变更文件最新全文，验证口径与行号锚点声明（如"第 N 条 = 行 N"）成立后再动笔——即使后续降级，这一步也是内嵌内容可信度的基础。
2. **定位目标产物（预算 ≤2 轮）**：read 派工单给的目标路径；报 File not found 则按文件名 glob 全项目搜一次。
3. **失配定性**：glob 空则列举仓库根目录及主要子目录一次——无对应产物根目录且派工单路径声明含"相对 wiki 根"字样 → 判定产物在外部根，非幽灵引用、非笔误，进入降级。
4. **降级执行**：以派工单内嵌的受影响小节当前内容为权威输入，按逐节 action 指令产出 patch；派工单未内嵌内容时禁猜路径，回报派工方。
5. **动笔前锚点交叉验证**：对 code_refs 中每个文件:行号逐条实读，命中行内容与引用语义相符才写入 patch（本次 3 处全部命中核实）；核实不符以实读为准。

## Faster Next Time

- 快捷信号：派工单路径出现"相对 wiki 根/相对外部根"字样 = 目标产物不在本仓库的显式前置信号，可跳过本地 glob 直接转入内嵌内容核验，省 1-2 轮搜索。
- 搜索纪律：失配后最多 1 次 glob + 1 次目录列举，超预算立即定性（符合"遇阻先修，≤3 次重试后降级继续"的执行纪律）。
- ROI：降级判定在 2 轮搜索内完成，派工未因路径问题中止，patch 按期产出且锚点零错源；若误判为幽灵引用上报，浪费一整轮派工往返。
- 反模式：把"目标路径不存在"一律当幽灵引用中止任务；无内嵌内容时强行猜路径落盘；失配后放弃内嵌内容核实直接动笔（错源产出风险）。

## Applicability Boundaries

- 适用：建议-合并分离的派工修订场景，目标产物路径相对外部根（wiki 根、外部知识库根等），且派工单内嵌权威输入内容；一般化到"下游执行者收到指向外部产物的相对路径"类派工。
- 不适用：上游生成规划产物时的引用路径预检（写前检查见 2026-11-08-ghost-reference-path-precheck）；本地路径笔误可直接修正的场景；派工单无内嵌内容也无外部根声明的情形（应回报）。
- 前提：派工单将内嵌小节内容明示为权威输入；降级产出仍需走锚点交叉验证，内嵌内容不免除核实义务。
- 证据等级：单次实战闭环（失配→定性→降级→patch 产出→3 处行号锚点实读命中）；上游合并脚本对该 patch 的应用结果在本 trace 之外。
