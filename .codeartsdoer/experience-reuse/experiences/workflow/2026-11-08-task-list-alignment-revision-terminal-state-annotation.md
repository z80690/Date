# 上游规格升版后任务清单的极简对齐修订：五落位清单 + 取消组逐任务终态标注 + 终态一览节

## Scenario

SDD 流水线的**下游任务清单对齐轮**：任务清单（tasks.md）已按旧版规格/设计生成并交付规划确认；随后执行阶段实质完成（多数门禁已放行），但用户下达了收紧类指令使上游规格与设计双双升版。此时用户要求任务清单做一轮"极简对齐修订"，硬约束是"减法为主、禁扩写、快速落盘、既成事实不回溯"。与首轮"从零生成任务清单"不同，本轮修订目的从"规划未来"变为"对齐口径 + 如实标注终态"。

规模参照：本次实战为 575 行任务清单 v1→v2（对齐 spec v5/design v3），24 处编辑分两批落盘，零扩写、零改写已闭环判定、零回溯。

## Key Signals

- 痛点信号：派工指令同时声明"基线已升版（附新版本号）"与"执行已实质完成，既成事实不回溯"——修订性质是"对齐+终态标注"而非"重新规划"，动笔前必须先识别这一性质切换。
- 痛点信号：某任务组被指令整组取消（如对比测试门），但组内任务实际进度不一：检出类任务已完成、出题作答类任务完成一半后中止留痕、后续任务从未开始——整组统一标一种状态必然与证据链矛盾。
- 痛点信号：清单正文含渗透性旧值（如"50 题"），上游已用全局注记切换为新值——任务清单若逐处改写旧值，反而销毁了已执行轮的既成记录。
- 痛点信号：追溯表中受取消影响的行（对比条款、门禁行）已含既有判定表述——直接重写会篡改判定记录，只加注才保审计链。

## Essence

任务清单对齐修订的要害是**"改哪里"与"不改什么"两个清单都要显式化**。"改哪里"=五处固定落位（头部基线、风险表、任务组注记、追溯表、终态一览节），照单执行即可覆盖全部承接点、不漏不散；"不改什么"=已闭环判定零改写（放行结论、评分、核验结论一律只加终态注记）。组级取消不等于组内任务全未执行——取消动作必须下沉到逐任务三态标注（已执行/部分执行/未开始即取消），各附证据指针，清单状态才能与证据链互证。文末新增终态一览节，让后续会话一条消息就能对齐全局状态，不用翻多个文档。

## Approach

1. **头部基线对齐 + 性质声明**：版本号升位，修订说明写明三件事——对齐目标（上游规格/设计的新版本号）、本轮性质（"任务清单对齐+终态标注，不改写已闭环判定"）、生效时点切割声明（引用生效时点切割经验：指令下达时刻起适用，既往既成事实只登记不追溯）。
2. **渗透值全局注记**：正文中的旧值（如已执行轮的题量）不逐处改写，头部加一条注记——"清单中'旧值'为已执行轮既成记录，自指令起后续轮次为新值"。清单是执行记录载体，保留旧值恰是保全证据。
3. **取消组保链 + 逐任务三态**：整组标题标注"已取消（指令依据编号+日期）"但组与任务行全保留（保链）；组内逐任务标终态——已执行（附产出/副本指针）、部分执行（附中止留痕指针）、未开始即取消。不整组一刀切。
4. **存续组执行结果注记**：每个未取消的任务组在组标题或组首行加一句终态注记（放行/完成/停驻待判），引用证据链指针（门禁证据文件名），不展开叙述。
5. **风险表与追溯表联动加注**：风险表中随取消项失效的风险行标注"随 X 取消失效"，其余保留；追溯表受影响行加后缀式对齐注（"v2 对齐：已取消（依据）"），禁改既有判定类注记。
6. **新增终态一览节**：文末 ≤15 行速览——门禁链终态逐项一行、当前停驻状态声明（如提交候选待人工终判）、待人工事项指针（指向留档文件的具体章节）。
7. **分批落盘**：按"头部→风险表→组注记→追溯表→终态节"顺序分两批 edit（结构位一批、追溯表+新增节一批），每批一次落盘，收工输出变更点+终态极简摘要。

## Faster Next Time

- 收到"对齐修订"类指令先列五落位清单再动笔，落位清单本身即可作为修订说明的骨架，动笔即有承接位置，不会漏也不会散。
- 取消组动笔前先逐任务问"实际执行到哪一步"，三态分散标注——这一步是清单与证据链保持互证的唯一机会，漏了就会产生"清单说未执行、证据链里有产物"的矛盾。
- 追溯表只做后缀加注不重写行内容；修订说明中显式写"禁改既有判定类注记"，给后续轮立约束。
- 反模式：整组删除取消组（依赖断链）；组内全部标"未执行"（与证据链矛盾）；重新生成整份清单（浪费既成产物、违反禁扩写）；逐处改写正文旧值（销毁已执行轮记录）；改写已放行判定（审计断链）。

## Applicability Boundaries

- 适用：执行实质完成后上游规格/设计升版、下游任务清单需对齐；门禁/任务组被取消但组内任务进度不一；指令带"减法/禁扩写/快速落盘"类约束。
- 不适用：任务清单尚未执行（直接按新版升排即可，无需终态标注）；结论被推翻需改判（走"重新闭合+编号缺口"模式）；变更仅渗透两三处（直接逐处改写更快）；首轮从零生成任务清单（走 spec→tasks 拆解流水线）。
- 与相邻经验的分工：《规则收紧类指令最小破坏性落盘》管上游规格/设计层"怎么改"（生效时点切割、全局注记、保链三法），本条管下游任务清单层"改哪里+终态怎么标"（五落位、三态标注、终态一览节），两者配套使用；《spec→tasks 覆盖映射》管首轮生成防遗漏，本条管生成后的对齐修订。

- 本次实战（源会话 ses_e4956df28ffefHFSeadS14m5wF，tasks.md v1→v2，对齐 spec v5/design v3）：执行已实质完成——M1/M2/M3/M4/M6/M7 六门放行或停驻、对比门已取消、证据链（gates/、learn/、exam/、e2e/）全部在档。

- 存续组注记实测：M1 组"已放行"、M2 组"已放行（R1 轮 50 题 98%）"、M3 组"已放行（V1 轮 100%）"、M6 组"已放行（1 次终扫+换绑完成）"、M7 组"8.1 完成+8.2 提交候选停驻待人工终判"。
