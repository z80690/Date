# 多平台证据链还原真实从业者工作流：全量转写 + 课件帧 OCR + 同名身份交叉定位

## Scenario

用户派工："把某从业者（实例：嵌入式 UP 主'欧工Ai'）的真实工作流还原成标准工作流并做仿真改造——去各平台找他的真实资料（开发文档、项目目录结构），**严禁脑子臆想**，必须还原其跑通项目的真实流程。"单一头条视频（3'30"，纯口播+字幕）只够给出环节脉络，不足以支撑"真实流程"的还原精度。

## Key Signals

- 派工单出现"严禁臆想/必须真实/跑通项目"字样 → 单源转写不构成交付，须构建多源证据链。
- 口播视频的画面全程为真人讲解（抽帧抽查确认无 IDE/目录树画面）→ 不能指望主视频提供结构化信息，但**贴片帧（课件截图、聊天记录、文件管理器窗口）是结构化信息的唯一载体**。
- 同一作者在其他平台（B 站）常有更细的同主题视频——跨平台同名身份是低成本的高价值增量源。

## Essence

"真实流程还原"的证据强度排序：**作者本人的结构化展示（课件帧里的目录树/配置）> 作者口播表述（转写）> 第三方实证（学员/客户聊天截图 OCR）> 调研者推断**。结论必须由前三级支撑，推断级只能标注为推断。三个机制性认识：①口播视频≠无干货，干货藏在贴片帧里，抽帧 OCR 不是可选项；②B 站搜索 API 是跨平台定位同名 UP 的最短路径（无需 wbi 签名的搜索接口仍可用）；③视觉分析工具不稳定时（同输入重复报错），单帧错位探测 + "信息足够即收"的 ROI 判断优于逐帧全覆盖。

## Approach

1. **源 1·全量转写**：主视频完整转写（全部段落无裁剪），从语流中提炼环节脉络（实例还原出七环节：资料准备→硬件接口→功能说明→代码开发→编译下载→闭环调试→交付验收）。
2. **源 2·贴片帧 OCR**：均匀抽帧后按 ≤4 帧/批串行视觉分析；前段抽查确认画面类型，重点分析中后段（课件贴片通常出现在讲解具体环节处）。目标捕捉：目录树/文件列表（逐行抄录）、聊天记录截图（逐条抄录）、配置文件内容。实例收获：标准项目目录全貌（00_项目管理~09_归档 + .claude/AGENTS/CLAUDE/README 三类 AI 配置文件）+ 学员微信实证（具体芯片型号、项目数、周期对比）。
3. **源 3·跨平台交叉**：用 B 站搜索 API（`api.bilibili.com/x/web-interface/search/type`）搜"主题关键词 + 工作流"定位同名 UP → `view?bvid=` 详情 API 取视频描述（描述常自带结构化总结）→ 下载其专题视频补转写。避开：空间接口（412 风控）、需要 wbi 签名的列表接口（返回非 JSON）。
4. **B 站下载降级**：空间被风控时直接按 BV 号 `yt-dlp` 单视频下载；B 站分流产物（`fXXX.mp4` 视频流 + `.m4a` 音频流分离）转写用音频流即可，无视频流不阻塞；视频无 CC 字幕（`player/v2` subtitles 为空）属常态，转写+抽帧兜底。
5. **视觉分析护栏**：同输入重复报错（EMPTY_OUTPUT_FALLBACK 类）达 2 次 → 换单帧/错位取样探测；关键结构化信息已到手后停止逐帧分析（信息足够即收）。
6. **交叉定稿**：转写脉络 × 课件帧结构 × 第三方实证三方对齐后成稿；推断性内容显式标注"（推断）"；产物落盘留档原始素材指针（temp 目录）。

## Faster Next Time

- 一句话路线：转写拿脉络 → 抽帧 OCR 拿结构 → B 站搜索 API 拿增量 → 三源对齐定稿。
- 成本锚点：实例全链（下载 20MB+1.2MB、转写 88+12 段、分析约 20 帧）约 20 分钟内闭环；跳过任何一源都会在"禁臆想"验收上返工。
- 警示信号：仅凭转写就想下"工作流还原"结论 → 停，等课件帧/实证补齐；B 站空间 412 → 不要等冷却，直接 BV 号直下。
- 反模式：为"全面"逐帧分析全部抽帧（ROI 极低，且工具不稳定时会连环失败）；把转写中的口播承诺（"我有配套教程"）当作已验证事实写入结论。

## Applicability Boundaries

- 适用：还原真实从业者/团队的工作流、方法论、工具链配置等需要证据支撑的调研任务；口播类知识视频的深度提炼。
- 不适用：用户只要"要点提炼"的资料入库（价值分级后浅处理即可，见入库先例）；有现成官方文档/开源仓库的第一手资料场景（直接读源，不必走视频证据链）。
- 边界：第三方实证（聊天截图）只能证明"该工作流有人用且有效"，不能证明流程细节准确——细节仍以作者本人的结构化展示为准。
