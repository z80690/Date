# 多域混合仓库业务术语表初次生成：业务权威源定定义、代码仅核对应、分域覆盖配额

## Scenario

由 subagent 独立派工为多域混合仓库**初次生成**业务术语表（business_term 类 project-knowledge 文档），执行者无法中途向派工方确认。仓库含多个相互独立的概念域（业务主域 + 治理域 + 第三方引入域 + 工作流域），README 只讲主域，其余域的术语散落在笔记/事实源文档中；同时仓库内有与术语同名的代码文件（枚举、状态机、判定函数齐全），构成"实现层最容易抄"的诱惑源。产出带格式硬约束：定义面向业务含义、禁代码枚举值/类名入术语、全文 ≤5KB、术语数量区间、code_refs 行号溯源。

## Key Signals

- 触发信号：派工单要求"术语定义面向业务含义（如某判定术语 = 对轮次合规性的判定结论机制，而非对应代码文件的类描述）"——即派工方已预判实现层污染风险。
- 痛点信号：与术语同名的代码文件近在手边且信息密度高（枚举值、状态机、计数键名），照抄实现层最省事，但会把"代码如何表达"写成"业务是什么"。
- 痛点信号：多域仓库的单一代价最小的入口文档（README）只覆盖主域，按文档易得性凑术语会静默漏掉次域。
- 预提取产物（symbols.json 等）缺失：代码验证角色需降级为直接读源码文件抽验，不构成动笔阻塞。

## Essence

术语表的**定义权在业务权威源，代码文件只承担核对角色**：定义文本从业务文档（README → 单一事实源/事实表 → docs/）提炼，代码文件仅在术语定型后反向核对"业务概念与实现是否对应"，反向过来（以代码为定义源）必然产出实现层伪术语。覆盖率以**概念域为分配单位**而非以文档易得性为分配单位——先列概念域清单再逐域配额提炼，防止按单一路径搜索时静默丢域。

## Approach

1. 先建概念域清单：从派工单/README/目录结构识别仓库含哪些业务概念域，作为术语覆盖的分配骨架；总数量约束（如 8-14 条）按域重要性分摊，每域至少 1 条。
2. 按"业务权威源优先级链"逐域提炼：README/入口文档 → 项目事实表/单一事实源 → docs/ 业务文档；每条术语记定义出处行号备溯源。
3. 定义口径检验：每条定义回答"是什么、解决什么问题"，出现类名/枚举值/常量名/函数行为描述即回炉改写为业务释义；别名栏登记项目内其他称呼。
4. 代码文件反向核对（验证角色）：术语定型后读对应代码文件，确认业务概念确有实现承载；仅修正"术语所指不存在/命名对不上"的问题，不从代码提炼新定义。
5. 产物契约同步收口：全文 ≤5KB、code-links.json 的 wiki_section 逐字复制中文小节标题、code_refs 一律 `文件相对路径:行号` 且行号必填（格式细则见关联经验 project-knowledge-provenance-format）；交付前核对术语数、覆盖域数、字节数三项。

## Faster Next Time

- ROI：来源链先行避免逐文件试探（本例一轮读齐主定义源即完成提炼）；分域配额防清单失衡，避免交付后才发现整域缺位返工；反向核对把"实现层污染"拦截在动笔口径层而非验收层。
- 警惕信号：某条定义里出现"枚举/XxxState/类名"字样 → 定义已被实现层污染，立即回炉；术语清单与概念域清单对不上 → 有域静默缺位。
- 反模式：以代码文件为定义源；按文档易得性而非概念域覆盖凑术语数；为凑溯源把没读过的文件塞进 code_refs。
- 与存量经验的分工：修订侧对齐（四态分诊/改名裁决）见 2026-11-08-glossary-term-rename-vs-revise-criteria，状态值刷新判零修订见 2026-11-09-glossary-status-refresh-zero-revision-criterion，建议态/技术发现不入术语表见 2026-11-13-glossary-advisory-and-techfinding-term-admission——本条只管**从零初次生成**。

## Applicability Boundaries

- 适用：多域混合（或单域但来源分散）仓库的业务术语表/概念表初次生成；subagent 独立执行、无中途确认的派工模式；定义须面向业务含义的知识文档。
- 不适用：术语表随规范大改版的修订对齐（走四态分诊，本条非裁决框架）；纯代码结构文档（API 说明等应直接以代码为准，无"业务面/实现面"分离问题）；派工单已显式给出来源优先级时按派工单执行，本条为来源缺失时的默认链。
- 前提：仓库存在至少一份业务口径权威文档（README/事实表/docs）；全部为代码无业务文档时本方法退化为"从 commit 信息与测试用例提炼"，覆盖配额仍适用。
- 证据等级：单次成功闭环（产物落盘、字节数与术语清单核验通过），无失败路径与用户纠偏数据。
