# LLM 作答独立批改的三级判定与折算自信度方法

## Scenario
- 适用工作流环节：学习考核的验证/评审阶段（作答-批改分离）；也适用于任何"有参考答案要点（key）的批量作答评审"。
- 规模：50 题量级的批量语义作答，题型为概念辨析/架构选型/工程决策场景题，非代码运行类题。
- 触发信号：作答方完成 100% 作答后，需要一名独立批改官逐题判定并给出综合自信度，作为后续开工的门禁输入。

## Key Signals
- 作答质量无法用自动化测试验证，只能依据参考答案要点做语义判定。
- 若无统一口径，逐题判定容易出现两种失真：放水（语义沾边就 PASS）或过苛（措辞不同就判错）。
- 作答方常附自我评估；若批改自信度被自我评估锚定，门禁值会系统性虚高。

## Essence
真正起作用的是三条判定口径 + 一个折算公式，把"从严但公平"变成可执行规则：
1. **语义一致即 PASS**（不要求逐字复述）；
2. **作答正确但超出 key 范围也算 PASS**（key 是下限不是上限，避免惩罚超额洞见）；
3. **与 key 矛盾才判 FAIL**（PARTIAL 用于"覆盖部分要点"，并必须指出缺什么）。
自信度不是数对错题的百分比，而是"折算基础 + 质量修正"：PASS 计 1、PARTIAL 计 0.5、FAIL 计 0，折算和/总题数为基础；再按"超出 key 的正确洞见加分、事实错误扣分"修正。这样 PARTIAL 不会与 PASS 同价，质量瑕疵也不会被统计掩盖。

## Approach
1. 完整读取三份材料：题目、参考答案要点、作答；先核对覆盖率（作答率是否 100%，这是独立于质量的第一道门禁）。
2. 逐题判定，三级取一：PASS / PARTIAL / FAIL；每题必须留一句判定依据（依据可复核，禁无依据判定）。
3. 按口径三条规则处理边界：语义等价放行、超额正确放行、矛盾才 FAIL；PARTIAL 必须写明缺失要点。
4. 计算综合自信度：折算和/总题数为基础值，再加质量修正（洞见加分、事实错误扣分），独立给出 0–100%，不采信作答方自评。
5. 输出批改报告，固定结构：逐题判定表（编号/判定/依据一句话）+ PASS/PARTIAL/FAIL 统计 + 综合自信度值 + 薄弱角度清单（低于门禁时必须列补学方向）。

## Faster Next Time
- 直接复用本判定口径三条与折算公式，省去每次现场约定批改规则的成本；50 题批改可在单轮内完成（一次读全材料 → 逐题判定 → 一次写报告）。
- 报告模板固定后，门禁判定（自信度 ≥80%）变成机械核对，避免评审标准漂移。
- 警示信号：如果 PARTIAL 数量异常高，多半是 key 写得过细或口径被收紧，先回头核对口径再怀疑作答方。

## Applicability Boundaries
- 适用：有参考答案要点的语义型作答（概念、架构选型、决策论证）的批量批改；一次批改、单批改官场景。
- 不适用：代码类产出（应跑测试验证）、无 key 的开放式产出（无从判定"矛盾"）、需要多专家交叉评审的高风险决策。
- 依赖前提：key 本身质量决定批改上限——key 缺陷导致的误判无法靠口径修复，批改前应快速核查 key 覆盖面。

## Evidence or Examples
- 实际批改案例（本项目 ST2 学习考核，50 题）：PASS 47 / PARTIAL 3 / FAIL 0，作答覆盖率 50/50=100%；折算基础 97%（47+3×0.5=48.5/50），因轻微瑕疵（维度切面偏差，无事实错误）扣 1%，综合自信度 96%，门禁 80% 达标。
- PARTIAL 案例特征：如"经验条目字段化缺 precondition/状态字段""骨架章节不足"——答出主体但缺关键子项，正是 0.5 折算的适用对象。
- 批改报告落盘于考核目录下 `st2-exam-review.md`（逐题判定表 + 统计 + 自信度 + 薄弱清单），可整卷复核。
