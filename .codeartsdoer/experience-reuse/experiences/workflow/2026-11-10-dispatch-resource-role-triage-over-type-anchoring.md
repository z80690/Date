# 连续派工中同类资源的处理定位按用途声明分流，不被资源类型与上轮成功模式锚定

## Scenario

SDD 门禁等待期连续三轮资源派工：第一轮 2 个头条视频定位"资料入库"（提炼要点存知识库、价值分级、不强制改动阶段文档）；第二轮第 3 个视频（同为头条链接）定位完全不同——"主力干活的工作流配置物"（须还原从业者真实流程+仿真改造+配成标准工作流+主备双方案落盘），用户以醒目篇幅预防性强调："这个视频【不是资料】！是主力干活的工作流！你之前若当资料处理，立刻纠正"，并附"最后一次"时限压力。

## Key Signals

- 同类资源（都是视频链接）连续出现 → 天然锚定风险：上一轮"下载→转写→提炼→入库"的成功模式会自动浮现。
- 用途声明决定论的判据词：**"作为参考依据保存到资料库/入库学习" = 资料定位；"配成主力干活的工作流/严禁臆想还原真实流程/仿真改造" = 配置物定位**。
- 纠正性句式（"不是X是Y"）+ 时限声明（"最后一次"）= 链路重置指令 + 一次性交付要求，两个信号都要接住。

## Essence

资源的处理链路（深度、产物形态、验证标准）由**派工单中的用途声明**决定，不由资源类型决定，也不由上一轮的成功模式决定。两类定位的验收标准完全不同：资料入库的合格产物是"要点提炼+索引登记"（允许价值分级、允许浅处理）；配置物的合格产物是"可执行落盘的标准工作流"（禁臆想、须多源证据链、须环境适配改造、主备齐备）。把配置物按资料浅处理的代价是整单返工——产出的"资料笔记"无法充当主任务的执行依据。用户花大篇幅做预防性纠正本身说明：锚定错误在该会话上下文里是高概率风险，纠正文本必须当作路由指令而非情绪表达。

## Approach

1. 每条含外部资源的派工进来时，先逐项回答"该资源在本单中的产物定位是什么"，从用途声明原文提取，不参考上一轮对同类资源的处理。
2. 按定位分流处理链：资料 → 提炼要点+价值分级+索引登记（浅链路）；配置物 → 多源证据链还原+环境适配+标准落盘+主备方案（深链路，见关联经验证据链条目）。
3. 见到"不是X是Y"句式：立即检查当前拟定链路是否与"Y"匹配，汇报中显式区分各资源定位（如"前俩=资料留痕、本条=主力工作流"），证明纠正已被执行。
4. 见到"最后一次/一次性搞定"时限声明：盘点全部未了事项（主产物+副产物+历史留痕+归档闭环），以清单交付，不拆多轮。
5. 汇报按用户指定的格式逐项回应（如"主备方案+归档清单"三段式），让验收点与派工单一一对应。

## Faster Next Time

- 一句话判据：**定位看用途声明，不看资源类型、不看上轮怎么做的。**
- 快速分流表：出现"入库/参考依据/备用" → 浅链路；出现"主力/配置/禁臆想/改造" → 深链路 + 证据链经验。
- 警示信号：用户用加粗/感叹号强调资源定位（"【不是资料】！"）→ 这是路由级指令，处理错了必返工；连续派发同类资源 → 主动自查本轮定位是否真与上轮相同。
- 反模式：因上轮同类资源处理顺利而跳过定位判定直接套链路；把用户的预防性纠正当作"未发生的事故"而忽略（它标记的是风险面，不是已了结事项）。

## Applicability Boundaries

- 适用：多轮派工会话中反复出现的同类资源（视频/文档/链接/代码库），每轮定位可能不同。
- 不适用：单轮单资源且用途明确的派工（无锚定风险，直接按声明执行）；定位由模板协议强约束的场景（走对应流程分支判据，见关联经验 auxiliary-dispatch 条——那条管"辅助任务 vs 流程分支"，本条管"同批资源内资料 vs 配置物"，两层分流正交）。
- 边界：当用途声明存在歧义（既像资料又像配置物）时，按更深的链路预期处理并向用户确认产物形态，勿自选浅链路赌验收宽松。

## Evidence or Examples

- 来源会话：ses_e3a9c97a3ffeCp9OO263dGGrPC（2026-11-10，欧工主力工作流配置任务）。
- 用户原话锚点："前俩视频（电路板/家电维修）仅作'资料入库'……这个欧工视频（第3个）【不是资料】！是'主力干活的工作流'！你之前若当资料处理，立刻纠正。"
- 执行实证：主智能体未套用上轮入库链路，本轮按配置物定位走深链路（todowrite 七项：下载转写→调研真实资料→还原工作流→仿真改造落盘→备用方案→归档→汇报），产物为主备双工作流文档+三资料归档+索引登记，汇报按"主力/备用/归档"三段式回应派工单验收点。
- 定位差异实证：同为头条视频，资料定位产物=学习成果笔记+索引行（第一轮）；配置物定位产物=含仿真改造映射表的标准工作流文档（本轮），两者的产物形态、证据要求、验收点完全不同。
