# 补充裁决型增量修订：冲突条款例外登记双指针 + 实测类交付物评估框架版防虚构

## Scenario

spec 等基线文档已经用户确认（版本冻结）后，用户下达"补充裁决"，要求在既有文档上原地升版（vX.Y），加入新的前置门禁/核验章节。此类增量常带四重张力：① 明示"只增不删、既有条款值不改写"；② 新增门禁与既有禁令条款字面冲突（如既有"门禁未过禁放行一切动作" vs 新裁决"实测性验证动作可与门禁并行"）；③ 未裁决事项因新门禁整体后置；④ 裁决要求新增核验报告类交付物，但实测尚未发生。

## Key Signals

- 用户裁决原文带修订纪律关键词："只增不删""既有条款值不改写""交叉引用联动更新并留指针"。
- 新增章节内容与既有条款字面冲突——改值会破坏已确认基线，不改值则两条并存矛盾。
- 附录级待裁决事项被裁决明示"暂挂，等门禁通过后一并裁决"。
- 新交付物为实测类报告（如可行性核验、解耦评估），此时实测动作尚未执行。

## Essence

版本冻结文档的增量修订中，既有条款值是已确认基线，冲突解法不是改写而是**例外登记**：在冲突条款上添加带版本标记的例外注记，与新章节条款互相留指针并标注授权来源——条款原值可追溯、冲突可见、可审计。实测类交付物未发生时只落**评估框架版**：登记裁决给定事实，实测项一律标"待实测"，以"未虚构"为底线；暂挂只标注不删除，防内容丢失也防提前催裁。

## Approach

1. 动笔前完整读取基线文档全文，建立"裁决要点→落点章节/条款"映射；裁决未引用具体条款号时如实记录（无口述编号错位），落位后在修订摘要偏差报告中声明。
2. 先定章节插入位与编号策略（如新门禁章插在学习门禁与后续执行章节之间、后续章节顺延），改号链按既有顺延纪律执行。
3. 冲突处理走例外登记：新章节写例外条款（含编号、授权来源、目的限定——"目的限于核验非正式执行"），既有条款尾部加【vX.Y 注记】指向新条款；两侧都不改原值，双向指针。
4. 待裁决事项整体后置时：附录头加暂挂总声明 + 逐项追加"暂挂状态"行，流程/数据约束条款同步新增"暂挂登记"条款（含"暂挂期间禁催裁、禁按默认执行、放行后解除"三态），原内容不删除。
5. 实测类新交付物落"评估框架版"：仅登记裁决给定事实 + 各实测项标"待实测" + 文档头部状态声明，交付物清单状态如实登记；修订摘要固定含一行偏差报告（口述引用 vs 文档实际落位）。

## Faster Next Time

- 自查口诀：**冲突不改值，例外双指针；未实测不虚构，框架版先行；暂挂只标注不删除**。
- 完成度证据链：修订处【vX.Y】标记全覆盖 + grep 交叉引用零残留 + 偏差报告行——三者齐备才可呈报停驻。
- ROI：本次 spec 666→814 行、13 轮编辑一次成形，例外登记避免了重写既有条款引发的基线争议；评估框架版使"拉取/解耦实测"与"文档框架"解耦，实测后仅填充数据即可提交审阅，零返工。

## Applicability Boundaries

- 适用：用户确认后的基线文档增量补充（补充裁决、追加需求、门禁后置类约束变化），尤其新增条款与既有条款字面冲突的场景。
- 不适用：打回重做型修订（应走差异分诊+继承纪律）；口径级全量替换；既有条款本身被判错需修正的场景（此时应改值并留修订说明，而非例外登记）。
- 相邻经验边界：2026-11-07-gate-exemption-semantic-annotation 处理"检查能力边界外的豁免标注"；本条处理"条款字面冲突的并存登记"——前者是执行期旁路，后者是修订期基线保全，勿混淆。门禁切分表三要素见 stage-gate-split-table-rework-degrade，本条不重复。同一修订任务的编辑执行编排（改号链一步一轮、插入式 Edit 最后执行）见 2026-11-12-sequential-edit-chain-one-per-turn-insert-last——本条管"改什么"（例外登记/暂挂/框架版），那条管"怎么改"（轮次编排）。
