# 学习成果沉淀闭环：五要素条目入知识库 + 按需复用 + 考核证据互链

## Scenario
派工单要求"学 5 篇论文（多角度）+ 5 个项目（含正反例）……这些东西必须永久记住"，并追问：学习成果"需不需要保存成一个链接，沉淀成经验？怎么维护？弄个链接，用的时候再读这篇文章？"——学习类任务存在三重落点：成果不能散落在会话里（否则下次重学）、不能只存链接（否则用时还要重读原文）、不能不给正反例（否则无法支撑后续同类判断）。

## Key Signals
- 学习任务伴随"永久记住/沉淀/怎么维护"类要求——说明成果需要跨会话资产化，而非会话内理解。
- 材料获取有保真度风险（论文可能是编造标题、项目可能是低质 demo）——沉淀前必须先过来源真实性核验。
- 学习与考核绑定（考核通过才准入）——成果条目天然需要与考核证据互链。

## Essence
学习成果的正确落点是**既有知识库的标准化条目**，而非新建档案或只留链接。条目用五要素固化（原文链接 / 条目名 / 浓缩版 / 正例 / 反例）：链接保真（溯源）、浓缩版省重读（上下文经济）、正反例保判断力（不只存结论）。登记走既有索引唯一入口（查重防重复），复用走既有三级渐进加载（索引→浓缩版→原文），使"永久记住"由机制保证而非靠记忆——这与知识库分层维护机制（见 2026-11-06-knowledge-base-tiered-maintenance-design）完全同构，学习成果只是其中一类条目。

## Approach
1. 学习完成即登记，不等任务完结批量补录：每份材料产生一个知识条目，登记前过索引查重（同一来源已有条目则更新线索而非新建）。
2. 五要素逐项落盘：原文链接（经核验的真实出处，禁编造标题）、条目名（含义清晰便于检索）、浓缩版（核心要点 + 关键结论，登记最后核验日期）、正例（该材料做对了什么、可复用模式）、反例（该材料或同类方案的失败模式、避坑点）。
3. 正反例用固定短格式（一句话 + 出处定位），禁止长篇复述原文。
4. 与考核证据互链：条目登记号写入考核记录，考核记录回指条目，双向可追溯（"学会了什么"与"怎么证明学会"一一对应）。
5. 复用时按需沿三级渐进读取：先索引定位，再读浓缩版，仍不够才读原文链接指向的源。

## Faster Next Time
- 一句话判据：学完的每份材料都问"五要素齐了吗？条目进索引了吗？"——缺任一项视为学习未闭环。
- 材料到手先验保真度（真实标题、真实出处、权威性），不合格材料不进学习清单（门槛判据见 2026-11-06-multi-purpose-resource-threshold-separation）。
- 警告信号：发现"学完了"但知识库里无对应条目 → 立即补登记；发现条目只有链接没有浓缩版 → 视为未沉淀。
- ROI：五要素条目使下次同类任务零重学（读浓缩版即可），正反例直接喂给方案设计；与只存链接相比省去重读原文的全部时间。

## Applicability Boundaries
- 适用：带"永久记住/沉淀"要求的学习型任务（论文调研、框架学习、竞品分析）；与能力考核绑定的强制学习。
- 不适用：一次性查阅（读完即弃，无需条目）；条目价值极低的碎片信息（纳入笔记即可，别为沉淀而沉淀）。
- 反模式：只存链接不存浓缩版（用时重读）；只写结论不留正反例（丧失判断支撑）；绕过索引另建学习档案区（制造第二登记入口）。
- 证据等级：五要素契约与互链设计已落盘于 spec（§5.5），但学习流程本身尚未执行（考核态未到），无实际登记样本验证；首次执行后的偏差应回写本条。

- 实证：2026-11-06 Date 项目 kb_arch_foundation spec v2（§5.5 学习成果沉淀）：登记时机=学习完成即登记、五要素=链接/条目名/浓缩版/正反例、与考核证据链互链、长期维护走既有知识库增删改查与一致性检查。
- 用户原始关切（口语转写）："需不需要保存成一个链接……怎么维护他？弄个链接，用的时候再读这篇文章"——答复落点即本条：链接只是五要素之一，核心是浓缩版 + 正反例入索引。
