# 强制机制随前提失效时的守线转移：拆目标与机制、降级为建议并把守线点移至可结构化校验层、边界显式登记

## Scenario

约束放宽类修订（本例：从"隔离环境运行"放宽为"Windows/Kali 本机直跑"）中，原守线机制"隔离环境网络闸门切断对外通路"失去存在前提——本机直跑后底座在结构上管不住进程（如隐匿通信浏览器）自发发起的网络连接。但机制守护的目标仍在：用户明确要求"四不红线保留""禁真实外连公网"。决策语境：用户授权自主全量修订、不预设方案，但红线目标是硬约束；修订结果须经用户确认门禁。

## Key Signals

- 强制机制依赖的前提被取消（闸门依赖隔离环境，隔离环境没了）。
- 该机制守护的**目标**仍然成立且被用户点名保留（禁真实外连公网）。
- 用户只指定了"保留什么"，未指定"用什么机制保留"——实现机制的选择权在执行者。
- 修订后文档若出现"禁 X"红线仍在、但对应校验机制全部消失的状态，即为守线真空信号。

## Essence

强制机制失效时，守线责任不能随机制一起删除。核心动作是**拆分守护目标与实现机制**：目标保留，机制按三选一处置——①新环境仍能结构化强制 → 重构机制；②只能部分覆盖 → 强制条款降级为建议，同时把强制守线点**转移到仍可结构化校验的层面**（数据层优先于行为层：任务/配置是底座可校验的数据，进程自发行为不是）；③既无法强制又无替代校验层 → 显式登记守线边界与残余风险回呈用户，不静默删除。共同纪律：无论走到哪一分支，"防线在哪里变薄"必须写进文档显式登记，让审阅者对防线变化有知情权——降级为建议不等于放弃守线，是把守不住的部分显式交还给用户知情。

## Approach

1. **盘点失效机制清单**：列出全部依赖被取消前提的强制机制（本例：网络闸门切断对外通路、虚拟机端口转发、Windows 本机隔离区）。
2. **逐个两问**：守护目标是否仍成立？新环境下该目标还能在哪里被结构化校验？
3. **三选一处置**：
   - 可重构 → 换一个不依赖旧前提的强制落点（本例："目标地址白名单"——仅放行本机回环/本机局域网自建资产，指向真实公网的任务配置在受理时直接拒绝+告警，替代闸门成为"禁真实外连公网"的可验收落点）；
   - 部分可守 → 强制条款降级为建议（"隔离环境网络闸门强制"→"建议本地离线演示"），强制点转移到可校验层（任务配置校验）；
   - 无处可守 → 登记残余风险回呈，不静默删。
4. **守线边界显式登记**：在文档中写明"本机直跑后底座管不住进程自发连接，靠用途限定+配置校验守线"——守线能力边界本身是一条应被审阅的信息。
5. **呈报单列"降级为建议"段**：与删除项、保留项分开列出，防线变化一目了然。

## Faster Next Time

- 一句话判据：机制删了，守护目标还在不在？在 → 找新环境里仍可结构化校验的那一层，把守线点搬过去；找不到 → 登记残余风险，不静默删。
- 可结构化校验层的优先序：**任务/配置数据层**（底座可判定、受理时可拦）> 进程行为层（底座难判）> 网络层（依赖环境形态，本机直跑后失效）。
- 警示信号：修订后"禁 X"红线还在但全文搜不到任何校验/拒绝/告警条款 → 守线真空；"建议"措辞出现但无守线边界登记 → 防线静默变薄。
- 反模式：机制随前提一起删（红线变口号）；降级为建议但不转移守线点也不登记边界；把守不住的守线责任伪装成已守住（措辞不降级、能力已降级）。

## Applicability Boundaries

- 适用：环境/架构/运行形态变更导致原强制机制失效，而守护目标须保留的场景；安全红线重构；流程文档防线调整；任何"约束保留但手段失效"的修订。
- 不适用：守护目标本身被取消（红线随目标一起删，无需转移）；新环境可直接沿用原机制（无需降级，原样保留即可）；无产出物、无执行代理的纯咨询约束（不存在守线面）。
- 证据边界：本条为 spec/design 文档层决策实证，"任务配置校验"在实施阶段的实际拦截效果未在本轨迹内运行验证，属文档层落位；进程自发连接不可管为结构事实推断，已标注。
