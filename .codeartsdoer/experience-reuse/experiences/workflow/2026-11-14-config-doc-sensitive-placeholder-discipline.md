# 配置类知识文档生成时敏感值一律占位化的写作纪律

## Scenario

为多子项目仓库生成配置体系类知识文档（project-knowledge / README / 架构说明均可复用）。此类仓库的配置事实散布在多种载体中：代码常量与 JSON 配置、PHP/模板文件的 getenv 兜底、容器编排文件的环境变量、根级敏感环境变量文件。触发条件是：文档将被长期入库并供 AI 检索复用，而仓库内存在真实或半真实凭据。

## Key Signals

- 文档定位为"长期入库 + 会被检索复用"，意味着任何复制进去的具体凭据都从"仓库内静态数据"升级为"跨会话持久泄漏面"。
- 上游编排文件（如 compose.yml）中肉眼可见的明文密码，会诱使写作时直接照抄"以保持真实性"。
- 敏感文件（.env 类）确实存在且可读，但读取并引用其内容毫无必要——文档只需要"机制与位置"。
- 派工方给定了粒度上限（如 ≤5KB），需要事后可验证的闭环，而非口头声称"应该没超"。

## Essence

知识文档的写作纪律核心是**机制描述与具体值分离**：文档回答"配置如何加载、在哪里校验、违反会怎样"，而不是"配置的值是什么"。凡属值（密码、token、连接串、密钥），一律占位符；凡属机制（加载顺序、校验失败行为、默认值兜底），如实归纳并带行号锚点。敏感文件只确认存在与用途，绝不读取复制内容值。粒度约束用写后字节数自检闭环。

## Approach

1. 按配置载体类别各读一份代表样本（代码常量模块、JSON 配置、dist 模板、容器编排），记录机制结论与行号锚点，不做全库扫描。
2. 敏感文件（.env 类）只确认存在与用途（如仅列出文件大小/确认键名用途），绝不复制内容值进文档。
3. 文档中所有配置示例值一律占位符（`***`、`<your-key>`）；上游文件中明文出现的密码同样不照抄。
4. 归纳加载机制形态而非罗列值，例如"getenv 环境变量优先 + 默认值兜底"、"启动即校验、缺失/损坏直接硬失败中止"。
5. 落盘后立即做字节数自检（如目录列表确认文件大小 < 上限），把粒度约束变成可验证证据。
6. 写作过程中外部工具（LSP 等）报出的上游第三方代码既有诊断，与本产物无关，按路径归因排除噪声，不据其修改产物。

## Faster Next Time

- 核验清单口诀：**定机制、不抄值、占位符、锚行号、自检字节**。
- 把"敏感信息禁令 + 占位符要求 + 粒度上限 + 核验起点清单"预先写进派工 prompt，子代理可一次通过零返工；事后修正不如事前红线。
- 机制归纳比值罗列更抗过期：配置值轮换后文档仍准确。

## Applicability Boundaries

- 适用：会被入库、检索、复用或公开的知识文档、README、架构说明的生成。
- 不适用：确需记录真实凭据的机密交接类文档——那类内容应走凭据管理通道，而非知识文档。
- 字节数自检仅在产物有明确大小/粒度上限时需要；无上限时可省略第 5 步，其余纪律仍然成立。

## Evidence or Examples

- 实例会话（ses_e2d3aa976ffe6ANX86cvmnz1ed）：生成配置体系知识文档时，上游 DVWA compose.yml 中 `MYSQL_PASSWORD` 明文密码未照抄进文档；.env（286 字节）仅确认存在与用途，未复制任何值。
- 产物自检证据：md 落盘 3953 字节（< 5KB 上限）、code-links.json 779 字节，均在写后立即确认。
- 行号锚点纪律：机制结论均带 `文件:行号` 引用（如配置常量定义处、白名单校验函数处），保证可溯源。
- 本轮一次通过零返工：派工 prompt 中预置了核验起点、格式契约、红线与上限，未出现方向修正。
