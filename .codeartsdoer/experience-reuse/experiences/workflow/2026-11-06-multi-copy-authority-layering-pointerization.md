# 同内容多副本文件的权威分层与指针化去重（副本不可删除场景）

## Scenario

单人 + Agent 长期协作工作区中，一份协作公约类规范内容被平台机制自然复制到多处（用户定稿文档、平台托管规则文件、平台元数据内嵌 content 字段）。每处维护主体不同（用户/平台自动写入），长期演进必然失同步；而"去重"常被硬约束阻挡：平台托管文件不可手改、定稿文档是用户裁决证据、项目禁删文件。

## Key Signals

- 同一内容在 ≥2 处以**全文**形式存在（非摘要引用）。
- 部分副本属平台托管——手改违规且会被平台覆写（见 2026-11-06-codeartsdoer-rule-init）。
- 某副本承载用户定稿/裁决证据身份，不可动。
- 出现"这内容以后改一处还是三处"的维护问题，而删除冗余副本的选项被硬约束禁止。

## Essence

当副本因外部约束（平台托管、证据保全、禁删令）**无法物理消除**时，去重的正确形态不是删副本，而是**权威分层**：按"谁实际生效""谁定稿内容""谁只是派生缓存"给每份副本定角色；写入只改权威源，读取按角色取信，副本间用指针引用、禁抄全文。

## Approach

1. **先实查副本清单**：路径 + 维护主体 + 可改性，逐字比对确认当前是否一致（不一致处列为待仲裁差异）。
2. **三级权威定角色**：生效权威（平台实际加载的那份，如规则文件——决定行为）；内容权威（用户定稿证据——决定"内容是什么"）；派生缓存（平台元数据内嵌副本——永不参与仲裁）。
3. **写路径收敛**：内容变更只改内容权威源；生效副本由用户经平台界面更新（Agent 对规则文件零写权限）；派生缓存靠平台机制自动同步，禁手抄。
4. **固化仲裁顺序**：冲突时的取信顺序预先写入 spec/规则（如：内容权威 > 生效权威 > 派生缓存），不等到冲突发生才临时裁决。
5. **指针化检查**：任何文档内出现对权威内容的全文复制即违规，只存路径指针 + 版本/哈希标记；同步偏差作为异常登记。
6. **零删除**：三份副本全部保留，各司其职。

## Faster Next Time

- 遇到"这内容改一处还是三处"，先问两个问题："哪份是平台实际加载的？""哪份是用户定稿证据？"——两问定位生效权威与内容权威。
- 指针化检查清单：副本文件全文复制=违规；仲裁顺序未预先固化=隐患；实查清单缺失=设计悬空。
- ROI：本例逐字核实三处副本当前实质一致后一次定稿方案，避免了后续每次修公约的三处手改与漏改返工；若放任副本各自演化，首次分歧即需跨会话仲裁。
- 反模式：为对齐副本而手改平台托管文件（违规且会被覆写）；以"删掉冗余副本"为第一方案撞上禁删约束后无备选。

## Applicability Boundaries

- 适用于副本不可物理消除的场景：平台托管文件、用户定稿证据、禁删令约束下的文档治理。
- 不适用于副本均可自由删除的场景——此时直接删除冗余副本 + 保留唯一源更简单，不必引入权威分层。
- 证据等级：三副本逐字一致实查 + 方案落 spec 固化，属已验证；三级角色划分的长期维护有效性尚待后续修订周期检验。
