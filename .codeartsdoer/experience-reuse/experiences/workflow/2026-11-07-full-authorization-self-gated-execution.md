# 全权授权批量执行：人工门禁转自执行检查+证据落盘，中断呈报例外仅限事实性阻塞

## Scenario

多阶段任务（环境接入→学习考核→架构设计→规则追认→实施→提交）原设计为每阶段人工确认门禁；任务中途用户改口下授权令："全权授权，一把到底，禁反复呈报""每个门禁自己卡自己过""仅事实性阻塞才允许中断呈报""干完直接交活"。任务规模：12 任务组、53 子任务、两道质量门禁、多次提交。

## Key Signals

用户授权语句可拆出三个要件，动工前逐项确认：

1. **范围**：授权覆盖到哪（"最终交付物一次到位"）；
2. **门禁处置**：门禁如何执行（"自己卡自己过"）；
3. **例外**：什么情况允许中断（"事实性阻塞：工具链彻底不可用、网络全断、磁盘满"）。

要件齐全才进入批量执行；缺失（如未给例外清单）须先澄清边界——这属于授权范围确认，不算违规反问。

## Essence

授权转移的是"确认动作的执行权"，**不是"检查义务的豁免"**。每道人工门禁转为自执行检查：判定标准不变、准出条件不变，仅把"等用户点头"替换为"按既定标准自判+证据落盘可复核"。质量下限靠证据链而非人工把关维持；中断呈报白名单收窄到事实性阻塞，避免把"拿不准"当阻塞频繁上报。

## Approach

1. 逐门禁改写：人工确认点 → 准出条件 + 自检动作 + 证据文件路径（如考核门禁 → 独立批改官评分报告）；
2. 每过一道门禁即时留痕：结果、判定依据、证据链位置，写进状态区/变更日志；
3. 未达标不跳过、不降标准：按预案补学/修复/重考直到过线（本例考核未达线时的补学闭环在授权范围内自行完成）；
4. 中断呈报白名单只列事实性阻塞（工具链不可用、网络全断、磁盘满）；执行层疑难一律自行消化；
5. 最终一次交活：报告按"结论 → 分项证据 → 留给用户核验的指针（报告路径、提交 hash、可复核数据）"组织，让用户验收时零追问可自查。

## Faster Next Time

- 授权语句到手先拆"范围/门禁/例外"三要件再动工，防止把全权授权误读成免检放行；
- 证据落盘标准：用户最终核验时无需追问任何中间过程即可自行验证结论；
- 与人工门禁模式（见关联经验）构成互补：用户未授权时用裁决单+人工门禁，授权后切换为本模式，两套预案都备好。

## Applicability Boundaries

- 适用于用户明确预授权、且门禁判定标准客观可量化（测试通过率、评分阈值、清单一致性）的流程；
- 不适用于判定标准模糊或涉及用户主观偏好的门禁（文档风格、命名偏好、取舍类裁决）——这类即使已授权也应保留呈报点，冒进自判风险大于呈报成本；
- 不可逆动作（删除、覆盖、外发）不在"自卡"范围内，无论授权与否都应显式呈报或遵循既有红线。
