# 参照某目录的风格/标准写新内容前，先盘点全目录并逐份实读，模糊指代先消歧

## Scenario

用户要求"参照某个目录/某处的文件风格，按它的标准写"（如"你看看人家怎么写的，能简单尽量简单，按照他的风格"）。产物规格较重（数百行规格/设计文档），目录中存在多份相关标准件（含官方标准文档、现行规范、历史副本）。上一版产物因参照系残缺被打回，用户给出失败评分并要求重入修订。

## Key Signals

- 指令中出现"参照/按照/看看人家的风格/标准/写法"类要求，且参照物是目录或位置指代而非明确文件名。
- 执行者只检索/读取了目录中**第一个**命名的相关文件即开始下结论——其余同名/同类文件从未打开。
- 用户在打回理由中重新指认参照物，所指与执行者实际读取的文件**不是同一份**。
- 目录里除标准件外还有同名副本（浓缩版/摘录版），未做全集盘点就引用了其中一份。

## Essence

单一文件样本不构成"某目录的风格/标准"。参照系必须是**全目录盘点+逐份实读**后的全集结论：同目录的相关标准件可能不止一份，用户口中的参照物很可能正是执行者没读的那份。模糊指代（"人家""那个文件"）不能凭记忆或碰到的第一份文件消歧，只能通过盘点全集+对比内容来确定唯一所指。盘点成本是分钟级，漏盘的代价是整版作废加失败评分。

## Approach

1. **先盘点后参照**：接到"参照某目录风格/标准"类指令，第一动作对该目录执行全量列举（列目录+glob 特征名），产出文件清单（含体积与日期），不先动笔。
2. **逐份实读**：清单内每份相关文件至少实读头部与关键段落；多份同类文件（如"官方文档+官方最佳实践+现行规范"）逐一比对，各自的角色（标准/清单/现行版）分别定性。
3. **副本甄别**：清单中同名或同内容文件标出，确认唯一权威源；引用参照系时只引权威源（副本处置与单一源机制见关联经验 2026-11-07-single-source-file-maintenance-duplicate-purge）。
4. **模糊指代消歧**：用户指代不明确时，用"目录实查+内容特征匹配"确定所指（谁最符合"能简单尽量简单"这类描述），仍不能唯一确定则在动笔前向用户确认，禁止凭单文件默认。
5. **红线固化**：把"参照某目录风格前必须先盘点全目录并实读"固化为产物内的显式红线条款，防下一轮重犯；失败根因如实写入产物附录（不辩解），与"打回理由映射修订动作"流程叠加使用。

## Faster Next Time

- 把"参照系盘点清单"作为该类任务的第 0 步交付物（目录清单+逐份定性结论），分钟级成本，直接防整版返工。
- 警惕信号：准备下笔时能说出的参照文件只有 1 份，而目录列举结果 ≥2 份——参照系必然残缺，先补读再写。
- ROI 对照：全目录实读（分钟级）vs 失败评分+整版重写+信任损失（整轮成本）。

## Applicability Boundaries

- 适用：产物需要"参照某目录/某仓库/某位置的风格、标准、写法"；目录内有多个候选文件；用户指代模糊。
- 不适用：参照物已明确到具体文件路径且唯一；产物为一次性小改（盘点全套流程过重，直接读指定文件即可）。
