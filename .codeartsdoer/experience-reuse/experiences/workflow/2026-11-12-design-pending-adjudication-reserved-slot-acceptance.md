# design 阶段暂挂裁决项承接：三列承接表+推荐项留标记+预留落位不实施，裁决后回填免重开

## Scenario

SDD 流水线 design 阶段，上游 spec 附录含编号待裁决项（涉及部署形态、接入方式、范围裁剪等实施分叉），且用户明令"design 不得替用户做最终决策，可给推荐项但必须留【待裁决】标记"。与既有"预设方案继续设计"口径的前提不同：本次用户明示维持暂挂、禁预设设计，设计仍须一次成型不阻塞。

## Key Signals

- 派工单逐条列出待裁决项编号并出现"维持暂挂""禁自作主张""不得替用户做最终决策"等字样——决策权显式留在用户侧。
- 裁决项直接决定实施分叉（如废弃口径/接入方式/就绪方式/范围边界），按任一未裁决方案写死即埋返工雷。
- spec 附录裁决项与 design 章节、后续配置点存在落位关系——只登记不落位会让执行阶段悬空。

## Essence

暂挂裁决项的承接本质是"**登记落位，不代决策**"：design 给每项建结构化承接行（承接口径原文指针 / 设计落位章节 / 改判影响面 + 推荐项与理由），设计正文对裁决依赖点只**预留落位**（章节或配置点占位、写明"待裁决后回填"），不按任何未裁决方案实施；推荐项必须带理由且显式保留【待裁决】标记，防下游把推荐当定论。改判影响面列把"裁决改判的返工成本"在设计期就显形——影响面小则裁决阻力低，影响面大则用户裁决更审慎，这正是把成本前置到决策时刻的价值。

## Approach

1. **承接表**：每项四栏——承接口径（spec 附录原文指针）/ 设计落位章节（正文中该裁决依赖点所在位置）/ 改判影响面（改判时需联动的设计章节与机制清单）/ 推荐项与理由（附【待裁决】标记）。
2. **正文预留落位**：裁决依赖点写"预留：见 §X，待裁决后回填"，机制小节只描述与裁决无关的不变部分，分叉点留占位。
3. **推荐项格式固定**：推荐值 + 理由 + 显式【待裁决】标记三件套，缺一不可；理由给事实依据（实测数据/资产现状），不给倾向性修辞。
4. **改判影响面预评估**：逐项列出"若裁决改判，需联动修改的设计章节/接口契约/部署形态"，作为回填时的改动清单底稿。
5. **自检条款**：设计自检加一条——全部暂挂项在正文中零实施、零定论化表述（grep 裁决项关键词核对无写死配置）。

## Faster Next Time

- 裁决后的回填 = 只改承接表状态列 + 对应落位小节正文 + 改判影响面清单执行，文档结构不动——这是"预留落位"口径的核心收益（免重开 design）。
- 警示信号：发现自己写了"采用方案 X"而该方案在暂挂清单中 → 立即降格为"推荐项+【待裁决】"，正文改占位。
- 反模式：按推荐项直接写死配置（改判即返工）；承接表只登记不落位（执行阶段无挂点）；把暂挂项写成"已解决"或从承接表悄悄移除；推荐项不带理由（用户裁决成本翻倍）。
- 摘要呈报把"待裁决项承接结果"列为必报项（逐项状态一行），与门禁登记结果并列。

## Applicability Boundaries

- 适用：spec 附录有编号裁决项 + 用户明示暂挂/禁代决的场景；裁决项关联部署形态或实施分叉、回填成本需要前置评估的场景。
- 不适用：用户允许按预设方案继续设计的场景（改走既有经验 workflow/2026-11-07-design-stage-large-spec-inheritance-discipline 纪律三的"预设承接、可改判"口径）；spec 无裁决项（整章省略）。
- 相邻经验边界：workflow/2026-11-07-spec-stage-conflict-adjudication-items 管 spec 阶段"识别冲突并编号呈报"（上游产出口径），本条管 design 阶段"承接已编号暂挂项"（下游消费口径），两者构成裁决项生命周期的上下游配对；本条与纪律三的差异在于前提——前者允许预设方案继续设计，本条是明令禁预设时的降格承接。
