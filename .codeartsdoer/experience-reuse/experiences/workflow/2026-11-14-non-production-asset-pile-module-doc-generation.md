# 非生产素材堆模块的知识文档生成：三步性质判定代替逐文件阅读

## Scenario
为仓库生成 codebase-knowledge/wiki 模块文档（含逐模块派工、全量生成、新增模块补文档）时，遇到**非生产目录**型模块：素材缓存堆、演练留痕区、抓取内容落地区、知识源沉淀区、评估残留区。此类模块与其他生产模块同处一棵模块树，必须产出一篇同格式文档，但其内容主体不是代码。工作流规模为单模块单篇文档派工，素材文件量可达数十至数百个。

## Key Signals
- 符号骨架/切片产物显示该模块符号数异常少（如仅个位数文件、十几个符号），与目录实体规模严重不匹配。
- 目录清单显示大量非代码文件：媒体、文档、日志、库文件、二进制安装包。
- 存在按"来源 ID"命名的同构子目录堆（每堆文件类型构成相似），另有少量一次性脚本散落在根。
- 痛点：若按生产模块套路读代码写架构，会得到几乎空白的架构小节；若逐文件阅读素材，成本不可接受且产出只是文件清单。

## Essence
素材堆模块的文档价值主体是**素材性质**而非代码结构。文档目标应从"描述代码架构"转为"描述有什么、什么性质、承担什么职责"。判定素材性质不需要逐文件阅读：骨架/切片先行锁定真实代码面，扩展名统计快速刻画各素材堆构成，每堆抽读 1-2 个代表性文档即可确认内容性质。

## Approach
1. **先读符号骨架与切片产物，锁定代码面**：确定该模块真实代码文件与符号数量，据此直接排除"逐文件读"路线；一次性脚本若 import 主工程包，该导入关系是 Relations 小节"依赖"的主要来源。
2. **列目录清单 + 扩展名统计 + 抽读代表**：对每个素材子目录统计文件总数与扩展名分布（一条 shell/PowerShell 统计即可），再从最有代表性的子目录抽读 1-2 个 md/文档确认内容性质；同构堆只需确认一次。
3. **按性质写作而非罗列清单**：架构设计小节用"- **子目录**：一句话描述"覆盖全部子目录，重点写每堆"有什么、什么性质"；禁止罗列具体文件名清单。
4. **执行粒度纪律锁定文档规模**：全文上限（如 5KB）、架构设计小节字数上限（如 300 字）、其余单节上限（如 200 字）；机器字段、敏感信息纪律照常执行。

## Faster Next Time
- 先读骨架（几秒）即可判定模块类型并选定文档策略，避免直接扎进素材堆逐文件阅读的沉没成本。
- 扩展名统计一行命令即可刻画多个素材堆的构成，是性质判定的最高性价比动作。
- 抽读 1-2 个代表即止：同构堆性质一致，多读无增量信息。
- 遇到"根目录散落一次性脚本 + 素材子目录"的形态，直接套本三步法；代码面以骨架为准，不以目录观感为准。

## Applicability Boundaries
- 适用：非生产目录型模块（素材缓存、演练留痕、抓取落地、知识源、评估残留）的单篇知识文档生成。
- 不适用：正常生产代码模块（按常规架构文档方法）；同质模块库的批量文档化（见相关经验"同质模块库代表性抽样"）；第三方开源克隆大目录（应判定不建模块并路由既有主题，见相关经验）；模块是否成立本身存疑需先裁决的场景。

## Evidence or Examples
- 实证会话（2026-11-14，会话 ses_e2d450151ffe5t8hvDlC75VIGX）：为非生产模块 temp 生成知识文档。骨架仅 14 符号/6 文件（1 个 mock 服务器 + 3 个演练/转写脚本）；素材面为 4 个按来源 ID 命名的抓取堆（6-210 个文件，含图片/音频/视频/脚本/JSON）+ 1 个知识源目录（8 个 md）+ 1 个演练留痕目录（11 文件）+ 2 个残留小目录。扩展名统计一轮完成 4 堆刻画，抽读知识源代表 md 确认"结论前置带出处"性质；imports.json 揭示演练脚本 import 主工程 adapter 包，写入 Relations。两份产物（md + 同目录同名 code-links.json）一次写入成功，全文控制在粒度纪律内。
- 该方法与"同质模块库代表性抽样"的边界：前者是单模块内多个异质素材堆各判一次性质，后者是多模块同质时抽代表模块判一次。
