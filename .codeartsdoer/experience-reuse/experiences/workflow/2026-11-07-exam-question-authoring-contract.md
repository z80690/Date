# 学习考核出题任务契约：维度分段编号+双文件分离+难度配比

## Scenario
- 触发信号：多代理学习流水线中，"学习 Worker"完成 N 篇论文 + N 个项目学习后，需独立的"出题 Worker"产出考核题验证学习效果（本轮为 kb_arch_foundation ST2：5 论文 + 5 项目，共 50 题）。
- 规模：智能体流水线内大批量结构化产出（50 题干 + 50 条答案要点组），单会话一次完成。
- 派工方式：以"派工单"形式下发——显式给出角度×数量、编号体系、题型、禁令、产出文件路径与格式。

## Key Signals
- 痛点一：题目与答案混写会让题干措辞泄漏答案提示，考核区分度失效。
- 痛点二：无统一编号体系时，批改、复核、难度统计都无法按题定位。
- 痛点三：不限题型与难度配比时，产出易退化为背诵题（如"请说出论文标题"），考不出理解与应用。
- 有效信号：本次派工单一次性锁死契约要素，出题 Worker 两次 write 成功、单轮通过、零返工。

## Essence
出题任务成败不在"写得快"，而在派工契约是否预先锁死四件事：维度到编号段的映射、答案物理隔离、难度/题型配比、批改粒度。契约完整的出题任务可单轮通过；契约缺失会因答案泄漏、编号混乱或背诵化而返工。

## Approach
出题派工单五要素（可直接复制为任务描述）：
1. 维度分段编号：按考核维度切分编号段并绑定考察点与材料来源，如 A1–A10 架构（P1/P2）/ B1–B10 协作（P3/J1/J2）/ C1–C10 记忆（P4/J5）/ D1–D10 方法论（P5/J4）/ E1–E10 治理与反例（J3/J4/J5）。
2. 题型与禁令：限定题型（概念辨析 / 架构选型判断 / 工程决策情景题，情景须绑定真实项目场景如知识库治理、状态机、注册表、编码必审），显式写明"禁纯背诵题"。
3. 难度配比：理解 40% / 应用 40% / 综合判断 20%；比例可按考核层级调整，但必须显式给出数字，否则执行方自行其是。
4. 双文件分离：题目文件只含编号+题干、零答案提示；答案 key 文件每题 3–6 条判定要点供批改；两个文件路径分开指定。
5. 职责边界：出题 Worker 只出题不作答（作答由被考者或另一角色完成）；出题所依据的学习材料须声明"已验证真实"，防止基于幻觉材料出题。

## Faster Next Time
- 直接复用五要素派工单模板，替换维度与配比即可，无需重新设计契约。
- 收口验收两查：① 题目文件全文检索无答案字样或提示性措辞；② key 文件中每题编号均有 3–6 条判定要点对应。
- 题号即坐标：批改、复核、难度分布统计均按编号段聚合，免于重读全文。

## Applicability Boundaries
- 适用：知识型/方法论型学习成果考核（笔试式、问答式），尤其出题与作答角色分离的多代理流水线。
- 不适用：动手实操考核、自动化测评（应以可执行测试或沙箱任务为载体）；选择题机判场景（判定要点粒度可简化，但双文件分离仍应保留）。

## Evidence or Examples
- 本轮实例（kb_arch_foundation ST2）：5 角度 × 10 题 = 50 题，难度分布理解 20 / 应用 20 / 综合 10。
- 产出：`specs/kb_arch_foundation/st2-exam-questions.md`（仅 50 题干）+ `specs/kb_arch_foundation/st2-exam-key.md`（每题 3–6 条判定要点）。
- 执行证据：general 子代理两次 write 成功、单轮完成、无返工（来源：session ses_e4d699a41ffeZ3To4H5jDmGIJi trace）。
- 反模式：答案要点混入题目文件→受考者从题干反推答案，考核失效；不设编号段→50 题的批改与统计需人工重读全文。
