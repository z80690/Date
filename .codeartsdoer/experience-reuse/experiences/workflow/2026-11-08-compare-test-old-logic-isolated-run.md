# A/B 对比测试旧逻辑轮的隔离执行：git 检出副本配置与跨轮三锁定口径

## Scenario

- 触发信号：多代理流程升级后需验证"新版 SOP 是否优于旧版"，采用对比测试：同一考核任务（出题 50 题）分别用旧版五段 SOP 与新版流程各跑一轮（COMPARE_OLD / NEW 轮），比较两轮产出与执行差异。
- 规模：单子智能体任务级 A/B 对比（一次派工一个子智能体一轮），旧版逻辑已被新版覆盖，无法在当前配置下直接复现。
- 事件序列（真实 trace）：读 git HEAD 检出的旧版配置副本 → 按旧版 SOP 逐步执行（读材料→按 5 角度各出 10 题→题答分离落盘 key）→ 落盘后列目录+读文件双通道验证 → 返回固定结构摘要。

## Key Signals

- 旧版配置已不在当前工作区：必须从 git 历史（HEAD=2861cd2）检出副本到独立目录（temp/compare/），派工单显式写明"严格按该副本执行、不使用新版 SOP"，否则执行方会混用两版逻辑。
- 对比失效风险：若材料指针、判分口径、验证方式在两轮间不一致，产出差异将无法归因——分不清是"流程版本差异"还是"输入/口径漂移"。
- 有效信号：本轮派工单将"同口径（与对照轮完全一致）"逐条写进材料指针、"判分口径与 NEW 轮一致"写进 key 文件头部、"落盘后必验"写成硬性交付条款，执行单轮通过、零返工。

## Essence

对比测试有效性取决于**唯一变量原则**：只让被测逻辑版本成为变量，其余输入与判定标准必须跨轮锁定一致。关键非显而易见做法是把"口径一致性"写进产物本身（key 文件头部显式声明"判分口径与对照轮一致，三条边界规则"），使口径对齐成为可审计证据，而不是停留在派工单口头声明。执行纪律上，旧版副本是本轮唯一执行依据，禁止执行方以"新版更优"为由自行混合 SOP。

## Approach

1. **版本隔离**：从 git 历史检出旧版配置到独立目录副本（如 temp/compare/examiner.md，注明 git HEAD），派工单写明"按副本执行、不使用新版 SOP"。
2. **材料锁定**：输入材料指针与对照轮逐条一致（同一批文件、同一路径原样下发），不因换轮而增删。
3. **口径锁定**：判定口径（如 PASS/PARTIAL/FAIL 三条边界规则）跨轮一致，并写入产物头部声明，形成可审计的口径对齐记录。
4. **验证条款化**：把"落盘后必验（列目录确认存在+读文件确认非空，验证结果写入返回摘要）"写成派工单硬性交付条款，而非依赖执行方自觉。
5. **摘要固定结构**：返回摘要固定为"各步执行结果+文件路径+计数（题数/分层覆盖）+验证方式与结果"，两轮摘要逐项 diff 即可定位流程差异。

## Faster Next Time

- 直接复用"检出副本 + 三锁定（材料/口径/验证）"清单组装对比轮派工单，省去每次现场约定对照规则的成本。
- 对比轮产物头部声明口径来源（"与 X 轮一致"），后续审计无需回溯派工单即可确认可比性。
- ROI：本轮单轮通过、零返工；若无三锁定，两轮产出不可比，对比测试需整轮重跑。
- 反模式警示：在执行方 prompt 中同时给出新旧两版 SOP（"参考新版但按旧版执行"）——版本污染，对比失效；正确做法是只注入被测版本副本。

## Applicability Boundaries

- 适用：同一任务契约的新旧版本对比（子智能体 SOP 对比、prompt 版本对比、流程改动前后验证）；要求两轮输入材料可得且口径可显式声明。
- 不适用：探索单一版本正确性的常规执行（无对照轮需求）；输入材料本身在被测变更范围内（此时材料无法锁定，对比结论天然不纯，应改用其他验证方式）。
- 前提约束：旧版配置必须能从版本控制历史完整检出；若历史不可得，只能凭记忆重写旧版，版本保真无法保证，对比结论降级为"近似对照"。
- 与相邻经验的分工：出题任务的派工契约格式见 workflow/2026-11-07-exam-question-authoring-contract；判分口径三条规则本体见 workflow/2026-11-07-independent-exam-grading-rubric；落盘后必验的操作细节见 agent-ops/2026-11-07-write-receipt-not-proof-of-persistence——本条只约束对比测试场景的版本隔离与跨轮口径一致性，不重复上述内容。
