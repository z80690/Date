# 清单类条目的分类归位以登记权威源为准：命名前缀是检索线索不是分类依据

## Scenario

以 patch JSON 模式对知识库 Wiki 文档做小节级修订（subagent 独立执行、无法中途确认），本轮增量新增 3 篇笔记，需在"架构设计"小节的分层列表中把新笔记归入正确类别（学习成果/工作笔记/机制文档等）并同步各类别计数与总篇数。坑在于：条目的文件名前缀与登记权威源登记的类别并不保证一致——本例"学习成果-P003演练经验.md"带"学习成果-"前缀，登记表中却登记为"工作笔记"。归错类会让列举清单与类别计数双双失真，且合并进文档后难以察觉。

## Key Signals

- 前缀信号（误导源）：文件名前缀"学习成果-"直觉指向"学习成果"类别；若按前缀归位，会得出"学习成果 7→8 篇、工作笔记 5→7 篇"的错误走向。
- 登记信号（权威源）：登记表（索引）的登记行明示登记类型——本例三篇新增笔记（登记行 124–126）全部登记为"工作笔记"，正确走向是"工作笔记 5→8 篇、学习成果保持 7 篇"。
- 系统性错位证据：登记表中既有"学习成果-SDD官方文档 | 工作笔记"行——命名前缀体系与类别枚举本就正交，前缀与登记类型不一致是常态而非异常。
- 派工信号：派工单明示"按索引登记类型归位"，即在派工契约层面已认定登记类型优先于命名前缀。
- 连带信号：凡小节正文同时承载"分类列举清单 + 类别计数"，归类是计数的上游输入——归类错则计数必错。

## Essence

分类归位的权威源是登记表中的登记类型字段，文件名前缀只是检索线索。命名体系（前缀、目录名、命名习惯）与类别枚举是两套正交体系，维护者登记时的类别判定不承诺与命名对齐。清单类修订的正确顺序是：先从登记权威源取登记类型完成归位，再由归位结果推导各类别计数与总数——归类错则计数必错，且这类失真不会在"存在性核实"（文件在不在）与"计数实测"（总数对不对）中暴露，只有"登记类型 × 归位结果"比对才能发现。

## Approach

1. **定位登记行**：在登记权威源（索引/登记表）中找到每个新增条目的登记行，读出登记类型字段，并记下行号作为归位证据。
2. **按登记类型归位**：小节列表中把条目放入登记类型对应的分组，忽略文件名前缀的暗示；前缀只用于定位文件本身。
3. **先归类后计数**：总数与各类别计数从归位结果推导（本例：工作笔记 5→8、学习成果保持 7、总篇数 25→28），禁止用前缀推断类别再反推计数。
4. **归位依据留痕**：code_refs 引用登记行行号（如 `notes/知识库索引.md:124`），使归位结论可复核。
5. **登记缺行时的失败分支**：条目未在登记权威源登记（或登记行与实文冲突）→ 不按前缀兜底臆测归类，升级呈报等待登记补齐——登记维护与文档修订是两个职责，修订者不代行登记判定。

## Faster Next Time

- 一行决策规则：凡修订"分类列举清单 + 类别计数"类正文，每个新增条目先读登记行的登记类型，再归位、再计数；前缀只作文件定位线索。
- ROI：登记行抽读（每条目一行）即可避免归错类后的双重失真（清单归属 + 类别计数）返工，且该失真合并后极难被常规核查发现。
- 反模式：按文件名前缀归类；把派工单叙述里的类别口语词（如"学习成果三篇"）当登记类型；登记缺行时按前缀兜底；只改计数不改清单归属（或反之），同一小节自相矛盾。

## Applicability Boundaries

- 适用：登记表/索引驱动的内容库（知识库、笔记层、技能库、资产清单）的小节级修订；任何"按类别分组的清单 + 计数"类正文更新；命名前缀与类别枚举存在正交性的场景。
- 不适用：无登记机制的自由文档（命名约定本身即惯例权威时按约定）；登记权威源自身待重建/纠错的场景（先修登记再修订）；条目无分类维度、只有平铺清单的正文（无归位问题，仅剩计数实测问题）。
- 与相邻经验分工：`wiki-stat-count-drift-recount-on-revision` 管计数的时效实测（glob/登记表核对数字），本条管归类的权威判定（归类是计数的上游输入）；`wiki-section-same-layer-action-criteria` 与 `wiki-section-tiered-revision-judgment-contract` 管逐节 replace/line_number_only 分流与只读 subagent 执行契约；`wiki-added-diagnostic-probes-body-exclusion` 管新增条目的正文收录粒度（不罗列内部条目细节，本 trace 派工单的兜底约束亦归该条管辖）；`claimed-count-vs-fact-source-conflict` 管数值口径冲突的仲裁结构，本条把"以权威源为准"从数字字段扩展到分类字段。
- 证据等级：单次成功闭环（归位、计数、patch 落盘全链），属预防性经验——前缀陷阱在本轮被派工契约提前拦截、未实际触发错误，跨项目复用稳定性待同类任务检验。
