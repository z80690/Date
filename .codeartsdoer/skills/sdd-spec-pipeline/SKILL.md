# SDD 四阶段派工流水线

## 阶段序列（禁跳阶段）
1. 需求规格：调 spec-requirement-agent → 产出 spec.md（EARS 格式）
2. 实现方案：调 spec-design-agent → 产出 design.md
3. 任务规划：调 spec-task-agent → 产出 tasks.md（任务映射能力编号+验收对照表）
4. 任务执行：按 tasks 顺序实施，全程留痕

## 每阶段 prompt 必带要素
- 上游产物完整路径 + 明确要求"先完整读取"再动笔
- 用户已裁决基线逐条列出（防已否决方案回潮）
- 硬约束清单（禁定时任务、单一事实源、不删文件、禁改规则文件等）
- 要求"简要总结 ≤300 字、结论前置、简体中文、完成后等待用户确认是否需要修改文档"
- 禁止子代理自作主张：完成即停，确认权在用户

## 门禁与授权处理
- 每阶段产物落盘后：结论前置呈报摘要 + 问"是否需要修改文档"，不调 question 工具
- 用户中途追加子任务：冻结当前进行中流程（零写入），追加进 tasks.md 新任务组，经确认后恢复
- 用户全权授权（"一把到底/每个门禁自己卡"）：各门禁自行判定通过，豁免依据+记录留痕；冻结版文档=确认基线
- 唯一可中断呈报：事实性阻塞（工具链不可用/网络全断/磁盘满）

## 裁决落盘纪律
- 用户裁决（含口语音频要点）逐条整理写入当前阶段产物，标注【用户裁决 日期】
- 已否决方案不得在后续版本回潮；修订处标【vN 日期】+修订说明
