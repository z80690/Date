## 角度一：SDD 总纲（第 1–10 题）

**1.【记忆】**
- 答案要点：SDD = Specification-Driven Development；中文含义=规格驱动开发模式。
- 判分：PASS=英文全称拼写正确且中文含义正确；PARTIAL=仅答出全称或仅答出中文含义（或中文表述大意对但不完整）；FAIL=全称拼写错误或含义错误。

**2.【记忆】**
- 答案要点：需求规格 → 技术设计 → 任务规划 → 编码实现（顺序必须正确）。
- 判分：PASS=四阶段名称齐且顺序正确；PARTIAL=四阶段齐但顺序有误，或漏一个阶段；FAIL=漏两个及以上或顺序严重混乱。

**3.【理解】**
- 答案要点：保障每一步开发均有据可依；实现过程可控与历史可查。
- 判分：PASS=两项保障均答出；PARTIAL=仅答出其中一项；FAIL=答错（如"提高代码运行速度"等材料外臆测）。

**4.【记忆】**
- 答案要点：{项目根路径}/.codeartsdoer/specs/{产物文件夹名}/。
- 判分：PASS=模板完整（含项目根路径、.codeartsdoer/specs、产物文件夹名三要素）；PARTIAL=缺一要素（如漏 {项目根路径} 或漏产物文件夹名占位）；FAIL=路径结构错误。

**5.【理解】**
- 答案要点：提示=产物文件夹名由模型自主生成，受生成随机性影响，同一需求描述多次输出的产物文件夹名可能存在差异；后果=产物定位漂移、跨阶段引用断链；规避=固定目录名。
- 判分：PASS=提示/后果/规避三点齐（后果答出"可能存在差异"及任一衍生后果即可）；PARTIAL=仅答出提示与后果、或仅答出后果与规避；FAIL=未指出随机性差异或规避方法错误。

**6.【理解】**
- 答案要点：标准 SDD 工作流=智能体主导推进流程串联，用户在关键节点接受或拒绝生成的文档（每阶段产物人工确认后进入下一环节）；斜杠命令模式=通过四个标准化斜杠命令由开发者自主调度、自主推进流程。
- 判分：PASS=两种方式名称齐+主导方差异（智能体主导 vs 开发者自主）明确；PARTIAL=两种方式名称正确但主导方差异未说清；FAIL=两种方式混淆或答错。

**7.【理解】**
- 答案要点：新项目初期（0→1）用标准 SDD 工作流快速跑通框架、建立完整的 SDD 文档体系；进入中期迭代切换到斜杠命令模式，利用四个命令进行增量开发和局部重构。
- 判分：PASS=两侧阶段-方式-用途对应完整；PARTIAL=仅答出一侧的阶段与方式对应；FAIL=对应关系颠倒或缺失用途。

**8.【记忆】**
- 答案要点：执行方式、灵活性、适用场景、适用角色（四个维度）。
- 判分：PASS=四维度齐；PARTIAL=答出 2–3 个维度；FAIL=≤1 个或答出表外维度冒充。

**9.【理解】**
- 答案要点：标准 SDD 工作流=产品经理快速验证想法、独立开发者做小型项目；斜杠命令模式=架构师需把关技术方案、团队协作开发企业级应用。
- 判分：PASS=两侧角色各答全（每侧至少完整一组）；PARTIAL=两侧各至少答出一个角色、或仅一侧答全；FAIL=两侧混淆或漏答一侧。

**10.【理解】**
- 答案要点：机制依据=阶段间硬依赖由命令前置条件强制：/sdd-design 必须存在目录和 spec.md；/sdd-tasks 必须同时存在 spec.md 和 design.md；/sdd-apply 必须同时存在 spec.md、design.md 和 tasks.md——前置条件在命令机制层面强制了阶段顺序，故属官方内建约束而非外部纪律。
- 判分：PASS=答出"由命令前置条件强制"+至少两条依赖示例；PARTIAL=仅答出"命令前置条件"或仅罗列依赖示例而无结论句；FAIL=归因为"纪律要求/用户自觉"等错误解释。

- 判分：PASS=0→1 场景+理由齐（补充场景加分不强制）；PARTIAL=仅答场景名或仅答其他场景；FAIL=答成迭代期项目用标准工作流等颠倒情形。

## 角度五：执行编码实现阶段与命令依赖（第 41–50 题）
