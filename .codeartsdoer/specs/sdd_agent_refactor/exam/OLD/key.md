# 考核参考答案与判分依据（OLD 轮·key）

> roundId=OLD ｜ 与 questions.md 逐题对应（1–50）。
> 判分口径（与 NEW 轮一致，三条边界规则）：
> - **PASS**：答案覆盖全部答案要点，或语义等价表述（措辞不同但含义一致放行）；超出要点的额外正确内容不扣分（超额正确放行）。
> - **PARTIAL**：触及核心要点但有缺漏，缺什么必须在判分依据中写明；不改变结论方向。
> - **FAIL**：答案与材料要点矛盾（如命令与产物错配、依赖方向颠倒、编造材料不存在的机制），或关键要点缺失致语义偏离。
> - 编造材料中不存在的命令参数/机制（如"自动重试三次"）一律 FAIL。
> 考教分离：本文件仅交付主智能体，禁止下发执行代理或混入题库。

## 角度一：SDD 总纲（题 1–10）

**1.【记忆】**
- 答案要点：英文全称 Specification-Driven Development；中文含义：规格驱动开发模式。
- 判分依据：两者都正确→PASS；只答对全称或只答对中文其一→PARTIAL（缺另一半）；写成 Software-Driven 或"需求驱动开发（Specification→需求）以外的错译"且与"规格"语义相悖→FAIL。

**2.【记忆】**
- 答案要点：需求规格→技术设计→任务规划→编码实现（四阶段、顺序正确）。
- 判分依据：四阶段齐全且顺序正确→PASS；缺一个阶段或顺序颠倒→PARTIAL（写明缺哪项/哪两阶段换序）；四阶段名称与材料不一致（如把"编码实现"写成"测试"）→FAIL。

**3.【记忆】**
- 答案要点：{项目根路径}/.codeartsdoer/specs/{产物文件夹名}/。
- 判分依据：三段占位符齐全且层级正确→PASS；缺"产物文件夹名"层或写成其他根目录（如 .codearts/）→PARTIAL；根路径段写错（如 specs 放在仓库外）→FAIL。

**4.【理解】**
- 答案要点：保障每一步开发有据可依；过程可控；历史可查。
- 判分依据：三点齐全→PASS；仅答两点→PARTIAL（写明缺哪点）；答"提高开发速度"等材料外臆断且遗漏三点→FAIL。

**5.【理解】**
- 答案要点：标准 SDD 工作流——智能体主导推进（用户关键节点确认）；斜杠命令模式——开发者自主调度（可灵活跳过或重复任意阶段）。
- 判分依据：两种方式名称+主导方均正确→PASS；只答对方式名未答主导方→PARTIAL；把主导方对调（说斜杠命令由智能体主导）→FAIL。

**6.【理解】**
- 答案要点：用户主要在关键节点确认（接受或拒绝生成的文档）；每阶段产物人工确认过后才进入下一环节。
- 判分依据：接受/拒绝+确认后进入下一环节两点齐→PASS；仅答"确认后进入下一环节"无接受/拒绝表述但语义等价→PASS（语义等价放行）；答"全自动无需确认"→FAIL。

**7.【应用】**
- 答案要点：选标准 SDD 工作流；理由：新项目从 0 到 1 启动，从需求分析、系统设计到 SDD 文档体系构建完整开发流程（材料适用场景首条）。
- 判分依据：选型正确+理由贴合材料→PASS；选型正确、理由笼统（"更规范"）→PARTIAL；选斜杠命令模式→FAIL（与材料场景选型矛盾）。

**8.【应用】**
- 答案要点：手动修改 spec.md→组合执行 /sdd-design→再执行 /sdd-tasks；无需重新生成 spec.md。
- 判分依据：改 spec+design+tasks 三步齐全→PASS；漏改 spec 或漏跑 /sdd-tasks→PARTIAL（写明漏项）；回答需重跑 /sdd-new 全流程→FAIL（与增量修订路径矛盾）。

**9.【理解】**

- 判分依据：明确不互斥+切换原则→PASS；只答不互斥无展开→PARTIAL；答二者只能二选一→FAIL。

## 角度二：建需求 spec.md 阶段（题 11–20）

**11.【记忆】**
- 答案要点：命令 /sdd-new；输入=需求描述（必选参数）；输出=spec.md。
- 判分依据：命令名+输入类型+产物名三要素齐→PASS；缺"必选参数"这一属性→PARTIAL；输入写成产物文件夹名→FAIL（与其他命令混淆）。

**12.【记忆】**
- 答案要点：{项目根路径}/.codeartsdoer/specs/{产物文件夹名}/spec.md。
- 判分依据：路径完整含 spec.md 文件名→PASS；漏 spec.md 或漏一层目录→PARTIAL；产物写成 design.md→FAIL。

**13.【记忆】**
- 答案要点：业务行为、需求约束（材料原文举例两 类）。
- 判分依据：两类齐全或语义等价→PASS；仅答一类→PARTIAL；编造"性能压测指标"等材料外类别且遗漏原两类→FAIL。

**14.【理解】**
- 答案要点：/sdd-new 的输入（需求描述）是必选参数；其余三命令的产物文件夹名为可选参数，系统会从对话上下文自动推断上一阶段的产物文件夹名。
- 判分依据：必选/可选对比+自动推断机制→PASS；答出必选/可选但漏自动推断→PARTIAL；说四命令参数要求完全相同→FAIL。

**15.【理解】**
- 答案要点：由模型自主生成；受生成随机性影响，相同需求描述输入也可能得到不同的产物文件夹名（后果：产物定位漂移/跨阶段引用断链——学习成果反例）。
- 判分依据：模型生成+随机性差异→PASS；仅答其一→PARTIAL；答"用户手工指定固定不变"→FAIL（与命令表注矛盾）。

**16.【应用】**
- 答案要点：两种途径=手动修改或通过智能体修改；目标=直到符合业务预期。
- 判分依据：两途径+目标状态齐→PASS；仅答一种途径→PARTIAL；答"不可修改只能重新生成"→FAIL。

**17.【应用】**
- 答案要点（示例四项，答出四项即可）：①登录成功后除 token 还返回用户基本信息（昵称、角色）；②锁定时间 15 分钟改 5 分钟；③补充限流（每分钟同一 IP 最多 10 次）；④响应码统一业务码 20000。
- 判分依据：四项齐→PASS；三项及以下→PARTIAL（写明缺哪项）；各项内容与原文矛盾（如"锁定改 30 分钟"）→FAIL。

**18.【理解】**
- 答案要点：再次查看修改后的 spec.md，确认需求理解准确后，单击"开始实现方案创建"。
- 判分依据：确认+按钮动作齐（按钮名可语义等价）→PASS；仅答"确认"无进入动作→PARTIAL；答"自动进入无需确认"→FAIL。

**19.【应用】**
- 答案要点（至少四项）：手机号/邮箱注册、JWT 登录认证、验证码发送、密码重置。
- 判分依据：四项齐→PASS；三项→PARTIAL；编造"第三方 OAuth 登录"等材料外功能点且遗漏原材料功能→FAIL。

**20.【理解】**
- 答案要点：后果=返工——spec 反复重写、阶段产物连锁作废；规避=确认点前置+增量修订路径（改 spec→重跑 design→tasks），禁带病确认。
- 判分依据：后果+规避两侧齐→PASS；仅答一侧→PARTIAL；答"无影响，可随时改"→FAIL。
