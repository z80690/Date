## ③ 机制摘要（SDD 怎么干活 · 结论前置 ≤300 字）

本项目按 SDD 四阶段流水线干活：需求规格（spec-requirement-agent 产 spec.md，EARS 格式）→ 实现方案（spec-design-agent 产 design.md）→ 编码任务（spec-task-agent 产 tasks.md，任务映射能力编号+验收对照表）→ 任务执行（按序实施+留痕），禁跳阶段。每阶段产物落盘后触发门禁：结论前置呈报摘要+询问是否修改；自信度 ≥80% 才过 ST 门禁；全权授权时自行判定通过并留痕豁免依据。编码完工前必审四查（交互功能/断网自包含/控制台无报错/内容覆盖度），未过不完工、返工 ≤3 次。常驻资产：公约 6 条（规矩层冻结）、编队 1主+2持久+4运行时、注册表（派工单口径 19 项 / 事实源实测 11 项激活）、知识库三级加载（规则层→知识库→经验/记忆）。冲突按 规则>知识库>记忆>推断 仲裁并报告。

## ④ 更新方式

- 常驻资产内容变更时：编辑 `sdd-workflow-visual.html` 内 `DETAILS` 数据对象（单一文案源；"背景资产"页由其渲染），渲染逻辑不动
- 同步修订本 README ③ 机制摘要；在 TASK.md 追加进展留痕行（派工单原文禁改）
- 后续派工单（P002…）按同目录命名规范 `日期_P编号_模块名` 在 `.codeartsdoer/specs/` 下新建，编号取历史最大+1（当前最大 P001，无空洞，下一单 P002）
