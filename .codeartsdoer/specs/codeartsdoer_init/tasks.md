# 码道规则初始化与经验沉淀（codeartsdoer_init）任务清单

## 0. 任务总览

### 0.1 执行者图例

| 标记 | 含义 |
|------|------|
| 【Agent】 | 码道 Agent 执行（调研、草案、核对、落盘、响应） |
| 【用户手动】 | 用户人工操作（界面点击、会话重启、测试指令） |
| 【平台自动】 | 码道平台自动行为（生成 .mdc 与 metadata.properties、会话加载规则） |

### 0.2 任务依赖关系

```
1.1 → 1.2 → 2.1 → 2.2 ─┬→ 3.1 → 3.2 → 3.3 ─┐
                        │                     ├→ 4.3 → 5.1 → 5.2 → 5.3 → 6.1 → 6.2
                        └→ 4.1 → 4.2 ────────┘
```

执行顺序：阶段 1（仓库拉取）→ 阶段 2（只读调研）→ 阶段 3（规则创建，人工界面）→ 阶段 4（技能沉淀）→ 阶段 5（验证）→ 阶段 6（验收汇报）。严格串行推进，前置任务未完成判据不得开始后继任务。

### 0.3 严禁项门禁对照表（贯穿全程的检查点）

| # | 严禁项 | 检查点所在任务 | 检查动作 |
|---|--------|--------------|---------|
| G1 | 禁手动往 rule 目录扔裸 .md 文件 | 3.1、3.2、3.3 | 任何向 rule 目录的写入意图一律阻断并提示改走界面创建；3.3 核对目录无裸 .md |
| G2 | 禁把 Hyra 科研代码混入本项目 | 1.2、2.1、6.1 | 克隆位置项目外隔离；调研只读；6.1 终局核对本项目工作区内无 hyra-results 任何源文件 |
| G3 | 禁在规则里写目录结构、技术栈介绍、命令参数 | 3.1 | 文案自检清单：行数 ≤5、只写原则与动词、无路径/参数/临时步骤 |
| G4 | 禁未经确认新增第 6 条规则 | 3.1、3.2 | 规则数量锁定为 5 条，新增请求先问用户，未获对话中明确同意即拒绝 |
| G5 | 禁修改 .workbuddy 目录内容 | 4.3 | 写入白名单排除 .workbuddy 路径，Agent 不读不改该目录 |
| G6 | 禁未经批准改 AGENTS.md 与规则文件 | 4.3、5.2 | AGENTS.md 保持不存在（不创建）；metadata.properties 由平台托管不触碰；5.2 拦截测试双重验证 |

### 0.4 环境约束说明

1. 本项目非 git 仓库，本任务清单不安排任何 git 提交动作；规则 d（提交纪律）为长效行为约束（design §1.2.3）。
2. Agent 对本项目工作区的唯一写入点为 `.codeartsdoer/skills/codeartsdoer-init/SKILL.md`（任务 4.3）；对参考目录的写动作仅限克隆本身，此后只读。
3. 用户手动步骤以交接单形式交付：规则创建走任务 3.1 交接单（D3），生效验证走任务 5.1 交接单（D7）。

## 3. 创建 5 条项目级规则（界面人工操作）

> 本任务组创建动作全部由用户在码道 IDE 界面手动完成（右上角设置→技能与规则→项目级→新建）；Agent 仅提供文案与指引、事后核对（spec 5.3 人工操作提示）。

### 3.1 提交规则创建交接单（文案草案 + 操作指引）
- [ ] 向用户提交 D3 规则创建交接单：5 条规则定稿文案（协作原则/沟通原则/文件禁改/提交纪律/经验复用，文案以 spec 5.3.4 为准）+ 统一属性设置（自动应用=是、适用范围=当前项目、类型=本地）+ 逐条界面操作路径指引；提交前逐条执行文案自检清单
  - 执行者：【Agent】
  - 前置依赖：2.2（结论要点完成规则 e 语义校验）
  - 需求/设计依据：spec 5.3.1-1、5.3.1-5、5.3.4（文案定稿）；design §2.2.2 D3
  - 门禁检查点：G3——文案自检清单逐条核对（行数 ≤5、只写原则与动词、无路径/参数/目录结构/临时步骤）；G4——交接单明示"仅创建 5 条，新增须先征得用户确认"
  - 异常处置：发现超限或违禁内容即精简改写，标注"已精简"及修改点后重新提交用户确认（spec 5.3.3-3）
  - 完成判据：用户拿到可直接照做的交接单并确认文案

### 3.2 界面逐条创建 5 条规则
- [ ] 按交接单在码道界面逐条新建 5 条规则：粘贴规则名与文案、设置统一属性（自动应用=是/当前项目/本地）后保存；每条保存由平台自动生成 .mdc 与 metadata.properties
  - 执行者：【用户手动】（平台自动生成文件）
  - 前置依赖：3.1 交接单获用户确认
  - 需求/设计依据：spec 5.3.1-1、5.3.1-3（数量锁定）、5.3.1-4（属性统一）、6.1（数据约束）；design §2.1.3.1 阶段 3
  - 门禁检查点：G1——全程禁止手工向 rule 目录放置任何文件，一律走界面创建；G4——界面操作仅限这 5 条
  - 异常处置：界面找不到"技能与规则"入口时停止创建并报告环境差异，列入"未决事项"（spec 5.3.3-2）
  - 完成判据：界面显示 5 条规则，逐条属性符合统一要求，通知 Agent 创建完成

### 3.3 核对规则齐套性
- [ ] 收到创建完成通知后核对 D4 规则齐套核对结果三项：① 界面规则数=5 且状态全部启用；② rule 目录下存在 5 组对应的 .mdc 与 metadata.properties 文件；③ rule 目录无裸 .md 文件
  - 执行者：【Agent】
  - 前置依赖：3.2
  - 需求/设计依据：spec 5.3.1-2a（裸文件禁止）、5.3.3-1（保存后未生成 .mdc）、5.6.2-2；design §2.2.2 D4
  - 门禁检查点：G1——核对 rule 目录无新增裸 .md
  - 异常处置：某条缺 .mdc 或 metadata.properties 判定该条创建失败，建议删除后重走界面创建；核对未全部通过不得进入任务 4.3 之后的验证环节
  - 完成判据：核对清单三项全部通过并反馈用户
