## 1.（记忆·角度① ARTEX）

**(a) 双图定位与关联**
- 资产图（Asset Graph）=全局共享真值库：节点为 root_domain/subdomain/ip/service/app/endpoint，归属公司，父子关系与去重 key 由程序计算，agent 只需提交原始信息（笔记 §1.3-1，README:476-483）。
- 探索图（Exploration Graph）=每任务独立：节点为 goal/intent/fact/finding/hint，带血缘边（spawns/derived_from/yields/proves，README:481-497）。
- 关联机制：`exploration_anchors(node_id, asset_id)` 锚点表把两图连起来，支撑资产测试覆盖度与覆盖图（笔记 §1.3-1）。

**(b) traffic 记录代理**
- 原生语义=请求记录与全量明文留痕：嵌入式 go-mitmproxy（traffic.go:1-5 头注释；README:443），每笔目标 HTTP 交换写入人类可浏览文件树+SQLite sidecar 分页索引（笔记 §1.2/§1.3）。

**(c) "HTTPS 伪装+加密心跳"归属认定**
- **非 ARTEX 原生功能，属演练侧衍生用法**。依据：traffic 原生语义仅为请求记录/全量明文留痕，traffic.go 头注释无"伪装/心跳"语义（learn-gate-trace.md §1 L1-4 实测核验）；spec R7 本身即登记为"traffic 模块本地化适配工作量"风险项，design R7 处置=仅取 HTTPS 伪装+加密心跳子集、最多重试 3 次后降级（R7）——即伪装是本单在其 traffic 记录能力之上要自建/适配的子集，不是官方开箱语义。

**(d) 默认端口**
- 前端+API=8787，流量代理=8788（README:319；笔记 §1.5）。

## 2.（理解·角度① PentAGI）

**(a) 官方推荐路径与硬化要点**
- 推荐：`DOCKER_INSIDE=true` + 硬化 dind（Docker-in-Docker）daemon over TLS；硬化要点含 DOCKER_INSIDE_HOST/TLS_VERIFY/CERT_PATH/POLICY_TESTS，证书只读挂载（README:683-707；笔记 §2.3-6）。

**(b) 挂宿主 DOCKER_SOCKET 为何是反例**
- **boot-order race**：宿主 socket 文件未就绪时，Docker 会把它建成目录，dind 启动即卡死（笔记 §2.3-6，README:683-705）。
- **blast radius**：挂宿主 daemon socket 等于授予 agent 特权容器与 mount / 能力——宿主被拿穿，PentAGI 自身也在爆炸半径内被拿穿（笔记 §2.3-6）。

**(c) 采信价值**
- 官方把危险做法与其爆炸半径写成显式反例并给硬化替代=权威结论，本单部署清单可直接采信推荐路径、引用其反例结论，无需自行验证沙箱隔离方案；直接对齐本单 R4（哑端点绑回环）与 R9（Docker 就绪自检）的编制依据（笔记 §2.2/§2.5；§2.6 正例条目）。

**(b) 接入组件与所属端**
- 接入经 **cairn-mcp**（README 三件套：构建端 cairnd/cairn-ingest/cairn-incremental/cairn-rebalance + 查询端 cairn-mcp/cairn CLI + Viewer）；cairn-mcp 属**查询端**（笔记 §3.6）。注册路径按 U11 收口前配置重建（mcp_settings.json，写前备份）。

**(c) 已核验架构不变量（≥两项+机制）**
- ①**查询端只读、零 LLM、零 embedding**（`make verify` 架构不变量强制，2026-11-07 实测 4/4 等价 PASS；pre_check 3.1）——机制：查询路径不依赖任何模型调用，MCP 查询零外连风险，保证查询纯净性。
- ②**构建端与查询端严格分离**——机制：图谱构建（含 LLM 提议）只在构建端发生，查询端只消费已落盘图谱，职责边界由不变量脚本强制。
- ③（补充）**mock provider 为一等公民**（build/internal/llm/factory.go，pre_check 3.1）——构建端可无真实模型跑通全流程；④**结构化回写**：UUID 锚点+human_curated 标记后 LLM 不覆盖，数据完整性可校验（笔记 §3.6）。

**(d) mock provider 对回执模式（方案 a）的复用价值**
- mock provider=框架级确定性响应路径，与本单"本地哑端点绑 127.0.0.1"完全同构：部署时可参照其 factory 工厂模式，把 LLM 提议路径落到 mock/码道智能体回执，查询端保持零 LLM；即"LLM 提议可插拔、查询纯净性不可破"的两层分离，正是方案 a（框架只做状态记录与回执、决策由码道智能体承担）需要的结构（笔记 §3.6/§4-2；design 2.1.3-M2）。

## 4.（应用·角度② 正反例蓝方取证映射）

**(a) 正例可检测特征两类（共提三类）**
- ①**入口类**：钓鱼邮件（西工大案报案事由）+中间人劫持部署远程控制武器（"酸狐狸"平台，笔记 §1.3-1）→蓝方手段：邮件网关与凭据重置链路监控、TLS 会话完整性校验；本地演练=白名单外唯一暴露面监控+抓包识别 MITM/劫持特征（J 系+T 系）。
- ②**内网潜伏与消痕类**：替换 3 个系统文件+3 类系统日志、"精准外科医生"+NOPEN 全面隐身（笔记 §1.3-3）；授时中心案清除武器内存占用/抹可执行文件头/DLL 劫持正常服务自启动/远程关闭杀软（笔记 §2.3）→蓝方手段：关键系统文件哈希基线对比、日志连续性/完整性校验、内存扫描+服务 DLL 校验+EDR 关闭事件告警（W 系取证+SIEM/EDR 模拟）。
- ③**跳板与回传类**：4 层加密隧道、匿名通信节点凌晨登录 80 余次、多级跳板加密回传 NSA 总部（笔记 §2.2/§2.3/§1.3-4）→蓝方手段：非常规时段会话检测、长期低频同源连接告警、匿名代理/TOR 特征流量识别（对齐 J3 异常外连=0）。

**(b) 反例三类共性规律→设计约束映射**
- ①**产物可见即暴露**（暗链当晚被网警发现/1.7 万僵尸账号规模效应自带指纹，笔记 §3.2/§3.4-1）→**白名单与越界即停**（spec 4.3.2/6.1）：一切动作产物被关在受控面内，越界动作即触发终止+留痕+告警。
- ②**工具与物证全留存**（电脑上黑客工具/云服务器登录态/查获源代码 2 套，笔记 §3.2-2/§4.3）→**全程留痕**（回执模式三重留痕：ARTEX traffic 明文留痕+探索图 intent/fact 登记+T 系抓包）：动作全留痕既是复盘素材也是纪律证明。
- ③**手法复用=串并案索引+数字指纹溯源**（同一手法打 80 余个系统/软件"数字指纹"锁定开发者，笔记 §3.2-4/§3.3）→**工具指纹与归档管理**（spec 清理重置+组件清单登记）：演练用工具/框架产生的请求指纹全部登记归档，演练资产不流入真实网络，证据链可回查。

**(c) "1100 余条攻击链路可被还原"的价值**
- 该事实证明：**留痕重建能力决定对抗复盘上限**——攻击方主动消痕（换系统文件/清日志）仍被事后还原（笔记 §1.4 正例价值）。对本地演练三重留痕设计的价值：保证演练每一动作可回放、隐藏判定 J1~J5 可复核、攻防报告可复现——即把正例中受害方"事后还原"能力反向内建为演练基础设施。

## 5.（理解·角度③ 近三月调研）

**(a) ARTEX 发版节奏/风险/处置**
- 节奏：窗口内五连发 v0.3.25（2026-10-29）~v0.3.29（2026-11-11），两周 5 版（api.github.com releases 实测；笔记 §1.1）。
- 风险：版本漂移——快速演进期行为可能变化（如审批工具 schema 变更，README:38）。
- 处置：演练必须锁 release tag（v0.3.29）并在部署留痕登记版本与 SHA256SUMS，禁用页面一键更新漂移（README:189-201 一键更新会中断任务并换装新版；笔记 §1.3）。

**(b) PentAGI 窗口内 release 与能力边界声明的分工含义**
- 唯一正式 release=**v2.2.0**（2026-10-05；笔记 §2.1）。
- 官方能力边界声明（README:93-97）：明示非 BAS/adversary emulation 产品、无预定义攻击剧本、"agent 自写攻击脚本"属概念/未来工作。
- 分工含义：**攻击剧本与演练设计由本单 spec/design 承担，PentAGI 只提供自主执行与工具调度**——这正是方案 a（码道智能体承担决策、框架执行回执）分工的官方依据（笔记 §2.3）。

**(c) EXECUTION_MONITOR 与 AGENT_PLANNING_STEP 双开关**
- 官方建议：<32B 模型**必开**（Qwen3.5-27B-FP8 实测：监督开启质量 2x、开销 2-3x；两开关默认关闭，笔记 §2.3-2/3；调研 §2.3）。
- 本单回执模式下：**保持关闭**。理由：①决策已由码道智能体承担（方案 a），AGENT_PLANNING_STEP 的 planner 二次规划会与码道决策双重规划打架；②EXECUTION_MONITOR 的 adviser 纠偏对象是框架内 LLM agent 循环（同工具重复阈值/总调用阈值），回执模式下框架内无 LLM 循环，开启徒增开销与行为干扰；③关闭口径如实登记于部署清单（调研 §2.3；笔记 §2.6）。
