## A 组：Agent 架构与分层（P1/P2）

**A1** P1 指出智能体决策建模从 MDP 演进到 POMDP。请说明这一演进的核心动因，并解释"部分可观测"这一性质对智能体设计记忆模块产生的直接影响。

**A2** P1 将智能体能力划分为规划、工具使用、记忆、推理、自进化、感知等类别。请辨析其中"规划"与"推理"两类能力的关系与区别，并回答：二者能否相互替代？为什么？

**A3** 你要构建一个网页操作智能体，其运行环境反馈延迟大且经常不完整。基于 P1 的 POMDP 建模视角，说明设计上应优先强化哪个能力模块，并论证该模块为何不可省略。

**A4** P2 提出模块化脑启发架构。请说明该架构将智能体拆分为哪几类功能子系统，并给出"模块化"相比"单体端到端大模型"在工程上的至少两个核心优势。

**A5** 某团队把记忆、规划、工具调用的全部逻辑塞进一个巨型提示词模板实现，评审认为这违背了 P2 的模块化架构思想。请从工程可维护性与能力演进两个角度，为模块化拆分辩护。

**A6** P2 论述了智能体的自进化机制。请辨析"参数级自进化"（如 RL 微调）与"经验级自进化"（如记忆、工作流沉淀）的本质区别，并说明后者为何在工程中落地成本更低。

**A7** P1 强调环境是 Agentic RL 的关键瓶颈并汇编了开源环境框架。假如你负责为内部智能体训练选型环境框架，应满足哪些条件才值得纳入？请给出三条判定标准并说明理由。

**A8** P2 将安全列为基础智能体的核心议题。请为一个带工具执行权限的智能体设计安全分层方案：哪些动作可直接执行、哪些需确认后执行、哪些必须沙箱隔离？并给出分层依据。

**A9** P1 将"感知"列为独立能力类别。请说明在 GUI 智能体（网页/桌面操作）场景中感知模块的输入与输出是什么，以及它与传统纯文本对话智能体的感知有何本质差异。

**A10** 结合 P1 与 P2：一个智能体要实现"自主进化"，需要哪几个能力模块协同形成闭环？若只能先落地其中一个模块，你会选哪个？请用模块间依赖关系论证你的选择。

## B 组：多代理协作与编排（P3/J1/J2）

**B1** P3 提出多代理协作机制的五维度分析框架。请完整列出五个维度，并辨析其中"结构（structures）"与"策略（strategies）"的区别。

**B2** P3 中的协作拓扑包含集中式与分布式等结构。请对比两种结构在通信成本与单点故障风险上的权衡，并说明各自适用的任务类型。

**B3** 你的系统需要实现"Router + 多个 Worker"的任务分发架构。请用 P3 五维度的语言逐维度描述该架构在每一维度上的取值。

**B4** J1 AutoGen 的核心抽象是"对话式编程"——代理之间通过多轮对话协作。请说明什么任务形态适合 AutoGen 的对话驱动协作、什么任务形态不适合，并给出判断依据。

**B5** J2 LangGraph 用"状态图 + 转移"表达编排。请将"代码评审流水线：生成 → 自审 → 不通过则回炉重写 → 通过则合并"建模为 LangGraph 的状态与边（含条件边），并说明该状态中应存放哪些字段。

**B6** J2 LangGraph 相比单向链式（chain）编排的核心优势是什么？"弹性 agent"能力（人工介入、循环、回退）分别如何在其图模型中表达？

**B7** 团队争论：实现客服工单自动分派，用 J1 的对话式多代理还是 J2 的图式编排。请给出你的选型结论与三条理由，围绕任务确定性、可控性、调试成本展开。

**B8** P3 的"协议（protocols）"维度指代理间的通信约定。请说明协议设计不良的典型症状，并论证为什么结构化消息（schema 化）优于自由文本传话。

**B9** 项目规矩要求"禁止自建定时任务，一切触发走事件"。请设计一个基于事件的多代理触发链：用户提交工单 → 分派 → 处理 → 回访。写出每个环节的触发事件与监听者，并说明轮询为何是反模式。

**B10** 多代理系统中"消息风暴"（代理间消息量失控增长）是常见故障。请结合 P3 的结构维度与 J2 的图编排手段，给出两条结构性预防措施，并分别说明其阻断风暴的机制。

## C 组：工作流记忆与经验沉淀（P4/J5）

**C1** P4 AWM 的核心思想是将交互轨迹归纳为可复用工作流。请说明"工作流（workflow）"与"原始轨迹（trajectory）"的区别：归纳过程丢弃了什么、保留了什么？

**C2** P4 提供离线与在线两种工作流归纳模式。请对比两种模式在触发时机、数据来源与适用场景上的差异。

**C3** 某网站改版导致 AWM 中已沉淀的旧工作流失效。请设计一套工作流失效检测与淘汰机制（结合选择性注入），避免失效工作流持续污染后续任务的提示。

**C4** P4 的"选择性注入"指按任务相关性挑选工作流注入上下文。请说明若不做选择性过滤、把全部工作流塞入上下文，会产生哪两类性能损害。

**C5** 你要为团队的编码智能体建立经验沉淀机制。参照 AWM 的思路，设计从"单次任务轨迹"到"可复用经验条目"的加工流水线（至少三步），并为经验条目设计三个必备字段。

**C6** J5 OpenHands 采用事件流（event stream）架构。请说明该架构如何保证智能体执行过程可回放、可审计，以及它与"把状态散落在内存变量中"的做法相比有何优势。

**C7** OpenHands 在沙箱中执行 shell 命令与代码。请为其设计沙箱权限边界：哪些操作放行、哪些需先审计留痕、哪些必须拒绝或需人工介入？并结合"编码必审"纪律说明代码写入动作应如何设卡。

**C8** P4 报告 AWM 在 WebArena 上提升 +51.1%，在 Mind2Web 上提升 +24.6%。请推测任务环境特性与工作流复用收益之间的关系，并据此判断：什么类型的业务适合优先投入经验沉淀建设？

**C9** 经验库出现"同一主题多篇重复经验、且内容相互矛盾"的劣化。请设计一套治理流程：如何合并去重、如何仲裁矛盾内容、如何保证引用方读到的始终是唯一入口。

**C10** 结合 P4 与 J5：若一个智能体运行时要同时支持"事件流可审计"与"经验自动沉淀"两个机制，请设计二者的衔接方式，并说明该衔接带来的额外收益。

**D3** 你接手一个智能体项目，其 AGENTS.md 写明"禁止自建定时任务，一切触发走事件"。新同事想加一个每天轮询外部接口的脚本。请依据 P5 的规范驱动思想，说明正确的落地路径（应改什么、走什么流程），而不是直接写代码。

**D6** J4 MetaGPT 用 SOP 将软件公司角色（产品/架构/工程师等）编码为多代理流水线。请分析 SOP 化的优势，以及它相对 P5 规范驱动方式在"需求变更响应速度"上的短板。

**D7** J4 被标记为反例：近 10 个月无推送、维护衰减。你正在做框架选型，团队有人主张"代码质量好就行，维护停了无所谓"。请给出你的选型判断与三条依据。

**D8** 项目规矩要求"核心状态只存一处（项目事实表），他处活引用不抄值"。请解释这条纪律与 P5 规范驱动思想的内在关联，并说明违反它会造成哪类具体事故。

**D9** 请为你的团队起草一份 AGENTS.md 的最小骨架：列出必备章节，并为每个章节写一句职责说明，使新加入的编码智能体能在 5 分钟内理解自身行为边界。

**D10** 结合 P5 的"有界自治"与本项目"编码必审"纪律：请设计一道质量闸门——AI 生成的代码在什么条件下必须触发人工审查？审查未通过时如何回退处置？要求体现阶段化文件与变更留痕。
