- 核心要点：Agentic RL 把 LLM 从被动序列生成器转为嵌入动态环境的自主决策 agent（MDP→POMDP）；能力分类=规划/工具使用/记忆/推理/自进化/感知；开源环境/基准/框架汇编（500+ 文献综述）。
- 关键结论：RL 是把静态启发式模块转化为自适应 agent 行为的关键机制。
- 正例：按能力模块划分 agent 系统的分类法可直接用于注册表的能力描述维度（适用：能力清单设计；出处=§taxonomy）。

## P2 Foundation Agents（2504.01990）

- 链接：https://arxiv.org/abs/2504.01990 ｜ 条目名：Foundation-Agents-Survey ｜ 核验：2026-11-07
- 核心要点：模块化脑启发架构（记忆/世界模型/奖励/目标/情绪映射）；自进化与自适应机制；多代理集体智能；安全对齐。四部分体系化。
- 关键结论：模块化+跨学科是 agent 系统设计的可行框架；自进化分自动化优化范式。
- 正例：模块化分层（认知/感知/操作模块分立）支撑本单四层架构（基础设施/领域/业务/界面）的分层合法性（出处=Part I）。
- 反例：无界自主进化缺乏审查会引入不可控行为（后果：行为漂移、不可审计；规避：进化须有护栏与审查——对应本单门禁与审批分离；出处=Part IV）。

## P3 多代理协作机制综述（2501.06322）

- 链接：https://arxiv.org/abs/2501.06322 ｜ 条目名：MAS-Collaboration-Survey ｜ 核验：2026-11-07
- 核心要点：协作机制五维度=actors（参与代理）/types（合作/竞争/竞合）/structures（对等/中心化/分布式）/strategies（角色型/模型型）/coordination protocols。
- 关键结论：从孤立模型转向协作中心的 MAS 需要**显式协作协议**，隐式协作不可规模化。
- 正例：中心化结构+角色型策略（Router/Worker 分工）在复杂任务中规模可控（适用：编排器设计；出处=§structures/strategies）。
- 反例：对等结构无协调协议时代理间消息爆炸、任务收敛失败（规避：显式协议+唯一对外汇报点——对应 Router 唯一汇报权；出处=§lessons）。

## P4 Agent Workflow Memory（2409.07429）【用户裁决入选】

- 链接：https://arxiv.org/abs/2409.07429 ｜ 条目名：Agent-Workflow-Memory ｜ 核验：2026-11-07
- 核心要点：从历史轨迹归纳可复用 workflow，选择性提供给 agent 指导后续生成；离线（先验归纳）与在线（测试时即时归纳）双模式；Mind2Web+24.6%、WebArena+51.1% 相对成功率。
- 关键结论：可复用工作流的沉淀与按需注入显著提升长程任务表现并减少步数。
- 正例：工作流沉淀→经验库条目→按需注入（适用：本单 H5 经验提炼与学习成果条目机制；出处=§method）。
- 反例：无差别注入全部历史 workflow 会引入过时/冲突指导（后果：性能反降；规避：选择性提供+核验日期——对应本单"活引用+核验日期"纪律；出处=§ablation）。
