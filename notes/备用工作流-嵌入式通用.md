# 备用工作流：嵌入式开发通用流程（本机仿真口径）

> 定位：**备用方案**。主力=欧工工作流（notes/欧工主力工作流.md）；本篇为通用嵌入式开发流程，来源为各芯片厂/开源社区公开标准实践（非欧工内容），供主力方案失效或不适配时切换使用。
> 入库日期：2026-11-10。

## 一、方案来源（现成用现成，全部为公开标准）

| 来源 | 类型 | 内容 |
|------|------|------|
| PlatformIO 项目规范（开源社区事实标准） | 项目结构/工具链 | src（源码）/ include（头文件）/ lib（库）/ test（测试）/ platformio.ini（环境配置）；跨平台工具链统一管理（STM32/ESP32/8051 全覆盖） |
| ESP-IDF 官方开发流程（乐鑫官方文档） | 厂商标准流程 | 配置（menuconfig）→ 构建（idf.py build）→ 烧录（idf.py flash）→ 监视（idf.py monitor）→ 测试（pytest-embedded） |
| STM32Cube 生态流程（ST 官方） | 厂商标准流程 | CubeMX 生成初始化代码 → HAL/LL 库开发 → 编译 → 烧录调试（OpenOCD+GDB） |
| Zephyr 项目流程（开源基金会） | 社区标准流程 | west 工作区 → 构建 → twister 测试框架 → 硬件/仿真双跑（native_sim 可本机跑） |
| 嵌入式 V 模型（行业通用方法论） | 流程模型 | 需求分析 → 系统设计 → 模块设计 → 编码 → 单元测试 → 集成测试 → 系统测试，左右对应可回溯 |

## 二、通用流程七环节（与欧工七环节对齐，便于互换）

1. **资料准备**：芯片手册/参考手册/勘误表收集；PlatformIO 初始化工程（标准目录自动生成）。
2. **硬件接口整理**：引脚分配表/外设映射表（CubeMX 或手写），留存工程内。
3. **功能说明**：需求清单 → 验收标准逐条可测（V 模型左侧）。
4. **代码开发**：模块化分层（驱动层→中间件层→应用层）；每层有头文件契约。
5. **编译构建**：PlatformIO/工具链一键构建，产物（固件）落盘。
6. **测试验证**：单元测试（Unity/pytest-embedded）→ 仿真运行（native_sim/Renode/QEMU）→ 日志比对验收标准。
7. **交付维护**：版本打 tag、CHANGELOG 记录、文档同步更新。

## 三、与本机仿真环境的衔接

- **仿真执行器**：Zephyr native_sim（最轻，本机进程直接跑，日志即标准输出）首选；Renode/QEMU 按芯片需求补充。
- **测试闭环**：单元测试与仿真运行均产出可落盘日志；AI 读日志 → 修代码 → 复测，与欧工闭环同构。
- **目录结构**：采用 PlatformIO 标准结构（src/include/lib/test + platformio.ini），在项目根补 docs/（资料）与 logs/（运行数据落盘），对齐底座"目录池"纪律。
- **红线**：同主力——全程本机回环、禁真实外连、执行只认回执。

## 四、主备切换判据

| 场景 | 用哪个 |
|------|--------|
| 协议类/客户项目、要交付文档、按 SOP 走（欧工强项） | 主力（欧工工作流） |
| 无客户协议、纯自研小项目、要跑开源 CI/单元测试 | 备用（PlatformIO/Zephyr 流程） |
| 主力就绪自检三项（工具链/仿真器/日志落盘）任一不可用且修复超限 | 降级到备用 |
| 两者都不适配（如纯 bootloader/裸机汇编级） | 上报用户裁决，禁自行造第三套 |
