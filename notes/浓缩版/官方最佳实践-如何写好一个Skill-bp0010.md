# 浓缩版：官方最佳实践-如何写好一个Skill-bp0010

- 原文路径：docs/官方最佳实践-如何写好一个Skill-bp0010.md
- 最后核验日期：2026-11-06

## 核心要点

- Skill 本质：隐性知识的代码化封装——把最佳实践直接编码进智能体执行路径，而非描述最佳实践的文档。
- 与普通提示词三维度差异：存储位置（团队共享库 vs 个人笔记）、激活方式（智能体按需自动加载 vs 手动粘贴）、迭代机制（版本化可回滚 vs 无版本管理）。
- 三核心要素：
  - name：唯一 ID，命名原则"动词+名词"（好：review-code/analyze-competitor；坏：helper/tool1）。
  - description：最关键且最易被轻视——智能体决定是否激活技能的唯一判断依据；写得模糊等于白写；须写清触发场景与不适用边界。
  - instructions（执行指令）：激活后的执行剧本，越具体执行越稳定，可含分析框架、输出格式、边界处理。
- 渐进式加载三层架构（防止全量常驻污染上下文）：
  - 第一层 元数据：仅 name+description，常驻视野，用于判断"有没有可用技能"。
  - 第二层 SKILL.md 正文：description 匹配成功后才读入，承载全部"怎么做"。
  - 第三层 捆绑资源：脚本/参考文档/输出模板，执行中按需加载。
  - 收益：技能数量增加不线性增加上下文负担——50 个技能常驻仅 50 条轻量摘要。
- 三类可附带资源：自动化脚本（固定机械操作）、参考文档（长篇背景知识，建议加目录索引便于定向检索）、输出模板（严格格式要求场景）。

## 关键结论

1. 写技能先写好 description 触发条件，其次才是 instructions。
2. 知识库按需加载设计可直接复用三层架构映射：索引（元数据）→ 浓缩版（正文摘要）→ 原文（深读）。
3. 本地技能审查/编写的对照基准就是本文档三要素与触发条件写法。
