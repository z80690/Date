## 二、本轮学习结论（详见 notes/DevSidecar+Tor攻防环境搭建笔记.md）

1. DevSidecar=按域名选择性 mitm+加速：名单内解密加速（github 实测 200）、名单外 TCP 直转（出口 IP 不变=设计行为非故障）。**定位=仅加速，永不隐匿**。
2. Tor 隐秘三要素：网桥（PT 插件伪装）→ socks5h 出口 → 出口 IP≠真实 IP。PT 插件已就位（OnionShare 捆绑 obfs4/meek/snowflake）。
3. torrc 关键坑：引号内反斜杠被转义（PT 路径必须正斜杠）、中文路径 ANSI 乱码（配置须全 ASCII）、启动保活须 WMI Win32_Process.Create（Start-Process 传参被吞）。

## 三、当前设置优化建议

1. **DevSidecar**：保持现状（系统代理开/排除国内域名开/CA 永不装/仅 GitHub 加速白名单使用）——**加速 ✅ 隐秘 ❌（定性：设计如此）**。
2. **Tor**：snowflake 内置参数在本网络受阻（broker 建连超时）；meek 新参数（appelboodersen）引入后 torrc 解析失败待修（digest 报错复现，待定位）；**下一步：obfs4 网桥行获取（BridgeDB 官方渠道或 Tor Browser 内置配置导出）后替换 snowflake**。
3. **隔离纪律**：DevSidecar 不接管 Tor 流量；敏感流量只走 Tor（连通后）；命令行引用 `-x http://127.0.0.1:31181`（加速）与 `-x socks5h://127.0.0.1:9050`（隐匿）。

## 四、后续步骤
