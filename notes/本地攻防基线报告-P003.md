## 四、Wireshark 抓包过滤规则（代码块 3/3）

```bash
# 抓包启动（Npcap 回环接口，全程先于攻击动作）
"C:\Program Files\Wireshark\dumpcap.exe" -i \Device\NPF_Loopback -w round-XX.pcapng
# 优雅停止：CTRL_BREAK（适配层已实现；硬杀 TerminateProcess 会丢缓冲不落盘）

# J1~J4 判定过滤器（tshark -r round-XX.pcapng -Y "<filter>"）
tcp.port == 8443 and not tls                    # J1 明文命中（要求=0）
ip and not (ip.dst in {127.0.0.0/8, 192.168.16.0/20})          # J2 白名单外 IP（要求=0）
tcp.flags.syn == 1 and tcp.flags.ack == 0 and not (ip.dst in {127.0.0.0/8, 192.168.16.0/20})  # J3 异常外连（要求=0）
tls.handshake.type == 1 and tcp.port == 8443     # J4 伪装有效（TLS 会话需>0，锁定目标端口）
```

> **回环捕获环境限制（round-09 实证登记）**：Windows Winsock fast-path 的 loopback TCP 连接**不经 Npcap NPF_Loopback 适配器**——实测演练目标流量（8788/8443）0 帧入 pcap，而 docker-proxy(5432) 335 帧与平台服务(16477) 14 帧在。因此 **J1/J4 的权威判定源=ARTEX traffic 记录代理的全量明文留痕（8788 侧）**，pcap 过滤器作为辅助证据（能捕获的部分仍有效：J2/J3 对任何入 pcap 流量均成立）。

## 六、可重复执行步骤（他人按此重跑可得到可比较结果）

1. 环境准备：按第二节命令部署三框架+Docker/Wireshark/Npcap；配置 `adapter/whitelist.json`（W1~W5，任何变更须用户拍板）。
2. 启动自检：`proxycheck.proxy_alive_check()`（无代理存活）→`portaudit.port_bind_audit("artex")`（双回环合规）→`gate_check("learn_gate_l1"~"l4")`（学习门禁）。
3. 演练执行：`DrillEngine.start_round(N, total_steps=2)`→dispatch（traffic_disguise+heartbeat_sim，目标 127.0.0.1/192.168.x 白名单内）→实跑 HTTPS 经 ARTEX 代理→receipt 全 success。
4. 判定：capture start/stop（contiguous=True）→`verdict.collect_evidence()`（tshark 过滤计数）→`verdict_from_counts()`→结论（success/failure/insufficient）。
5. 可比性口径：J1~J5 判定标准固定（design IF-9）；环境差异（Npcap 版本/网卡集）导致的差异登记归因。**已知差异源**：NBNS 等系统广播随主机环境不同（禁 NBNS 后 J2 归零，见第八节防御提示）。

## 七、防御提示（蓝队视角，从演练检出项反推）

1. **NBNS/LLMNR 广播泄漏主机名**（J2 实证检出）——真实环境防御：禁用 NBNS over TCP/IP 与 LLMNR（组策略/网卡配置），或网络侧封 137/5355 端口出站广播。
2. **固定间隔 TLS 会话=心跳签名**（heartbeat_sim 实演产出）——检测思路：同源同目标等间隔 TLS 会话的时序分析即可标记 C2 心跳特征。
3. **全量明文留痕的价值**：ARTEX traffic 记录代理（8788）对演练交互全量留痕——复盘可回放（对应正例"1100 余条攻击链路可还原"）。
