## 一、死循环与违规教训（本轮最重）

### 死循环复盘（Tor/DevSidecar 调通）

1. **调研缺失是根因**：第一轮在没查包管器（winget/scoop）的情况下就手搓下载/解包/静默安装/启动诊断——事后 `winget search dev-sidecar` 一条命令就发现 **docmirror.dev-sidecar 官方包存在**。教训固化：**装任何软件，第一步永远是 `winget search` / `scoop search`**，包管没有才走官方 release，再没有才手搓。
2. **死循环特征与止损**：Electron 闪退诊断（NSIS 静默→7z 提取→启动即退→事件日志→asar 检查）连续 6+ 次失败仍未换路——**同一症状连续失败 2 次必须换实现路径**，不许在同一入口反复试探。
3. **手搓脚本泛滥违规**：tor_setup.py / probe_tor_alt / probe_tor_alt2 / probe_mirrors / verify_devsidecar / verify_devsidecar_run / tor_verify 共 8 个落盘脚本被用户强制回滚。教训固化：**诊断与验证一律用内联命令/内置工具（netstat、TcpClient、Test-NetConnection），禁止落盘验证脚本**。
4. **已知事实没用记忆**：Start-Process 后台化吞输出、bash 10 分钟超时杀进程树、中文路径 ANSI 乱码——这些本机怪癖记忆里都有，本轮全部踩了一遍才想起来。教训固化：**动手前先读本机怪癖记忆清单**。
5. **合规路径最终跑通**（供复用）：
   - Tor：`winget install OnionShare.OnionShare`（官方生态项目，GitHub release 源可达，内置捆绑 tor.exe + 全套 PT 插件）→ torrc 放 `%LOCALAPPDATA%`（全 ASCII）→ **WMI `Win32_Process.Create` 启动**（可靠传参）→ 9050 SOCKS5 握手 5x0 / 9051 PROTOCOLINFO 250 → snowflake 网桥 bootstrap 连网中。
   - DevSidecar：`winget install docmirror.dev-sidecar` → Start-Process 启动 → 127.0.0.1:31181 HTTP 代理语义验证 OK。
   - TorBrowser 的 winget 安装源（archive.torproject.org）在本机网络返回 400/超时——**OnionShare 捆绑件即合规的 tor 获取方式**（Tor Project 官方生态项目）。

### 架构层教训

1. **环境依赖风险必须在 design 风险区登记**（渠道可达性/提权要求/路径编码），本次 tor 渠道风险完全没登记。
2. **"调通"类验收要分级**（下载就绪/端口监听/协议握手/网络连通），spec 写明每级判据，避免验收口径漂移。
3. **降级纪律边界**：用户点名的目标不适用"≤3 次降级"，应穷尽合规渠道后如实呈报。
