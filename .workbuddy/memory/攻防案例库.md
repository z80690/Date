## 案例 001 — 群晖 DSM OAuth 命令注入（CWE-88）

- **来源**：今日头条文章《9.8分的NAS认证漏洞：群晖OAuth接口命令注入怎么防》
  URL: https://www.toutiao.com/article/7711665880567955995/
  发布 2026-11-24，作者 儒雅饼干lPI
- **漏洞编号**：CVE-2026-120382，CWE-88，CVSS 3.1 = 9.8，2026-11-23 公开
- **官方公告**：Synology_SA_26_21
- **本质（大白话）**：程序把外部字符串拼进命令行，没当成一个完整参数处理，字符串里的分隔符被当成新参数。CWE-88 全称"命令中参数分隔符的不当中和"。
- **危害**：认证前路径（OAuth 登录/第三方授权/回调，未登录可达）→ AV:N / PR:N / AC:L → 9.8。官方描述：读写任意文件、拒绝服务。
- **受影响版本（低于以下 build 即在范围内）**：
  - DSM 7.1.1 → 7.1.1-42962-10
  - 7.2.1 → 7.2.1-69057-14
  - 7.2.2 → 7.2.2-72806-11
  - 7.3.2 → 7.3.2-86009-6
  - 7.4.1 → 7.4.1-90080-2
- **自查三步**：①控制面板看 DSM 版本/build 对照清单；②看 5000/5001 是否映射公网、QuickConnect 是否开；③翻登录/OAuth 日志看异常分隔符、超长参数请求。
- **处置顺序**：先降暴露面（关公网映射/QuickConnect，改 VPN+白名单）→ 再按官方路径升 build → 短期不能升就 WAF/反代对 OAuth 路径做参数白名单 → 开管理员 2FA、查权限。
- **验证边界（文章原话）**：只在隔离环境、同版本 DSM 虚拟机、断外网做；不对任何真实设备执行。
- ** PoC 情况**：文章明确"不含可直接用于攻击真实目标的载荷"，无现成 PoC。
- **模拟可行性（2026-11-25 实测）**：
  - 能：本地复现 CWE-88 分隔符注入。脚本 `box/demo_cwe88/demo_linux.py`，在 Kali/bash 里跑（Windows cmd 不认分号当分隔符，会假阳性，别在那跑）。
    判据：第二条命令是否真创建 `/tmp/cwe88_injected_marker` 文件，不用字符串匹配。
    实测：有病写法 shell=True → 标记文件出现（注入真执行）；补丁写法 shell=False+参数数组 → 不出现。
  - 不能：真复现群晖 DSM 漏洞——缺同版本 DSM 靶机，且公网真实目标禁碰。
  - 文章无现成 PoC，上述是原理级本地演示，不是对群晖的真实利用。
