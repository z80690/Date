# 项目工作规则（原八条 + 本地一条 · 欧工 SOP）

> 来源：项目根目录 `AGENTS`（无扩展名）与 `CLAUDE`，2026-11-15 全文复用。
> 本文件是 WorkBuddy 侧的规则全文，运行时只读本目录（`.workbuddy/rules/`）。
> 原八条正文一字不改，逐字对齐来源文件。
> 2026-11-25 用户授权追加本地修订：第 9 条合并「实事求是 / 显式纠正 / 冲突裁决」三种语义为一条，避免与 W7、C6 重复；第 8 条加例外。原八条不动。

1. 目录池纪律：新项目开工第一步按根 README 目录池建齐目录，缺目录不得开写代码。
2. 资料归档：协议/需求 → 00；硬件资料 → 01；代码 → 02；运行数据/日志/验证记录 → 04（带时间戳）；工具与流程 → 06；参考 → 07；交付 → 08；旧版 → 09。
3. 文档同步铁律：代码变更必须同步更新 08_交付文档功能说明，不一致视为任务未完成。
4. 数据落盘铁律：运行数据必须落盘 04_测试验证 且 AI 的分析结论必须引用落盘数据，禁止凭空描述现象。
5. 就绪三自检（嵌入式开工前置）：工具链可编译 / 仿真器可加载 / 日志可落盘——任一未过不开工。
6. 回环红线：全程 127.0.0.1 本机回环，禁真实外连公网；四不红线保留（不真实入侵/不控真实肉鸡/不混真实虚拟币/不隐匿真实服务器）。
7. 回执权威：模型只规划不直控，执行结果成败只认回执，禁止猜测标记成功。
8. 门禁纪律：每阶段产出经用户确认才推进；驳回则修订重提，不越门禁。**例外：用户明确说"你定/你自己决定/听你安排"时，该步授权自决，不卡门禁；事后照常汇报结果。**

9. 实事求是：没查过就说没查过，查到什么说什么。错了直接认、当场显式纠正，不许用"大概/应该/可能是"糊弄，不许悄悄改口。没验证的结论必须带把握程度，不许光秃秃下判断。两条规矩打架时先摆出来，不自行挑一条遵守，按协作公约 C6 的顺序裁决（规则>知识库>记忆>推断）；裁决不了就问用户。

10. 试错与止损（分类型重试 · 取代旧"固定3次/40分钟"）：干活必然试错，不试长不出经验；但试错按"怎么停的"分类处置，不许一刀切试三次就判死。①外部故障（网络/工具/权限/限流）：直接重派同方向。②预算耗尽（做到一半被掐）：看执行记录从断点续，不从头重来；标 exhausted，不算失败。③正常跑完但没成：禁止原样重派，"再试一次说不定行"不算理由；只有出现新事实/新机理才另开方向。④连续在同一处卡住：换方向，不是加次数。同类失败连着来要退避（等待翻倍并封顶），不立刻反复撞。失败必须落盘"停在哪一步"，状态与计数同事务写，不靠记忆。时间用绝对截止时间，每轮按剩余时间缩放；到点就地收尾、写回已有结果，不硬砍半截。次数上限只是最后一道保险，不是主逻辑。机器判定见 `.workbuddy/scripts/retry_policy_check.py`（exit 0 = 规矩一致且落盘）。
