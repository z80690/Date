## 1. ARTEX（D:\refs\ARTEX）

### 1.1 是什么
AI 自主渗透测试系统（Go 后端+Next.js 前端），LLM 多 agent 驱动；核心是**双图架构**及其上的两条自主性机制（worker 间过程级信息交换、planner 多轮共享 todolist）。百度"agent+"攻防挑战赛冠军项目（出处：pre_check.md 2.1 多个历史快照仓库一致描述）。本地为 RuoJi6/ARTEX 社区续维护版（AGPL-3.0，保留原仓库提交历史；README:12）。

### 1.2 为什么值得学
- **探索图节点=goal/intent/fact/finding/hint**（README:481）——与黑板机制概念同源，是"意图图谱"在渗透编排中的完整工程化实现（血缘链：spawns/derived_from/yields/proves，README:481-497）。
- **事件驱动闭环**是"模型只规划不直控执行靠回执"底座原则的最佳参照：图变更 debounce 唤醒 planner→派意图→worker 领一条意图执行→写回→再唤醒，直到 prove_goal（README:516-539）。
- **guard/intercept 工具审批门**（README:444/460）= 本单人工审批与拦截审计的现成参考。
- **traffic 记录代理**（README:443；traffic.go:1-5）= 蓝方取证素材生成器：嵌入式 go-mitmproxy，每笔目标 HTTP 交换写入人类可浏览文件树+SQLite sidecar 分页索引，全量明文留痕。

### 1.3 核心机制（官方文档浓缩）
1. **双图分工**（README:476-483）：资产图（Asset Graph，全局共享真值库：root_domain/subdomain/ip/service/app/endpoint，归属公司，父子关系与去重 key 由程序计算，agent 只交原始信息）；探索图（Exploration Graph，每任务独立：goal/intent/fact/finding/hint 节点+血缘边）；两图靠 `exploration_anchors(node_id, asset_id)` 锚点相连→支撑资产测试覆盖度与覆盖图。
2. **引擎与意图生命周期**（README:514-539）：每任务一个 plannerLoop+N 个 worker goroutine；planner 读态势（graph_overview 预取+coverage/scope）派 0..N 个意图（大多数唤醒派 0 个——无新方向即结束）；worker claimNext 领一条意图→取意图 asset_ids 原始资产作初始信息→真实工具执行（Kali/Bash/HTTP 全程留痕+CA 验证）→写回 fact/asset/finding+每步 activity。
3. **worker 间过程级信息交换**（README:541-548）：`search_all_worker_traces(q)` 按关键字检索其他 work 的执行过程（自动排除自己）；`list_worker_traces`/`get_worker_trace(intent_id, step_ids)` 取具体步骤完整内容——信息以"执行过程"为粒度流动，边界不变。
4. **planner 共享 todolist**（README:560-582）：按任务保留、跨唤醒共享；每次唤醒是全新会话，串行利用链记录一次、按依赖逐步派意图（前置步骤已完成且依赖 fact 已存在才派下一步）→攻击链稳定推进、不重复、不错序。
5. **审批门与人审**（README:443-447/460）：guard/intercept 工具审批门；拦截审批支持展开详情（AegisHook 组件参考）；Jev/System One 拦截裁判外部化（docs/jev-integration-review.md：POST /v1/systemone 提交 choice 问题+allow/ask/deny criteria，低于置信度阈值转人工，证据截断时 allow→ask）。
6. **证据链设计**（docs/漏洞流量证据.md）：漏洞↔流量多绑定（baseline/proof/verification/supporting 四角色）；快照存原始 ID/URL/方法/头/正文长度/SHA-256，正文按哈希落 `data/evidence/blobs/`；PostgreSQL advisory lock 协调证据文件与 SQL 引用；md-zip 导出含 request.http/response.http/request.bin/response.bin+manifest；版本校验（evidence_version 不匹配拒绝旧版本写入）。

### 1.6 五要素条目

- **链接**：`D:\refs\ARTEX\README.md`（上游 https://github.com/RuoJi6/ARTEX ）
- **条目名**：ARTEX 双图架构与事件驱动意图闭环
- **浓缩四要素**：
  - 是什么：双图（资产图+探索图）+ planner/worker 分离 + 全程留痕记录代理 + 审批门，事件驱动闭环自主推进攻击链的渗透编排系统。
  - 为什么值得学：它是"意图图谱+血缘链+回执式执行"的完整开源工程实现，与本单底座原则（模型只规划、框架靠回执）天然契合；探索图节点命名与黑板机制概念同源。
  - 怎么用：本地部署（PostgreSQL+8787 端口）后以白名单哑端点为目标，复用其探索图/审批门/流量留痕作为蓝方取证与红方调度参考；模型层用 ARTEX_LLM_BASE_URL 重定向或置空旁路（方案 a）。

## 2. PentAGI（D:\refs\PentAGI）

### 2.1 是什么
开源自托管多智能体自主渗透测试系统：自然语言描述目标与目标态，一组专业 AI agent 规划并在隔离 Docker 沙箱内运行 20+ 专业工具（nmap/Metasploit/sqlmap 等），记忆结果并产出报告（README:60）。VXControl（迪拜安全公司）出品；33981 stars（api.github.com 2026-11-12 实测，pre_check.md 2.2）。

### 2.2 为什么值得学
- **专业角色分工+分层监督**是"小模型可生产化"的公开参考（README:477-541：Execution Monitoring 对 <32B 模型实测 2x 质量提升/2-3x 开销）。
- **沙箱与宿主隔离的官方安全设计**（README:683-707）直接对应本单 R1/R4 约束：硬化 dind+TLS 为推荐路径，挂宿主 Docker socket 为明确反例（特权容器挂 / 即拿穿宿主）。
- **外连面官方清单**（search 八家/scraper/graphiti/update-check）是本单外连治理的权威底稿（pre_check R1）。
- **官方能力边界声明**（README:93-97）：明示"非 BAS/adversary emulation 产品、无预定义攻击剧本"——为"框架只做调度执行、攻击剧本由演练设计承担"的分工提供官方依据。

### 2.3 核心机制（官方文档浓缩）
1. **多角色 agent 体系**（README:545-550/504-516）：Primary/Pentester/Coder/Installer/Assistant 为 general 类（工具调用上限默认 100），Searcher/Enricher/Memorist/Generator/Reporter/Adviser/Reflector/Planner 为 limited 类（上限默认 20）；Reflector 在 LLM 3 次未能生成合法工具调用时介入纠偏。
2. **执行监督（Beta）**（README:477-489）：adviser（mentor）按模式自动介入——同工具重复阈值 5、总调用阈值 10（可配 `EXECUTION_MONITOR_SAME_TOOL_LIMIT`/`_TOTAL_TOOL_LIMIT`）；检测循环低效、建议替代策略与检索现成解；工具响应附 `<original_result>`+`<mentor_analysis>` 两段。
3. **智能任务规划（Beta）**（README:490-502）：planner 先生成 3-7 个可执行步骤、经 enricher 分析全上下文、`<task_assignment>` 结构化下发，防 scope creep；官方实测（Qwen3.5-27B-FP8）质量 2x、开销 2-3x——**小模型与监督机制强耦合**的公开量化结论。
4. **记忆系统五层**（README:575-580）：长期记忆（PostgreSQL+pgvector 持久化成果与成功路径）/工作记忆/情景记忆/知识库/上下文链式摘要管理。
5. **可选知识图谱**（README:552-555）：Graphiti+Neo4j 按 flow 范围捕获 agent 响应与工具执行（本单 R1 外连治理对象之一）。
6. **沙箱双路径**（README:683-705）：推荐 `DOCKER_INSIDE=true`+硬化 dind daemon over TLS（DOCKER_INSIDE_HOST/TLS_VERIFY/CERT_PATH/POLICY_TESTS，证书只读挂载）；反例=挂 `DOCKER_SOCKET`（boot-order race：socket 未建时被 Docker 建成目录卡死 dind；blast radius：挂宿主 daemon socket=授予 agent 特权容器与 mount / 能力，PentAGI 自身也会被拿穿）。
7. **多租户**（README:709-712）：单实例 `TENANT_ID` 留空即默认。

### 2.4 模型依赖点（pre_check.md 3.1 实测，行级证据）

## 3. Cairn（oritera/Cairn——黑板机制出处）与 xcosmosbox/Cairn（同名区分）

### 3.0 保真度声明（先讲清两个 Cairn）
- `D:\refs\Cairn` = **xcosmosbox/Cairn**（MIT）：Skill 文档知识图谱工具。经 2026-11-12 实测（git log --grep blackboard 零命中、git grep blackboard@HEAD 零命中、README 273 行全文无黑板机制），**与 spec"L1 含黑板机制 Cairn"预期不符**，系同名混淆（learn-gate-trace.md §1 剔除留痕）。
- spec 语境所指黑板机制 Cairn = **oritera/Cairn**（AGPL-3.0，5075 stars/993 forks，api.github.com 实测 2026-11-12），由 `D:\refs\ARTEX\README.md:599` 官方"参考"一节引用（https://github.com/oritera/Cairn ）。本节学习内容以其 README 为准。

### 3.1 是什么（oritera/Cairn）
通用 AI 状态空间搜索引擎："给定起点与目标，在未知状态空间中搜索路径"；自主渗透测试是其首个验证域（README："Cairn is a general-purpose problem-solving engine... AI Penetration Testing is one such problem — and a proven one"）。腾讯云 Hackathon AI 渗透挑战赛第 2 期：610 队/1345 人，唯一 AK（54/54），决赛第 3 名（README"Results"节；系统赛前未经测试，比赛日凌晨 4 点全链路首次上线）。

### 3.2 为什么值得学
- **黑板架构（Blackboard Architecture）+ fact-intent 图**：三种原语 Fact（已确认写入黑板的客观发现）/Intent（已声明未执行的探索方向）/Hint（人工判断随时注入，agent 下次读取时吸收）——无角色、无预定义工作流，一切协调经共享黑板（Stigmergy 共识机制：无直接通信、无信息孤岛）。
- **与本单方案 a 天然同构**：Worker 后端为 **Claude Code/Codex/Pi CLI**（复用编码代理而非框架内直连 LLM）——"模型推理由外部承担、框架只做状态与调度"的现成开源实证。
- **OOADA 循环与任务运行时生成**：Worker 跑 Observe→Orient→Decide→Act，读全图、判目标是否达成、决定下一批 Intent、执行探索并写回 Fact；任务从图当前状态生成而非预定义岗位说明书。

### 3.3 核心机制（README 浓缩）
1. **三类任务同一 Worker 执行**：Bootstrap（开局直接尝试解题→Fact+可能直接 Complete）/Reason（读全图：目标达成了吗？下一步探什么？→Complete/新 Intent/no-op）/Explore（领一条 Intent 执行→产出一条 Fact）。
2. **三组件架构**：Cairn Server（只维护图一致性，Read/Write API）/ Dispatcher（读图、调度任务、起停 worker 容器、协议唯一写入者）/ Worker Container（每项目一个容器，内多 Agent Worker 并发；agent worker 只收 prompt 返回结构化输出）。
3. **local mode**：Worker 可直接跑在 dispatcher 主机，无需 Docker（README"Local mode"节）。
4. **依赖**：Python ≥3.12；macOS/Linux；worker 容器镜像 ghcr.io/oritera/cairn-worker-container；LLM 端点与 key 填 dispatch.yaml。
5. 成绩背书细节：零 MCP 工具、零 RAG、零预定义 agent 角色（README 自述）。

### 3.4 模型依赖点
不内置 LLM 调用——由 worker 后端（Claude Code/Codex/Pi CLI）自行对接各自模型；对 P003 意味着：黑板调度决策可由码道智能体承担（方案 a），黑板状态机经 Read/Write API 回执。

## 4. 三框架横向对照与对本地演练的总启示

1. **调度范式三分**：ARTEX=意图图谱+事件驱动闭环（回执式）；PentAGI=角色分工+监督纠偏（可控但开销大）；Cairn(oritera)=黑板无角色搜索（最自主）。本单演练编排可按阶段混用：侦察阶段参照 ARTEX 意图血缘（每动作登记 intent/fact），利用阶段参照 PentAGI 监督（重复动作阈值告警），复盘阶段参照黑板机制（全量动作与发现上板）。
2. **模型依赖全部可拆**（pre_check.md 3.2 结论）：ARTEX 单 env 重定向、PentAGI custom provider、Cairn(oritera) worker 后端天然外置——方案 a（回执模式）在三框架均低改造量。
3. **留痕即证据链**：ARTEX traffic.go 全量明文留痕+SHA-256 证据快照（docs/漏洞流量证据.md）、PentAGI 沙箱全程日志（README:573）、Cairn 黑板即状态日志——三框架天然产出蓝方可消费的取证素材，本单 T 系抓包与 W 系取证任务可直接对齐。
4. **安全边界文档化水平**：PentAGI（socket 反例+dind 硬化）>ARTEX（免责声明+Basic Auth/反代指引）>Cairn（local mode 简述）——本单部署清单需自行补齐 Cairn 侧等价约束。
