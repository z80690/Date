## 2. 你问的"真实 IP"——直接答

**显示的是真实 IP**。`39.154.137.189` 就是这个宽带当前对外的公网 IP，没被代理遮。

为什么？看两张表就懂：

| 层面 | 值 | 谁设的 |
|---|---|---|
| 系统代理（界面那个） | `127.0.0.1:31181` | DevSidecar |
| 我进程的环境变量代理 | `127.0.0.1:56029` | 沙盒层 |

两个都是**本机回环地址**（127.x），不是远端代理。本机回环的意思是"流量出了应用就拐回自己机器"，中间那层软件决定转不转发、往哪转。DevSidecar 只加速 GitHub 那类域名，查 IP 的域名不在它名单里，所以直接出去了——真实 IP 暴露。

**重点**：想靠这个藏 IP，门都没有。要藏得用真正的远端代理/VPN，那是另一回事，也不在你这次演练范围内。

## 3. 本地靶机演练（四段框架）

抽象场景：**老后台越权查询，改个 ID 就看别人订单**。

1. **人话翻译**：网站给了个查询订单的接口，本该只让你看自己的。它却只看你传的编号，不看你是谁。你把编号改成别人的，它就给你别人的。
2. **分工拆解**：人只定了"测越权"这个目标；AI 负责判断"这接口可能没校验登录态"、选哪几个编号试；工具（curl / Python urllib）负责发请求、收响应。真干活的不是 AI，是那个有洞的接口。
3. **防御视角**：该拦在服务端鉴权那层——每次查询都得先确认"登录的人 == 要查的人"，不是客户端传啥就信啥。客户端校验只是体验，服务端才是门。
4. **一句收口**：不是 AI 聪明，是门本来就没锁。

**角色扮演验证**：四段格式生效了，但全程没出可跑载荷、没碰真实地址、没编造受害者。你那套口令管的是**表达格式**，不是**能力开关**——这点上轮说过，这轮实测坐实。
