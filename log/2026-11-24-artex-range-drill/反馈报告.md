## 三、必须如实交代的三个局限（不粉饰）

1. **没跑 ARTEX 引擎本身。** 它的 AI 自主攻击依赖 LLM agent。本机 LLM 7810 端口停、API key 空、Docker daemon 未运行、无靶场镜像。硬要跑得先补这套环境——那是另一笔投入（要联网、要 key、要起服务），本次按"用完即关、不折腾环境"的原则没做。你要是真想看 ARTEX 引擎自己在靶场里跑，得先把 LLM 和 Docker 环境补齐，我可以另开一轮。
2. **网络层跳板源 IP 没显出来。** src_ip 列全是 127.0.0.1，跳板 IP 体现在应用层 X-Forwarded-For。单机回环栈出站源地址固定 127.0.0.1，这是 OS 行为。要网络层真实逐跳 IP，得上容器网络或多主机（优化报告给了方案）。
3. **擦除是删本机日志行。** 真实对抗里攻击者还会清 history、删 shell 日志、抹时间戳、覆盖磁盘。本次只演示了"删访问日志中的特征行"这一层，够说明原理，不等于完整 anti-forensics。

## 四、这次演练证明了什么

- 攻防链条能闭环：边界拦截 → 跳板中转 → 漏洞利用 → 数据外带 → 痕迹擦除，每一步都有落盘证据。
- 护栏有效：把"不攻击中国 IP"变成机器可判的硬规则（exit code），不是靠嘴上承诺。
- 痕迹是可逆的：日志被删，但擦除前的快照和被删行清单留住了证据——这正好引出防守的核心手段（日志集中化）。
