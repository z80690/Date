# 优化建议报告 — ARTEX 案例关键词本地靶场复现（Cairn 黑板真跑）

日期：2026-11-24｜配套：运行时报告.md / 反馈报告.md

## 建议一：给 worker 加一个"决策可回溯"层（本次最该补的）

**问题**：这次 worker 是我按协议手工步进，bootstrap→reason→explore→complete 的决策写死在 `cairn_local_worker.py` 里。去掉 LLM 换来了"零成本、纯本地"，但决策逻辑不通用——换个靶场要改脚本。
**方案**：把"读图→选 intent"的判定规则抽成 `config/worker_policy.json`（机器可判的维度编码进规则表），worker 读规则表决策。符合项目"维度可判的编码进检查器"的硬约定。
**收益**：换靶场只改规则表不改代码；决策过程可审计、可单测。

## 建议二：日志实时外发，反制痕迹擦除（防守核心）

**问题**：本次攻击者删本机日志就得手（wiper 删 `../secrets` 特征行）。虽然擦除前快照留了证，但那是演练机上的，真实对抗里攻击者也能删快照。
**方案**：每行日志生成即双写——本地文件 + 独立 collector（`artifacts/logs_remote.jsonl`）。擦除后对比：本机剩 5 行，remote 仍含被删行 → 证明集中日志让擦除失效。
**价值**：这是反 anti-forensics 的标准手段，也是 ARTEX 类 agent 攻击下最有效的兜底（它们动作快，但删不到已外发的副本）。

## 建议三：容器网络拿网络层真实跳板 IP

**问题**：单机回环栈出站源 IP 固定 127.0.0.1，跳板 IP 只在 XFF 体现。
**方案**：Docker 容器网络，每跳独立容器独立 IP（172.20.0.2/.3/.4），日志的 `src_ip` 就是真实上一跳。本机 Docker daemon 当前未跑，按需再起。
**代价**：要起 Docker（临时、用完即关），本次没做。

## 建议四：护栏升级为"规则表 + 检查器"

**现状**：`boundary_guard.py` 白名单硬编码 127.0.0.0/8，够用但写死。
**方案**：按项目既有约定拆成 `config/range_rules.json`（允许网段 + 禁止网段含中国 IP 段 + 动作）+ `scripts/boundary_check.py`（exit 0/2）。改规则不动代码。
**收益**：中国 IP 段单列禁止清单，命中即拒并标注原因，机器可判。

## 建议五：把"共享大脑"做成常驻能力（按需，非本次）

**问题**：本次 Cairn Server 用完就关了（符合你的约定）。下次要复现得重新起。
**方案**：如果以后要长期做这类演练，把 Cairn Server 注册成一个**手动启动**的本地服务（不设开机自启、不常驻），要用时按命令起、用完关——严格守住"不污染环境"的底线。注意：这条只有你明确要长期用才做，默认不做。
