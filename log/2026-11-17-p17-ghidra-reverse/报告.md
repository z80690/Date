## 5. 实测记录（模拟测试任务，2026-11-17）

**样本**：`demo_app.exe`（由 `secret_algo.c` 用 gcc 15.2 -O0 编译，x86:LE:64，含 MinGW 符号表；逆向层"看不到"源码）。

**适配层端到端**：`ghidra_adapter.analyze_binary('D:/refs/_p17_work/demo_app.exe')` → `status=verified`，全程约 57 秒（无头分析 21–29 秒 + 逐函数反编译）。

**Ground truth 三条验收（源码注释里预埋，逆向层事后核对）**：

| # | 标准 | 结果 | 证据（反编译 C 原文） |
|---|---|---|---|
| GT1 | 认出 check_license 函数 | **过** | 函数名清单含 `check_license`（MinGW 符号表恢复），40/40 函数全部反编译成功 |
| GT2 | 魔数 1337 恢复 | **过** | `return local_c == 0x539;`——0x539 = 1337 的十六进制写法，加权和循环结构逐字符还原 |
| GT3 | ACCESS GRANTED 分支恢复 | **过** | `printf("ACCESS GRANTED\n");` / `printf("ACCESS DENIED\n");` + `banner()` 调用链全部还原 |

**判定：模拟测试任务端到端跑通，L4（干净环境 + 完整日志 + 对照 ground truth）。**

**踩坑实录（全是实测抓的，非猜测）**：

1. Ghidra 11.3.2 要求 **JDK 21**（`application.java.min=21`），本机只有 17 → 绿色版 Temurin JDK 21.0.13 落 `D:/refs/jdk21`，适配层只给 Ghidra 子进程注入 JAVA_HOME，不动全局。
2. zip 解压顶层目录名是 `ghidra_11.3.2_PUBLIC`（无日期尾缀），适配层默认路径按实测改。
3. 版本键是 `application.version=`，不是 `GHIDRA_VERSION=`。
4. **Jython 2.7 PyString 不吃中文路径**——脚本原来放仓库（路径含"软件源码"）直接崩；改为运行时拷到 ASCII 工作目录。
5. **Jython 要求编码声明**——脚本含中文注释必须加 `# -*- coding: utf-8 -*-`。
6. `-deleteProject` 会删工程：想 `-process` 复用旧工程必须先前一次没带 `-deleteProject`；出错时 .bat 会"按任意键继续"挂着（子进程卡死风险由适配层 timeout 兜底）。
7. 下载通道实测：curl 直连 Adoptium API 连续失败（52/35）；aria2 默认吃了失效代理（Proxy connection failed）；**`--all-proxy=""` 禁代理后 aria2 8 连接 195MB 约 3 分钟**。
