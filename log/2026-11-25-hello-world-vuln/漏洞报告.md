# 漏洞报告：Hello World 越权访问演示

> 性质：**本地教学靶机，故意留的洞，不是真实漏洞**，不能拿去任何平台提交。
> 测试范围：`http://127.0.0.1:8765`（本机回环，未碰任何外部目标）

## 1. 基本信息

| 项 | 内容 |
|---|---|
| 漏洞标题 | `/api/orders` 接口存在水平越权（无身份校验，改 `user_id` 可读他人订单） |
| 漏洞类型 | 水平越权 / 未授权访问（业务逻辑缺陷） |
| 影响资产 | 本地教学靶机（`vuln_app.py`） |
| 危害等级 | 演示用，不评级 |
| 发现时间 | 2026-11-25 |
| 测试人 | 本机授权演练 |

## 2. 漏洞原理

接口 `GET /api/orders?user_id=<数字>` 直接按参数返回对应用户的订单，**没有校验"当前登录者是不是这个用户"**。

正常设计应该是：从登录态里取当前用户 ID，忽略请求参数；或者校验参数 ID 与登录者一致。这里两者都没做。

## 3. 复现步骤（照着做就能重现）

1. 启动靶机：`python vuln_app.py`（只绑 `127.0.0.1:8765`）
2. 摸情况：访问 `http://127.0.0.1:8765/`，页面提示有 `/api/orders?user_id=1`
3. 正常请求：`curl http://127.0.0.1:8765/api/orders?user_id=1`
   → 返回 `{"user": "alice", "orders": ["订单A-001 手机 5999元"]}`
4. **越权请求**：`curl http://127.0.0.1:8765/api/orders?user_id=2`（无任何登录信息）
   → 返回 `{"user": "bob", "orders": ["订单B-001 电脑 8999元", "订单B-002 硬盘 599元"]}`
5. 判定：没登录、没凭证，只改了一个数字，就拿到了 bob 的订单 → 越权成立
6. 对照：`user_id=999` 返回 404，说明接口只按参数查库、不做身份校验

## 4. 证据

完整请求与响应存于同目录 `evidence.txt`（14 行，含 3 次稳定复现）。

## 5. 危害

真实系统里，这类洞意味着：任何人改一个 ID 就能遍历全站用户的订单、手机号、地址等隐私数据。属于 OWASP Top 10 里的"失效的访问控制"，是 SRC 平台新手最高产的一类漏洞。

## 6. 修复建议

1. 用户身份从服务端登录态（session/token）中获取，**不信客户端传来的 `user_id`**
2. 若业务必须传 ID，服务端校验 `请求ID == 当前登录用户ID`，不符返回 403
3. 对批量遍历做速率限制和审计日志
