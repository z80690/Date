# 漏洞报告（进阶关卡）：SQL 注入登录绕过

> 性质：**本地教学靶机，故意留的洞，不是真实漏洞**，不能拿去任何平台提交。
> 测试范围：`http://127.0.0.1:8766`（本机回环，内存数据库，未碰任何外部目标、未碰真实系统）

## 1. 基本信息

| 项 | 内容 |
|---|---|
| 漏洞标题 | `/login` 接口 SQL 注入，可无密码登录任意账号 |
| 漏洞类型 | SQL 注入（认证绕过） |
| 影响资产 | 本地教学靶机（`vuln_app2.py`） |
| 危害等级 | 演示用，不评级 |
| 发现时间 | 2026-11-25 |

## 2. 漏洞原理

后端把用户输入直接拼进 SQL 语句：

```python
sql = f"SELECT username FROM users WHERE username='{name}' AND password='{pwd}'"
```

用户输的 `'` 会闭合字符串，后面的内容被当成 SQL 代码执行——密码校验就被绕过去了。

## 3. 复现步骤

1. 启动靶机：`python vuln_app2.py`（只绑 `127.0.0.1:8766`）
2. 摸情况：访问 `/`，提示有 `/login?u=admin&p=wrong`
3. 密码错误：`/login?u=admin&p=wrong` → `FAIL`（对照）
4. 密码正确：`/login?u=admin&p=S3cret!` → `SUCCESS`（对照）
5. **注入一（永真）**：`/login?u=admin&p=x' OR '1'='1`
   → `SUCCESS`，`matched: ["admin","alice"]`——两个账号全钓出来
6. **注入二（注释）**：`/login?u=admin' --&p=anything`
   → `SUCCESS`，`matched: ["admin"]`——注释掉密码判断，无密码登录

判定：不知道密码，靠改输入就登录成功 → 注入成立。3 次复现均稳定。

## 4. 证据

同目录 `evidence_sqli.txt`（16 行，含 4 组对照 + 3 次复现）。

## 5. 危害

真实系统里这等于"任何人都能当管理员登录"，是 OWASP Top 10 常年第一。比上一关的越权更狠——越权只能看别人的，注入能直接变成别人。

## 6. 修复建议

1. **参数化查询**（prepared statement）：`WHERE username=? AND password=?`，用户输入永远当数据不当代码
2. 密码存哈希（bcrypt），不明文比对
3. 输入做白名单校验 + 最小权限数据库账号

## 7. 两关对比

| | 关卡一：越权 | 关卡二：SQL 注入 |
|---|---|---|
| 改什么 | URL 里的数字 `user_id` | 输入框里的文字（一个引号） |
| 拿到什么 | 别人的订单 | 直接登录成别人 |
| 真实价值 | SRC 新手高产，100–1000元 | 更严重，但真实系统里已少见（多数用了参数化） |
