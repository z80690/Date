# P15 优化建议报告

## 下一份派工单待办（按证据强弱排序）

### O1：查浏览器接线层（现在的第一硬骨头，已锁定范围）
仿真内核单测 18/18 通过，证明内核没坏。问题缩到 `frontend/src/store/useSimulatorStore.ts` 的 `compileBoardProgram`（约 3064 行 `sim.loadHex(program)`）和 `loadHex`（约 4157 行），以及 rAF 时钟驱动。重点查：浏览器里点 Run 后 hex 是否真喂进 AVRSimulator、`start()` 是否被调用、rAF 循环是否被触发。单测里 rAF 被 mock 成同步单步，真实浏览器靠 rAF——差异很可能在这。

### O2：ESP32 / 小智固件编译（真目标，依赖重）
需要 ESP-IDF v5.5.4 + arduino-esp32 3.3.10，依赖大。等 O1 把"仿真怎么真正跑起来"搞清楚再碰更有意义。

### O3：Kali / Docker 路线（已评估，暂缓）
- Kali：仿真是前端 JS，换 OS 无效；且 Kali 内 pypi/npm 超时、无代理，重装依赖路不通。
- Docker：镜像 1.5G 拉不动。两条都暂缓。

## 一条经验（又是第七条预测校正）
这单用户提"换 Kali"，我没直接否也没直接干，而是先查了两个硬事实：仿真是不是前端？（是）仿真内核好不好？（18/18 好）。靠这两条把问题的位置钉死，才敢说"换 Kali 方向偏"。这就是先猜一步、拿现实校一步——不查就附和用户的想法，或者不查就武断否定，都是错。用户要的"商量"正是这个：给判断，但判断得有实测撑着。
