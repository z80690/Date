# P18 · Lucky 本机防守环境（带面板 + 防火墙）实测

日期：2026-11-17
性质：软件部署/安全实验（与 P17 软件开发、域名折腾均为独立事件）
目标：用户要"不是 demo 级"——本机跑一个带操作面板 + 防火墙的正规防守工具，并真实验证拦截能力。

## 1. 结论先说

做到了，且是 L4 铁证：
- Lucky 3.5.0（Windows 绿色版）跑在本机，管理面板 `http://127.0.0.1:16601`，账号密码默认 666/666，登录成功（截图为证）。
- 防护功能不是摆设：开启"端口诱捕"后，模拟一个扫描者碰诱饵端口，Lucky **真的识别、拉黑、记录了这次访问**（拦截计数 0→1，日志写明 `Blocked IP 192.168.0.104 port 3389`）。
- 全程本地、绿色包、不装系统、不碰注册表、零域名、零个人信息。

## 3. 面板真实菜单（截图 lucky_loggedin.png 为证）

总览 / 日志中心 / 快速上手 / 动态域名 / Web服务(反向代理+WAF) / 端口转发 / STUN穿透 / Web终端 / 网络存储 / 网络唤醒 / 计划任务 / SSL证书 / **防护中心 → IP过滤、安全组、IP地址库、第三方认证** / Passkey / 设置 / 关于。

防护能力落点：
- **IP过滤**：黑白名单 + 全局黑名单，"诱捕"标签页（端口陷阱）
- **安全组**：建组后把 Web / 端口转发规则绑定进去，按组控制谁访问
- **Web服务**：反向代理，自带 WAF（Coraza），这是视频演示的核心

## 4. 端到端拦截验证（核心证据）

配置（PUT `/api/ipfliter/porttrapconf`，接口方法从前端 chunk 反查确认）：
```
Enable=true, TCPPorts=[2233,3389,8088], UDPPorts=[137,138]
```

模拟扫描（从局域网 IP 连诱饵端口 3389）：
```
echo > /dev/tcp/192.168.0.104/3389   # 192.168.0.104 是本机另一网卡 IP，充当"外部扫描者"
```

验证结果（三个独立 API 交叉确认）：
```
/api/ipfliter/porttrap/stats  → running:true, tcpListenerCount:3, totalCaptureCount:1, uniqueIPCount:1
/api/ipfliter/porttrap/blockedips → total:1, ips:[{ip:192.168.0.104, protocol:tcp, port:3389, captureCount:1}]
/api/ipfliter/porttrap/logs → "[PortTrap] Blocked IP 192.168.0.104 (protocol: tcp, port: 3389)"
                              "[PortTrap] TCP connection from 192.168.0.104 on port 3389"
```

判定：**L4**（真实工具、真实运行、改一个变量=扫描动作、三接口交叉、机器可判）。
注：从 127.0.0.1 自身连接不计数（本机 IP 属信任侧，符合预期）；从局域网 IP 连才触发——这恰好说明它在区分"自己人 vs 外部"。

## 6. 下载踩坑（固档）

- GitHub release 直链 curl SSL 35、aria2 禁代理也握手失败；**gh-proxy.com 镜像通道成功**（16.9MB）。大文件/直链失败优先走镜像。
- 登录是加密挑战，不是明文 POST：需先 GET `/api/login/challenge`（带随机 32 字节 `Lucky-Login-Session` 头）拿 challengeId+nonce+RSA 公钥，前端 `JSON.stringify` 后 RSA PKCS#1 v1.5 加密再 POST；登录后 token 在响应体 `token` 字段，请求头用 `lucky-admin-token`（不是 Authorization）。
- 配置保存端点 `/api/ipfliter/porttrapconf` 用 **PUT**，不是 POST（POST 返回 404 "Are you ok?"）。

## 7. 边界与如实说明

- 这是**防守方**工具，与 Kali（攻击方）不是一个路子——之前用户问"是不是 Kali 里部署"，方向反了，已纠正。
- 本机测试 bound 在 127.0.0.1 / 局域网，没公网 IP、没域名，所以"防外网扫"是用局域网 IP 模拟的，等价验证机制，非真实互联网流量。
- 没配反向代理规则（把 8765 服务挂到 Lucky 后面）—— WAF 拦截 HTTP 攻击这层未实测；本轮实测的是"端口诱捕"这层。
- Lucky 本体闭源（GitHub 只开源到旧版），免费使用但不可读源码改源码——接上前一轮"开源转闭源"的话题。
