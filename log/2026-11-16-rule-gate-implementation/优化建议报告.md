# 优化建议报告 — 规则程序化管控落地

这一轮把上轮纸上的建议真做成了程序。大白话讲。

## 先纠正三个错

1. 我以为规矩没进子智能体是"平台没注入"。翻了定义文件才知道：俩子智能体压根没写过"要先读规矩"，它们只写了自己出啥题、改啥卷。不是坏了，是没教。
2. 我以为规矩权威源是 `.workbuddy/rules/`。实测系统这次自动塞进来的，是 `.codebuddy/rules/`。两份内容一模一样，但我一直认错了门。
3. 我以为码道有个后台守护进程能仿。翻遍码道的规格书，它自己明令禁守护进程、禁定时、禁轮询，全走事件。你记的可能是反的。我没去造一个不存在的东西。

## 落地的东西

写了一个门禁程序 `.workbuddy/scripts/rule_gate.py`，纯标准库，不装任何新东西。它管四件事：

| 编号 | 卡什么 | 为啥 |
|---|---|---|
| C1 | 两份规矩的 md5 对不对得上基线，两个目录都查 | 有人偷偷改规矩，立刻现形 |
| C2 | 两个目录的副本字字节节一样 | 防只改一边造成"到底听谁的" |
| C3 | 两个子智能体定义里有没有"开工先读规矩"这一步 | 没这步，规矩就进不了它脑子 |
| C4 | WorkBuddy 文件没把码道目录写成依赖 | 你最怕的打架，卡在这 |

全绿退出码 0，有红的就非 0。以后谁想验，跑一行命令就行，不用靠我记。

还给了 `--context`：一条命令把两份规矩正文原样打出来，派活时直接贴给子智能体。

## 子智能体那边

在俩 agent 定义里各加了一段"开工先读规矩全文"，写明去哪读、读不到就停手上报。这是唯一能让规矩真进它们上下文的办法——平台不会自动塞，得让它们自己读。

## 还没解决的（不吹）

子智能体刚被喊起来那一刻，上下文里仍然没有规矩正文。这是 WorkBuddy 造子智能体的方式决定的，我在外面改不了。我能做到的是：让它一接活就知道必须先读哪两份文件。真正"读没读、照没照做"，得等它接一个真任务、看它产出对不对才算数。这次它只是自报，没读，正常。

## 建议下一步

真派一次出题任务给 `sdd-examiner`，要求它开头声明"已读规矩全文"并贴一句六条里的原话。它做到了，才算 B 项彻底翻绿。在那之前，B 保持 FAIL，不喊"已生效"。
