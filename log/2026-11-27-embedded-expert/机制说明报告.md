# WorkBuddy 加载机制说明 + 嵌入式专家包落地

- 日期：2026-11-27 11:12
- 证据等级：目录/格式 L4（实读）；注入机制 L4（两次快照对比）；新专家生效 L1（未实测，需新会话）

## 1. 一句话结论

WorkBuddy 挂专家 = 会话启动时，服务端把专家提示词塞进快照的 `PluginAgentPrompt` 一个槽。**不是动态扫目录**。技能是另一套目录，按需加载。连接器第三套，走授权。

## 2. 三套东西各自的目录和格式

| 东西 | 目录 | 格式文件 | 谁注册 |
|---|---|---|---|
| 专家包 | `C:\Users\Administrator\.workbuddy\plugins\marketplaces\experts\plugins\<包名>\` | `.codebuddy-plugin/plugin.json` + `agents/*.md`，可选 `avatars/` | 同级 `marketplace.json` 追加一条 |
| 技能 | `C:\Users\Administrator\.workbuddy\skills\<技能名>\SKILL.md` | YAML frontmatter：`name` / `description`（必填），`version` / `allowed-tools` 可选 | 放进去即被扫；前台"从本地添加技能"或"管理技能"挂 |
| 连接器 | `C:\Users\Administrator\.workbuddy\connectors\<用户ID>\` | MCP 配置 | 前台"管理连接器"，走 OAuth/授权 |

**专家两种形态**：
- 团队型（`expertType: team`）：`plugin.json` 里写 `teamInfo.leadAgent` + `memberAgents`，`members[]` 列人，`agents/` 放 5 个 md。软件开发团队就是这种。
- 单 Agent 型（`expertType: agent`）：`plugin.json` 里写 `agents: ["./agents/xxx.md"]` + `agentName`，一个 md 完事。全栈开发专家是这种。

**单选还是多选**：截图里专家列表只有"软件开发团队"一个打勾，换专家是单选——一次一个角色。技能列表全没打勾，跟专家独立，可另挂。

## 6. 需要你前台配合的动作

要真正验证"挂上嵌入式专家后我行为变了"，得你在界面里做一步：

1. 点输入框上方的「专家」→ 列表里应该出现「嵌入式开发专家」（新加的）
2. 选它（会替掉当前打勾的"软件开发团队"——单选）
3. 发一句测试指令，比如"开工前检查嵌入式工具链"
4. 我下一轮抓新快照，对比槽里是不是变成了嵌入式提示词

技能那边：点「技能」→「从本地添加技能」或「管理技能」，把 `embedded-dev-workflow` 挂上。不挂也能用（我可以直接读文件），挂了是前台显式加载。

连接器不用动——这次没加连接器，它跟专家/技能是三套独立机制。

## 7. 一句收口

文件落地 ≠ 生效。WorkBuddy 是"启动时填槽"架构，不热加载。你把专家切过来，才算真的给我换了脑子。
