# P19 · Kali 本地反向代理环境搭建（2026-11-18）

## 目标
用户要求：不用云服务器，用本机 WSL Kali 搭一个真服务器，练反向代理环境搭建。验证"我能不能把这套环境搭起来"。

## 实测过程（全部有命令输出，无假设）

### 1. 探查
- `wsl -l -v`：kali-linux Running (v2)，docker-desktop Stopped。
- `.env` 内容：只有 `CONTEXT7_API_KEY` 和 `KALI_SSH_PUBLIC_KEY`（注释 `workbuddy@kali`），**没有连接地址**。
- Kali 内实况：用户 `kali`(uid 1000)，IP `192.168.17.238/20`，sshd active 监听 `0.0.0.0:22`，**Nginx 未装**，无 `workbuddy` 用户，ufw/iptables/nft 全无。

### 2. SSH 连通性排障（证伪）
- Windows → `ssh kali@192.168.17.238:22`：**Connection timed out**。
- `ping 192.168.17.238`：100% 丢包（截图也显示 WSL 回退 NAT、DNS 隧道不受支持）。
- Windows → `ssh kali@127.0.0.1`：**成功**，用户 kali，`sudo -n true` 成功 → 免密成立。
- 结论：WSL NAT 模式下虚拟 IP 从 Windows 不可达；localhost 转发可用。**用户 SSH 配置本身没问题，只是地址该用 127.0.0.1。**

### 3. 装 Nginx（离线绕 DNS）
- Kali DNS 全断：`getent hosts` 失败、ping 223.5.5.5 100% 丢包、curl 出站 http_code=000。
- Windows 主机访问源站正常（tuna/kali 均 200）。
- 处理：Windows 下载 `nginx_1.30.4-5_amd64.deb` + `nginx-common_1.30.4-5_all.deb`（670K+108K）→ 落 `temp/nginx_debs/` → 通过 `/mnt/c/...` 在 Kali 内 `dpkg -i` 离线安装。
- 结果：`nginx version: nginx/1.30.4`。
- 踩坑：SSH 里 apt 被 SIGTERM 留下 apt-get 进程占锁；`pkill -f "apt-get install"` 把自己也匹配杀了 → 改用按 PID 精确清理。

### 4. 搭反向代理
- 后端：`/home/kali/rp-demo/backend.py`（纯 stdlib Python），绑 `127.0.0.1:5000`，返回 `BACKEND OK` + 路径 + hostname。
- 用 `setsid nohup ... & disown` 启动（普通 `&` 会被 wsl 会话退出带走）。PID 392 稳定监听。
- Nginx：`/etc/nginx/sites-available/rp-demo`，`listen 80`，`proxy_pass http://127.0.0.1:5000` + 4 个 `X-Forwarded-*` 头；删 default、软链 sites-enabled。`nginx -t` 通过。
- 踩坑：heredoc 里 `$host` 被上层 shell 展开成空 → 配置报错 `invalid number of arguments in proxy_set_header` → 用 `\$` 转义修正。

### 5. 三层验证（全通）
| 路径 | 结果 |
|---|---|
| Kali 内直连 `127.0.0.1:5000` | BACKEND OK |
| Kali 内经 Nginx `127.0.0.1:80` | BACKEND OK |
| Windows 经 Nginx `127.0.0.1:80` | BACKEND OK |

关键隔离验证：后端只绑 `127.0.0.1`，从网卡 IP `192.168.17.238:5000` 访问 **http_code=000（不通）** → 外网只能看到 Nginx 的 80，看不到后端。这就是反向代理的核心价值。

## 未做及原因
- **防火墙规则**：Kali 内 iptables/nft/ufw 命令全无。当前架构是 WSL NAT + 后端只绑回环，暴露面已天然收窄，为"演示"硬装防火墙工具属多余动作，与用户"验货没意义"的批评一致，故不做。真要上公网服务器时再装。
- **域名绑定**：WSL NAT 无公网 IP，域名解析无处可指。这一步必须等真云服务器。
- **持久化**：后端用 setsid 启动，wsl 整机重启（`wsl --shutdown`）后会消失；需重跑第 4 步命令。未写 systemd service（Kali WSL 默认不跑 systemd）。

## 结论
**能搭起来。** 用户的核心疑问"我是否能把这套环境搭起来"——答案是能，已实测三层全通。反向代理的概念（前端 80 收请求、转给藏在回环的后端、后端对外不可见）已经在这台本机上落地，不是纸上谈兵。

## 复现命令
```bash
# 启动后端（wsl 会话退出后需重跑）
wsl -d kali-linux -- bash -lc 'cd /home/kali/rp-demo && setsid nohup python3 backend.py > backend.log 2>&1 < /dev/null & disown'
# Nginx 已在跑；若未跑：sudo nginx
# Windows 验证
curl http://127.0.0.1/
```
